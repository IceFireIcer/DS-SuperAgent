# ds-bot

The DSH client and HTTP bridge for DS-SuperAgent. The package keeps the existing DS Bot interface and exposes the
public `superagentProduct` service in a DSH profile.

## Scope

The plugin installs `installProduct` only. It does not load the former roster, group, round, team-governance,
Bot-to-Bot, native-history, `/api/bot` façade or profile-switch runtime.

The supported product path is:

1. DSH starts `@deepseek-ai/dsh-base`, `@deepseek-ai/dsh-web-app`, `ds-bot` and `ds-superagent` in one
   `ds-superagent` profile.
2. The browser half applies the existing client UI through `applyProduct`.
3. `POST /api/product` forwards product commands and queries to `superagentProduct`.
4. Direct native Session list, read and export requests are refused. Main and Worker turns use the core's public
   execution path, so the UI has no native Session write bypass.

The UI remains the repository's existing client. The retained surface covers Main conversation, work cards,
attachments, browser import, credentials, memory, MCP configuration, Office, schedules, proactive review,
supervision and local or remote execution settings.

## Install

Add both packages to a DSH profile:

```json
{
  "dependencies": {
    "ds-bot": "link:/path/to/DS-Bot-Super-Agent/ds-bot",
    "ds-superagent": "link:/path/to/DS-Bot-Super-Agent/superagent"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "ds-bot",
        "ds-superagent"
      ]
    }
  }
}
```

Install from the profile, start DSH, and configure model providers in DSH settings. The plugin itself has no
runtime configuration and does not read `DSH_HOME` directly.

## Develop

Use Node.js 24 from `ds-bot/`:

```sh
npm ci
npm run harness
npm run build
node scripts/build-client.mjs --check
npm test
npm run lint
```

Run targeted tests with the harness loader while changing one area:

```sh
node --import ./test/harness-resolve.mjs --test test/product-execution.test.js
```

`client.js` and `office.js` are generated by `scripts/build-client.mjs`. Never edit `client.js` by hand. UI changes
under `src/client/` and the generated assets require the repository's UI boundary check.

## Layout

| Path | Purpose |
|---|---|
| `index.js` | Host entry; installs the product bridge only |
| `src/host/product.js` | `POST /api/product`, native Session refusal and the `superagentProduct` dependency |
| `src/client/index.js` | Existing client entry; applies the product surface only |
| `src/client/product*.js` | Main conversation, work observations and retained capability settings |
| `src/client/styles.js`, `themes.js`, `icons.js` | Shared presentation used by the product surface |
| `src/office/` | Office document tools retained for Worker use |
| `web-search.js` | Independent `auto` web-search provider |
| `test/` | Product host and client tests |

## Compatibility and data

The R5 product deliberately has no old contact, group, round, history, activation, reversal or profile rollback
entry. Existing user files are not removed or rewritten by this package. The business store belongs to
`ds-superagent`; the app keeps that profile under its own data location and never points it at the user's `~/.dsh`.
