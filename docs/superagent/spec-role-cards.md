# 侧栏角色卡与只读 Router/Worker 上下文

- 追踪：[#213 规格：侧栏角色卡与只读 Router/Worker 上下文](https://github.com/IceFireIcer/DS-SuperAgent/issues/213)。

## Problem Statement

Main、Router 和 Worker 已经按三层运行，但当前桌面界面没有把 Router 和 Worker 作为可点击的运行观察入口放在左侧。用户只能看到 Main、Activity 和底部的角色状态条，无法像切换 Main 一样打开 Router 或某个 Worker 的只读上下文和实时状态。

同时，角色名被当作普通界面文案翻译，侧栏 Main 入口显示成“主角色”，底部状态条显示成“主角色 / 路由角色 / 执行角色”。这与产品既定的 Main、Router、Worker 名称不一致，也让角色卡看起来像角色切换器或旧 Bot 联系人。

## Solution

左侧以 Main、Router、Worker 的角色卡组织运行观察：

- Main 卡片始终存在，是唯一可输入入口。
- Router 卡片在首次产生持久工作后自动出现；一个 Instance 只有一张 Router 卡片。
- Worker 卡片由持久 Ticket/Assignment 事实驱动，按工作自动出现；卡片的身份是工作，不是 Session。
- 点击卡片只切换阅读视图，不创建第二套对话或写入口。Router/Worker 上下文保持只读，没有 composer、停止、重试、审批或工具重放。
- 新卡片自动出现但不切页、不抢焦点。完成或停止的 Worker 仍保留在可折叠的历史中。
- 无论界面语言是什么，角色名始终显示 `Main`、`Router`、`Worker`。

## User Stories

1. 作为用户，我希望左侧始终有一个 Main 卡片，以便从任何观察视图回到唯一的主对话。
2. 作为用户，我希望第一次触发 Router 后自动出现 Router 卡片，以便知道调度层已经参与。
3. 作为用户，我希望 Worker 被真正分配执行安排后自动出现卡片，而不是因为模型声称启动了 Worker 就出现。
4. 作为用户，我希望每一项工作只有一张 Worker 卡片，以便重试、换代或重连不会把它变成新的 Bot 联系人。
5. 作为用户，我希望 Router 卡片在多个 WorkBrief 之间保持唯一，以便它代表一个逻辑 Router，而不是每个 Ticket 的重复副本。
6. 作为用户，我希望卡片直接显示角色名、工作标题和当前状态，以便不打开详情也能判断谁在做什么。
7. 作为用户，我希望卡片显示 `Main`、`Router`、`Worker`，而不是“主角色 / 路由角色 / 执行角色”，以便产品角色名称始终一致。
8. 作为用户，我希望点击 Main 卡片回到主对话并保留原草稿、附件、滚动位置和输入焦点，以便切换观察不打断交流。
9. 作为用户，我希望点击 Router 卡片看到 Router 的只读总览，包括当前 WorkBrief、Ticket 生成、最近路由事实和状态，以便核查调度过程。
10. 作为用户，我希望从 Router 总览继续打开某次 WorkBrief 的只读路由记录，以便定位一次工作的分解和派发。
11. 作为用户，我希望点击 Worker 卡片看到该 Ticket 的只读执行上下文，包括 Assignment 代次、工具事实、输出、报告和证据，以便核查执行结果。
12. 作为用户，我希望 Router/Worker 页面没有输入框或发送按钮，以便我不能误把观察视图当成第二个聊天。
13. 作为用户，我希望 Router/Worker 页面没有停止、重试、审批或工具重放，以便观察和干预是两个明确分开的动作。
14. 作为用户，我希望停止工作和回答问题仍在 Main 工作卡或明确的工作控制区完成，以便每个写操作都有明确工作目标。
15. 作为用户，我希望新 Worker 卡片出现时当前页面和键盘焦点不变，以便后台工作不会打断阅读或输入。
16. 作为用户，我希望新卡片有轻量的未读提示，而不是弹窗或自动跳转，以便我决定什么时候查看。
17. 作为用户，我希望 Worker 完成后卡片保留最终状态，以便之后仍能回看执行历史。
18. 作为用户，我希望已结束的 Worker 卡片可以折叠，但 Activity 仍能搜索全部历史，以便侧栏不会被长期工作淹没。
19. 作为用户，我希望重试或新代次只更新原 Worker 卡片并在详情中切换代次，以便不会把同一项工作看成多个执行者。
20. 作为用户，我希望刷新、重连或 Host 重启后角色卡按持久事实恢复，以便当前与历史状态不会丢失或重复。
21. 作为用户，我希望当前选中的 Worker 卡片在观察项状态更新时继续可读，以便任务完成不会让页面突然清空。
22. 作为用户，我希望 Activity 保留为 Router/Worker 的聚合搜索和分页入口，以便角色卡之外的完整历史仍可查。
23. 作为用户，我希望窄侧栏以头像和状态点保留 Router/Worker 卡片，以便窄窗仍能切换观察。
24. 作为键盘用户，我希望卡片可用 Enter/Space 打开，当前卡有 `aria-current`，新卡片出现不会移动焦点，以便可预测地导航。
25. 作为使用减少动态效果的用户，我希望卡片仍有文字状态和可见标记，以便不依赖动画判断工作状态。
26. 作为 Host 所有者，我希望 Router/Worker 卡片只读取已授权的 Instance、WorkBrief、Ticket、Assignment 和 Session 事实，以便跨工作或跨代次的数据不会泄露。
27. 作为使用只读远端客户端的用户，我希望角色卡和观察视图按读取能力可用，但不能借此获得停止或回答权限。
28. 作为用户，我希望设置里的角色配置继续只负责 Main/Router/Worker 的模型和指令，不把点击角色卡解释成切换运行时身份。
29. 作为用户，我希望设置中的 `Team` 分组改名为 `Roles` 或等价角色配置名称，以便不再暗示旧 Bot 团队。
30. 作为用户，我希望 Router/Worker 卡片的出现、排序和状态更新不改变 Main 的待答问题、在途回复或工作停止约束。
31. 作为用户，我希望历史 Worker 卡片不会把旧代次显示为当前，以便我核查的是当前有效执行安排。
32. 作为用户，我希望看到 Router 与 Worker 的实时状态文字，而不是仅靠颜色、旋转或脉冲动画，以便状态可辨认。
33. 作为用户，我希望从 Worker 观察页返回 Main 后仍看到原工作卡和同一结果，以便观察不会替换 Main 的事实。
34. 作为用户，我希望角色卡不会把 Router/Worker 私聊、@派活或群聊语义带回产品，以便产品仍然是 Main 对用户、Worker 对工作。
35. 作为用户，我希望卡片只展示当前授权范围内的工作标题和状态，以便敏感项目不会出现在无权查看的 Instance。

## Implementation Decisions

### 角色卡模型

- 客户端派生一个统一的 `roleCards` 视图模型，卡片类型只有 `main`、`router`、`worker`。
- Main 是单例卡片，状态来自 Main 健康、当前回合和排队输入。
- Router 是 Instance 级单例卡片。首次出现由持久 WorkBrief、Router 观察项或路由回执触发；状态由工作回执和 Router 观察项合成。
- Worker 卡片按 Work Item/Ticket 建立稳定身份，不按 Session 或 Assignment 建立。相同 Ticket 的重试、换代或重连更新原卡片。
- 一张 Worker 卡片只对应一项工作。工作没有持久 Assignment/Session 事实时不生成 Worker 卡片。
- 卡片列表的活动部分按首次出现顺序稳定排序；完成和停止的卡片进入可折叠历史组。历史只显示有界最近项，完整历史由 Activity 分页读取。

### 侧栏与导航

- 宽侧栏在 Main 卡片下增加“执行过程”区域，依次显示 Router 卡片、活动 Worker 卡片和历史 Worker 组。
- 宽屏不再把底部成员状态条作为角色观察主入口；角色卡成为唯一的角色级导航。窄侧栏继续以紧凑卡片或头像形式保留相同入口。
- 点击 Main 恢复主对话；点击 Router 打开 Router 总览；点击 Worker 打开对应 Worker 只读上下文；当前卡片显示选中态。
- 选中卡片只改变产品内容视图，不改变当前 Main Session、Main 草稿、附件或待答问题。
- 新卡片自动插入但不自动选中、不滚动、不移动焦点。新活动使用轻量未读提示，用户点击后清除。
- Activity 继续作为 Router/Worker 的聚合搜索和分页入口；角色卡与 Activity 不互相替代。

### 只读边界

- 角色卡和 Router/Worker 观察页只能调用现有只读观察能力；不得调用发送、停止、回答、重试、审批、工具重放或 Session 写接口。
- Router/Worker 观察页不挂载 composer、发送按钮、语音发送或任何隐式写入快捷键。
- 停止工作、停止准备、回答当前问题和恢复工作仍从 Main 工作卡或明确工作控制区发起，并携带精确 Ticket、Attention 或 Assignment 目标。
- 卡片本身不提供停止按钮，避免把只读角色卡变成工作控制面。
- 服务端继续按 Instance、WorkBrief、Ticket、Assignment、Session 和代次校验读取授权；猜测身份或写字段必须拒绝。

### 数据与实时状态

- Main 使用现有 Main history、健康状态和活动回合。
- Router 卡片使用持久工作回执、WorkBrief 和现有 Router 观察项；一个 Router 卡片可以汇总多个 WorkBrief。
- Router 总览先使用现有按 WorkBrief 授权的路由观察投影，按工作分组展示。完整共享 Router Session transcript 不属于本 spec 的第一版范围。
- Worker 活动状态使用现有活跃成员查询，历史使用工作观察列表；两者在客户端按 Ticket 合并，避免把活跃状态和历史状态当成两张卡。
- 观察列表继续使用稳定游标和增量合并；刷新、重连和轮询只更新卡片事实，不改变当前选中项或页面。
- 当前角色卡的详情按需读取；打开后增量补读历史，不默认把完整日志写回 Main。
- “实时”指状态和卡片事实随产品事件/轮询更新，详情按页补读；token 级流式输出和完整 Session 实时镜像不在本范围。

### 命名与文案

- `Main`、`Router`、`Worker` 是产品名，不进入界面翻译表。所有语言环境都显示这三个词。
- 侧栏、工作成员、设置 Overview、Memory、Provider 角色标签等处统一使用同一角色名来源。
- 设置中的 `Team` 分组改为 `Roles` 或等价角色配置名称；角色配置卡片只打开配置页，不切换当前 Main。
- 中文等界面语言可以保留，只移除角色名翻译；整个界面强制英文是独立范围。

### 文档关系

- ADR 0001 的 Main/Router/Worker 职责分离和 Router/Worker 只读约束不变。
- R4 三层 UI 方案中“左侧执行过程、Worker 自动出现”的布局继续有效；本 spec 补齐卡片点击、历史、实时状态和验收。
- 原 #135 中“成员状态放在 composer 上方 dock”的放置决定由本 spec 取代；其数据来源、活动 Worker 和只读动作边界继续保留。
- 已关闭的 #97 曾验收“侧栏自动发现 Worker 与历史”；当前实现没有满足该侧栏角色卡行为，本 spec 作为后续修正，不重新打开旧票。
- UI 标准需要补充角色卡的尺寸、状态、折叠、窄栏和焦点规则。

## Testing Decisions

### 测试接缝

- 最高层使用现有产品 UI 挂载夹具：模拟产品 Host 的 `history`、`work-members`、`observe-list`、`observe-read` 响应，挂载完整产品表面。
- 该接缝覆盖用户真正看到的行为：卡片出现、点击切换、只读页面、Main 草稿和焦点、无写请求、历史保留。
- 现有 `product-work-view`、`product-main-voice`、`product-settings-navigation` 和 `work-feedback` 测试可作为同类行为先例。
- 增加一个纯状态单测，验证 Router 单例、Worker 按 Ticket 去重、历史夹持、代次更新和稳定排序。
- 增加 i18n 断言，验证所有语言的 `Main`、`Router`、`Worker` 都不被翻译。
- 如果实现引入 Router 聚合只读投影，则扩展现有工作观察服务测试，覆盖授权、分页、写字段拒绝和跨 WorkBrief 隔离；如果没有新投影，不新增服务端读模型。

### 测试行为

- 侧栏按持久事实显示 Main、Router 和 Worker 卡片；角色名在所有语言下保持英文。
- 新 Worker 卡片出现时不自动切页、不移动焦点、不改变 Main 草稿。
- 点击 Router/Worker 卡片会读取对应观察事实并显示只读上下文；页面没有 composer。
- 卡片点击和观察读取只产生只读请求，不产生停止、回答、重试或工具调用请求。
- 点击 Main 返回原主对话，保留草稿、附件、滚动位置和当前工作事实。
- 相同 Ticket 的重试/换代只更新原卡片；旧代次可以在详情中切换，但不显示为当前。
- 完成或停止的 Worker 卡片保留在历史组；Activity 能分页看到完整历史。
- 窄侧栏仍能通过键盘打开角色观察；当前卡片有 `aria-current`，状态有文字而不只靠颜色。
- 服务端拒绝观察请求中的写字段和猜测身份；只读远端客户端不能通过角色卡取得写权限。

## Out of Scope

- 直接与 Router 或 Worker 聊天、发送跟进、steer、审批、重试、停止或工具重放。
- 把 Worker 恢复成旧 Bot 联系人、群成员或长期私聊身份。
- 恢复旧 Bot roster、群 relay、Main Bot 治理或旧协作历史入口。
- 完整的共享 Router Session transcript 聚合；第一版只提供按 WorkBrief 授权的 Router 总览。
- token 级实时流式输出、完整执行日志实时镜像或新的模型运行时。
- 更改 Main/Router/Worker 的模型、执行、工作或权限架构。
- 整个产品强制英文；本 spec 只固定角色名。
- 移动端 App 的独立布局；本 spec 只要求现有窄窗/窄侧栏可操作。
- 新增自动停止、自动回答或根据角色卡状态自动推进工作的行为。

## Further Notes

- 本 spec 的来源是维护者对当前桌面界面的明确修正：Router/Worker 触发后应在左侧自动出现可点击卡片，点击后查看各自只读上下文和实时状态。
- 这与 ADR 0001 不冲突：卡片是运行观察入口，不是可聊天、可干预的角色会话。
- 建议实施顺序：先统一角色名和文档契约，再做侧栏卡片与点击，再补历史/实时状态，最后补 Router 总览和回归验收。
- 建议默认：一个 Router 卡；活动 Worker 全部显示；已结束 Worker 折叠保留；Activity 保留完整历史。
- 本 spec 发布标签为 `ready-for-agent` 和 `enhancement`；标签表示可用于拆分与实施，不代表已在真实桌面构件上验收。
