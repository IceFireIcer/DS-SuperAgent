# DS SuperAgent 桌面 UI 整改 P0

## Problem Statement

首次进入 Main 时，用户需要从多个并列入口判断如何配置模型。保存供应商凭据、选定 Main 的模型和真正收到回复是三个不同进度，界面应让用户知道当前做到哪一步，以及失败后从哪里继续。

日常使用时，执行目标、工作目录、附件、语音和发送集中在输入区。在窄窗、放大或显示长路径时，用户需要清楚地找到发送动作，并在提交前核对将使用的授权环境。设置提供五个分组和 25 个内容落点，用户还需要通过名称或任务关键词找到正确页签，编辑完成后返回原处。静态审查已覆盖主对话、执行选项、首次密钥输入、Activity 和各设置落点。键盘与运行行为以隔离 profile 和候选构件复现为准。

## Solution

- 缺可用模型时，Main 给出一个明确的下一步。用户通过当前桌面 profile 提供的配置路径完成设置，回到同一主对话，保留草稿并收到第一条回复。
- 设置沿用现有覆盖层、五个分组与页面标识。普通入口打开 General，快捷入口直达目标，搜索可按中英文名称和任务关键词找到现有页面或页签。窄窗有带文字的页面选择入口，离开未保存的 Roles 表单时可以继续编辑或放弃更改。
- 主对话为消息阅读、任务上下文和输入动作建立清晰层级。发送前可辨认当前执行目标与目录或环境，发送后可从接纳回执、回复状态和工作卡得知结果。
- 布局和状态沿用现有主题。在键盘、系统减少动态效果以及支持的桌面窗口范围内，用户可以用相同的流程完成上述任务。

## User Stories

### 首次模型配置

1. 作为首次使用者，我希望看见配置读取中、未配置和读取失败的不同提示，以便知道应该等待、开始配置还是重试。
2. 作为没有可用模型的用户，我希望 Main 给出一个首要操作 `Set up a model`，以便直接进入配置流程。
3. 作为准备使用 DeepSeek 的用户，我希望看到当前 profile 实际提供的登录或 API key 路径，以便选择可完成的一种方式。
4. 作为使用自定义模型的用户，我希望直接打开当前可用的原生 Models 或产品 Models，以便找到真正能操作的配置入口。
5. 作为已有可用模型目录的用户，我希望 `Choose a model` 打开 Roles 并聚焦 Main，以便为主对话选模型。
6. 作为填写 API key 的用户，我希望看到字段标签、掩码和显示控制，以便检查输入并安全提交。
7. 作为正在保存 key 的用户，我希望看到保存状态并防止重复提交，以便判断是否需要等待。
8. 作为遇到 key 保存失败的用户，我希望在原位置看到错误和重填提示，以便安全重试并保留普通消息草稿。
9. 作为 key 已保存但配置刷新失败的用户，我希望重试读取配置，以便确认已经完成的写入并继续选模型。
10. 作为完成登录或保存 key 的用户，我希望分别看到凭据状态和 Main 模型就绪状态，以便知道下一步。
11. 作为发现角色配置冲突的用户，我希望查看最新版本并保留自己的编辑意图，以便审核后再保存。
12. 作为从配置返回的用户，我希望回到同一个 Main 和原有草稿，以便由我发送首条消息并看到回复。

### 设置导航与编辑

13. 作为打开普通设置的用户，我希望落到 General，以便从稳定、熟悉的位置开始。
14. 作为从 Account 打开自动化、用量、模型或连接器的用户，我希望跳到对应内容落点，以便直接完成当前任务。
15. 作为在页面间跳转的用户，我希望父页和页签同时显示正确选中态，以便知道自己在哪里。
16. 作为知道功能名称但不了解分类的用户，我希望能用中文、英文及 API key、OAuth、schedule、backup 等关键词查找设置，以便快速定位可用入口。
17. 作为搜索没有匹配的用户，我希望知道当前查询无结果并能清除关键词，以便回到完整导航。
18. 作为使用最小窗口或放大显示的用户，我希望用带文字的页面选择入口打开任一现有落点，以便无需横向挪动即可找到和操作设置。
19. 作为键盘用户，我希望焦点按视觉顺序移动并保持可见，以便操作导航、页签和表单。
20. 作为打开嵌套选择器或确认框的用户，我希望 Esc 优先关闭最上层交互，以便继续留在原操作位置。
21. 作为关闭设置的用户，我希望回到原触发按钮或可用的替代位置，以便继续之前的任务。
22. 作为有未保存 Roles 编辑的用户，我希望关闭、切页或从快捷入口跳转时能选择保留编辑或放弃，以便自己决定草稿的去留。
23. 作为使用即时保存偏好的用户，我希望在原控件附近看到实际结果，以便确认修改是否生效。
24. 作为已连接远端 Host 的用户，我希望入口和状态反映当前授权，以便理解哪些操作可以在这次连接中完成。

### 主对话与日常输入

25. 作为阅读已有消息的用户，我希望新回复到达时保留正在阅读的位置，以便继续查阅历史。停在末尾时，我希望消息继续跟随。
26. 作为阅读长代码、表格或路径的用户，我希望在相应内容内部滚动或查看完整值，以便保持窗口其他操作可达。
27. 作为准备提交工作的用户，我希望发送前看到执行目标、目录或环境，以便核对将使用的授权范围。
28. 作为为下一条本机请求临时选目录的用户，我希望折叠侧栏、查看设置或提交失败后仍能继续使用这一选择，以便完成当前任务。
29. 作为已有工作在运行的用户，我希望那项工作继续归属原授权环境，新请求使用本次选择，以便核对各自的运行位置。
30. 作为带附件发送的用户，我希望看到附件和环境发生冲突时的具体原因，以及返回原环境或移除附件的操作，以便修正输入。
31. 作为使用中英文输入的用户，我希望输入框和发送键有清楚的可访问名称与反馈，并保留输入法组合期间的行为，以便按预期发送。
32. 作为遇到提交或回复故障的用户，我希望区分输入尚未接纳和输入已接纳但回复失败，以便选择提交重试或从已有回执继续。
33. 作为需要中断的用户，我希望分别控制当前 Main 的生成和一项明确的工作，以便停止想要停止的对象。
34. 作为使用连续语音的用户，我希望只听到本次输入对应的完整回复，以便保持对话连续。遇到问题卡、暂停、停止回复或窗口隐藏时，我希望音频及时停止。
35. 作为暂时进入设置或 Classic Agent 的用户，我希望回来时看到原 Main 的消息、草稿、附件和工作状态，以便从原处继续。
36. 作为使用屏幕阅读器或减少动态效果的用户，我希望辨认当前选中项、表单错误和处理状态，以便完成相同的配置、输入和设置任务。

## Implementation Decisions

1. **产品接缝。** 在现有单一产品 profile 与 DSH 客户端内完成改动。沿用 DSH 公开入口、现有产品命令、客户端事件和本机/远端授权区分。测试数据使用隔离产品目录与模拟模型。客户端 bundle 由源文件生成。
2. **稳定的导航目标。** 继续使用已裁定的五组、四组页内标签和 25 个内容落点。普通入口打开 General，显式子页直达，显式父页使用首个可用子页。入口、导航与搜索共享目标映射，按 profile 和访问权限显示。Automation 直达定时任务，Usage 直达用量，连接器快捷入口直达连接器。
3. **搜索和布局。** 搜索可见的页面、页签和经评审的中英文关键词。同名结果显示父页与页签，点选后更新当前选中状态。普通表单采用有限版心与单一内容滚动区，数据表和代码可局部滚动。960/720 CSS px 作为测量起点，按内容区与实际最小窗口表现收敛。
4. **设置生命周期。** Tab 与 Shift+Tab 在可见模态控件间循环。Esc 逐层处理，遮罩点击、关闭、切页和显式跳转共享 Roles 草稿判定。默认动作是 `Keep editing`，`Discard changes` 完成原请求的退出或跳转，提交仍从表单 `Save` 发起。保留同次打开期间的返回位置。关闭后恢复触发点，触发点消失时使用对应回退焦点。
5. **模型引导。** 按当前 profile 提供可用路径。公开登录入口、供应商可写权限和可用的原生或产品 Models 决定显示内容。已有可用目录时提供 `Choose a model`，由用户打开 Roles 并聚焦 Main。配置成功后刷新状态，在同一主对话恢复焦点。Router、Worker 的配置需要由现有工作就绪状态表达。
6. **保存、刷新和敏感字段。** 首次引导使用现有供应商写入命令。凭据写入、配置读取和模型回复各有独立结果。key 输入默认掩码，失败后清空并提示重填。模拟 key 原值应从持久客户端存储、日志、诊断及归档截图中缺席。异步结果只应用于原操作和相应实例。保存成功但重读失败时提供只读重试。角色配置版本冲突沿用重新读取、合并与审核保存。
7. **主对话阅读与输入。** 消息区单独滚动并保留历史锚点。输入区只有一份可访问的文本输入，发送是主要动作，附件、听写和连续语音使用相应控制。执行目标、目录或环境靠近输入。菜单根据剩余可用空间展开，键盘焦点及错误项可滚动进入视口。
8. **接纳事实与授权。** 现有产品协议决定接纳、回复和工作状态。同一未决输入的安全重试使用原操作身份。下一条本机请求的临时工作目录在对应请求被接纳后恢复默认，取消、授权失败和提交前失败保留选择。原工作及跟进保留其已绑定的执行环境，附件继续受上传环境约束。
9. **停止、语音和原有视图。** 停止生成作用于 Main 的当前回复。停止工作作用于明确的工作，按持久状态与原有授权呈现结果。连续语音按原接纳身份匹配回复，并在规定的交互停止时释放音频。回归 Work、Activity、问题卡和同窗 Classic Agent 往返。
10. **主题与可访问性。** 复用现有主题、动效和次级控件。状态用文字与可辨视觉标记。常规文本对比度目标至少 4.5:1，大字与必要控件或状态指示至少 3:1。图标按钮有可访问名称，焦点可见。普通动效与系统减少动态效果下可完成同一路径。

## Testing Decisions

**主要测试入口**为产品现有浏览器探针。用一次性 profile 驱动真实渲染、产品命令和预设的模拟模型回复，以可访问名称、可见状态、设置落点、持久消息和回执断言结果。现有设置外壳、模型引导、输入、语音及翻译定向测试覆盖容易稳定复现的分支。桌面打包探针复用同一路径并补齐真实窗口、焦点、按键、系统动效设置及构件退出验证。

| 验收场景 | 用户可观察的通过条件 |
|---|---|
| P0-01 改前基线 | 在隔离 profile 复现 Main、Activity 和设置代表路径。为 29 个审查场景记录对应设置目标或触发方式，记录候选 SHA、构件指纹、窗口及未复现场景。 |
| P0-02 首次配置 | 无配置启动，走可用的 API key 或已有模型目录路径。选择 Main 模型，回到同一主对话，原草稿与可用焦点仍在。用户主动发送，得到一条接纳和对应的一条模拟回复。 |
| P0-03 配置边界 | 模拟配置读取失败、key 写入失败、写入成功后刷新失败、角色版本冲突、取消及公开 slot 缺失。恢复动作与当时结果一致，截图、诊断和持久客户端存储通过占位密钥检查。 |
| P0-04 页面查找 | 从普通入口、Account、Main 引导、页内链接和中英文搜索进入。核对 25 个内容落点、正确的页签、`backup` 对应的 Status 和 Automation 对应的定时任务。零结果能清除并回到分组。 |
| P0-05 编辑与焦点 | Roles 有更改时分别触发 Esc、遮罩、关闭、切页和快捷导航。继续编辑保留草稿，放弃后到原目标。验证嵌套 Esc、Tab 循环、焦点可见及关闭后的返回。 |
| P0-06 宽度、缩放与主题 | 实测最小桌面窗口及宽窗，抽验断点两侧与 100% 至 200% 代表缩放，覆盖四主题浅深和普通或减少动态效果。长路径、长模型名和中英文标签可读，核心操作可达，弹层在视口内。用键盘及平台可用的屏幕阅读器核对核心路径。 |
| P0-07 目录与附件 | 让工作在 A 运行，为下一条本机请求选 B，经折叠和设置往返、取消及授权失败后仍保留 B。接纳后恢复默认，原工作留在 A。附件目标冲突可恢复。 |
| P0-08 提交和停止 | 注入提交失败、接纳后回复失败和待确认结果。同一未决输入的重试对应原回执。分别停止 Main 生成与明确工作，校验范围和人工停止状态。 |
| P0-09 语音与既有视图 | 用现有测试入口检查单次听写与连续语音、对应回复匹配、问题卡或窗口切换释放音频。检查 Work、Activity、问题卡和 Classic 往返保持访问与原主对话归属。 |
| P0-10 候选证据 | 桌面包的 bundle 与候选源码一致。记录平台、构件指纹、用例实测和自然退出。真实服务与设备的结果按环境逐项记录，进入交付范围的真实登录使用真实账号验收。发布沿用同一候选的完整 CI 门槛。 |

## Out of Scope

- 应用内独立设置视图、六组导航重排、主题替换、窗口最小尺寸调整。
- Work 与轨迹的视觉重排。此类改动以取得对应的独立截图并确认具体用户路径为前置。
- 新模型供应商、额外登录协议或独立连通性检测，以及新增 Host API、权限、数据迁移或客户端表面。
- 连接器、手机、凭据管理、监控和其他 P1/P2 业务页的改版。其现有设置落点、授权入口与必要导航回归属于本规格。

## Further Notes

规格范围为已确认的 P0。先取得基线，再交付设置目标解析与焦点返回，随后跑通首次模型配置和第一条 Main 回复。设置搜索、窄窗与草稿保护属于设置路径验收，日常输入按自己的工作目录、附件、语音与工作状态用例验收。实施工作应按可独立验证的用户路径拆分。
