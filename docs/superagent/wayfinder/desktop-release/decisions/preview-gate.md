# 确定 Windows 桌面首发的放行门槛与证据记录

正式决策票：[确定 Windows 桌面首发的放行门槛与证据记录](https://github.com/IceFireIcer/DS-SuperAgent/issues/197)。类型：`wayfinder:grilling`。状态：已关闭。

## Question

Windows x64 公开预览发布前，如何记录同一候选提交、公开包、隔离产品数据与核心流程（无项目时只启动 Main；用户创建项目后由 Router 分派两个可独立交付的并行 Worker）的放行证据？明确 mock 证据的适用边界、最低验收场景、结果记录、签核及失败处置。公开后无需用户承担试用或反馈义务。不要求未声明支持的外部渠道验收；稳定版证据底线由稳定版决策票决定。

## Resolution

公开下载前，维护者须签核具体的 Windows x64 候选包，记录以下四项：

1. 首次启动：在隔离数据下打开候选包，不自动创建项目或指定工作目录；用户可直接和 Main 对话，Router 与 Worker 均不启动。
2. 并行交付：用户从侧边栏创建项目、选择文件夹，向 Main 提一条含两项独立工作的请求。两个 Worker 的执行时间须有重叠；A 等待用户回答时 B 先交付，回答 A 后其结果也回到原对话。只有两张工作卡不算通过。
3. 跨目录授权：用户明确要求时可读取项目外文件；修改前 Main 先询问。若拒绝，文件保持不变，不依赖该权限的工作仍可完成。
4. 更新与回滚：可以自动检查和下载，用户未确认时不得安装；更新失败后能回到上一可用版本，项目文件不变，个人 DSH 数据不被写入。若涉及产品数据迁移，备份必须可恢复。

一份放行记录绑定候选提交 SHA、包的 SHA-256、必需 CI 结果、各项证据与已知限制，由维护者签核。预览对话与编排流程可使用 mock 模型，须明确标注，不得据此声称真实模型已验收。任一必需项失败、缺证，或换包仍引用旧包记录，均不放行。本决议只定门槛，不是实际候选包的放行记录。
