# 确定桌面稳定版的 Go/No-Go 门槛

正式决策票：[确定桌面稳定版的 Go/No-Go 门槛](https://github.com/IceFireIcer/DS-SuperAgent/issues/198)。类型：`wayfinder:grilling`。状态：已关闭。

## Question

Windows x64 首发为公开预览，不设内测、邀请码或反馈义务；不得将用户试用反馈作为稳定版晋级的必要条件。既定稳定版底线是同一候选 SHA 通过全部必需 CI、所有声明支持平台的包与核心流程验收，并至少以一个声明支持的真实模型跑通核心流程；未声明支持的外部渠道与设备不构成阻塞。请决定自愿公开反馈的处理方式、Main 半双工能否作为稳定版已知限制、候选 SHA 改动后的重验规则，以及最终签核标准。

## Resolution

维护者授权代定以下规则，不代表对当前候选包签核：

- 对同一候选提交记录全部必需 CI 结果。每个声明支持的平台均记录构件 SHA-256，并在该包上完成四项验收：无项目仅启动 Main、多个 Worker 独立并行交付、跨目录授权与拒绝、更新确认与失败回滚。至少一个声明支持的真实模型跑通端到端核心流程，不能以 mock 替代。
- 提交 SHA 变化按新候选重新验收；同 SHA 重新打包也要核对新构件摘要并重新执行包级检查。维护者逐一核对提交、构件摘要、证据和已知限制后签核，仅对记录中的构件放行。
- Main 半双工可以作为已披露限制，前提是用户输入不会静默丢失、其他 Worker 不会被阻塞。违反授权或数据隔离、数据丢失、更新或恢复失效、核心流程被破坏，以及证据缺失或失败，一律不放行。仅有已披露且有可行绕行办法的轻微缺陷，可以放行。
- 公开反馈自愿，不以试用时长、人数或反馈数量作为门槛；收到的报告按实际影响归类，触及上述阻塞条件按同一标准处理。
