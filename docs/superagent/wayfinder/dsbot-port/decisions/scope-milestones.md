# 确定首版与全量 C 域范围及里程碑：待决问题

对应决策：[确定首版与全量 C 域范围及里程碑](https://github.com/IceFireIcer/DS-SuperAgent/issues/136)。

## 问题

确定迁移范围与里程碑：是接受“首版 21 个入口、17 页可用、7 页空态”，还是承诺全量 C 类（98 个上游调用 → 50 族，≈128.5 人日）？哪些 C 域必须做（团队/群聊、连接器、IM/手机、浏览器、电脑操控、本地 Agent），哪些可以长期 fail-closed？全量单人 8–10 个月是否接受，是否需要并行拆分？

## 约束与已知依据

- 用户已定“不裁剪”，但“页面存在”与“能力实现”是两件事；本票决定后者。
- C 类含电脑操控 53 族、≈257 改造点（±30%）；团队/群聊一域 ≈42 人日。
- 首版最小闭环 21 入口、16 个 product endpoint，≈9 人日后端 + 10–15 人日 UI 接线。

## 产出

首版与后续里程碑的范围表、每域的启用顺序、明确的“长期不实现”清单。
