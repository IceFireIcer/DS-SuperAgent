# Main 语音、停止和 Classic 往返（#191）

Main 回复在 Classic Agent 打开期间完成时，旧输入的接纳回执只清除它提交的那份草稿。等待期间在同一 Main 写下的下一条草稿会保留，重复输入相同文字也一样。未发送附件往返后仍属于原执行环境，只有主动发送才会提交一次。

## 定向验证

| 路径 | 已验证行为 |
| --- | --- |
| Main 和工作分别停止 | 同时存在回复和在途工作时，两种动作分别使用 `messageId` 和 `ticketId`。工作卡保留接纳回执并等待设备确认。Main 停止待确认时禁用重复停止和语音续听，确认后迟到的匹配回复不会被朗读。 |
| 人工停止 | Host 定向测试验证停止 Main 后已接纳工作仍可完成，停止选中的工作不会取消其他执行，人工停止跨重启保留，未确认的取消保持等待。 |
| 单次听写和连续语音 | 通过模拟识别验证单次听写填入草稿，用户主动发送。连续语音只读本次接纳输入匹配的完整回复。问题卡、暂停、隐藏或离开使旧识别、合成或回执无法继续该语音轮次。 |
| Work、Activity 和 Classic | 定向测试验证 Classic 往返恢复原 Main 焦点、草稿、附件和工作回执。隔离 Chromium 验证 Work、Activity 和问题卡的只读或交互路径及 Main 停止。隔离 profile 的 Classic 探针验证独立原生会话、授权撤回和原 Main 回执不重复。 |

在 Windows 的 Node `24.22.3` 下串行运行定向测试，使用隔离 profile 和模拟模型。类型检查、构建和生成客户端一致性检查通过。重新生成的客户端也带入 #190 已落地的重试提示与样式。

真实麦克风和远端设备待实机验证，打包候选验收见 [#192](https://github.com/IceFireIcer/DS-SuperAgent/issues/192)。
