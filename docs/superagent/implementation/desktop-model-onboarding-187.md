# 完成首次模型配置并收到回复（#187）

Main 区分配置读取中、缺模型和读取失败。缺模型时，`Set up a model` 展开当前 profile 可用的公开登录、API key 或模型设置入口。目录已有可用模型时，`Choose a model` 打开 Roles 并聚焦 Main 的模型字段。角色配置保存并确认 Main 就绪后，首次引导打开的设置自动关闭，焦点回到原主对话输入框。

API key 默认掩码。提交时清空输入，失败后提示重新输入。取消编辑或失去写入目标时清理临时值。凭据或角色配置写入成功后，读取故障有独立反馈，重试仅读取配置。继续沿用现有产品动作与公开 DSH 接口。

## 验证

- Windows Node `24.22.3` 下，模型引导、设置导航、文案和反馈共 24 项定向测试通过。覆盖无公开登录入口、取消、写入失败、重复刷新失败、写入目标失效和焦点返回。
- 隔离 profile 的 Edge Chromium 探针使用合成凭据与公开 mock 模型目录，验证默认掩码的截图、两次写入各自只发生一次、刷新重试及原主对话草稿。角色配置写入通过实际产品命令。用户手动提交草稿，产品历史中有一条接纳消息和以该消息 ID 关联的模拟回复。
- 浏览器检查持久存储、诊断状态和收集到的客户端错误未包含合成密钥。密钥写入使用浏览器夹具，真实供应商密钥写入日志与实际 DeepSeek 登录仍待相应环境验证。一次探针运行触发已有的 Main 启动断言，复跑通过。
- 类型检查、构建、生成客户端一致性、改动文件 lint 和 UI 边界检查通过。
