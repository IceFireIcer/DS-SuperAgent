- 工单：R5-15 / #107；规格：`docs/superagent/spec-r5.md` D09、D12、D13 与 A21。
- 基线：`dev` 的 `4a6e060`；隔离分支 `feat/107-resource-credentials`。

## 已实现

`ResourceCredentials(storage, instanceId, vault)` 是仅由受信 Host 构造的领域接缝。创建和轮换只接收先在 vault 中登记的引用；业务库保存 Instance、资源元数据、授权、请求状态和不含密钥的命令回执，不保存密钥值。资源没有默认 grant。授权单独指定 Main/Router/Worker、可选精确 workItemId/Environment/sourceInstanceId 和用途 `source`、`tool`、`outbound`；来源接收和外发必须指定来源 Instance。缺失、失权、跨 Instance、已删除均明确拒绝，无其他来源或全局凭据回退。

受信调用方可以用 `create`、`update`、`request`、`cancel`、`grant`、`revoke`、`delete`；所有写命令有稳定 commandId 和持久回执，相同命令同输入去重、异文冲突。更新/授权/撤销/删除使用 revision 条件。`get`、`list`、`getRequest` 只返回不含 vault 引用的视图。`use` 在每次调用时检查当前 grant，再委托受信 vault 和消费函数使用秘密；vault/消费函数异常只转为固定错误码，不透传异常文本。删除持久封禁资源且从业务记录去掉 vault 引用；vault 中的物理清理由后续 Host 集成负责。

SQLite/PostgreSQL 使用同一现有 `Storage` 事务协议和 `RecordKind` 白名单，无新专用表。新增 `resource-credential`、`resource-command`、`resource-request`；按并行 R5-14 的文件所有权约定，仅在同一白名单中登记 `product-attachment`，本票没有实现附件行为。

## 受信接口与集成边界

- Host 需提供持久且按 Instance 隔离的 `CredentialVault.assertReference(instanceId, reference)` 和 `withSecret(instanceId, reference, consume)`，由其负责安全存放、轮换后旧值清理和删除后的物理删除；本票没有连接 DSH credentials 或 OS vault。vault 引用只在受信创建/轮换命令和内部记录出现，不进入模型工具参数、日志、UI 或 manifest。
- Engine 必须在已认证的受信用户设置入口调用写命令；不能把类实例或 `use` 的消费回调交给 Agent。Engine/Host 要把 `source` 绑定来源接收、`tool` 绑定当前工作与 Environment、`outbound` 绑定发件依据，并在实际适配器调用点再次查当前状态；当前没有这些运行路径的接线。
- `use` 对一次已开始的消费不提供可中断撤权；撤销或删除提交后，后续调用会拒绝。Host 若要求对在途外部动作即时撤销，需另加租约/取消与副作用对账，不能声称本接缝已经解决。
- UI 仍需提供现有设置页中的资源创建、授权预览、轮换、取消请求、撤权和删除操作及真实回执；旧资源导入需要显式预览、选择和冲突恢复。本票没有 UI 证据、真实 vault、真实来源/工具/外发或完整 Engine 产品验收。
