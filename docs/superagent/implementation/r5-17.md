## 交付行为

主对话复用既有 `FolderMenu`。用户可在设置中保存 Instance 默认工作目录，也可在发送消息前为本次工作选择目录；选择器复用 DSH 公开 `directoryPicker`，无原生选择器时保留输入已有目录路径的入口。产品 Host 验证目录、排除产品状态目录及个人 DSH 数据目录，为明确选择建立独立 LocalEnvironment，并持久保存目录记录和版本化默认值；重启后恢复原绑定。目录命令按 ID 与输入指纹重放，冲突拒绝。

Main 输入在接纳事务中固定当前 Environment ID。WorkBrief、Ticket Trigger、Assignment、Worker Session 与用户可见工作卡保留该选择；修改 Instance 默认不会移动已接纳的工作。原有跟进、停止、恢复及重试继续按同一 Ticket/Assignment/目录处理，两个 Worker 不共享全局 currentEnvironment。未选择目录时 Main 仍可聊天，但该条输入不能在之后突然获得工作目录并建立新工作。

产品 LocalEnvironment 显式开启 `command` 权限，在同一个 DSH 公共 fs/subprocess 执行世界提供 `run_shell`、`start_shell` 和 `start_terminal`。Shell/PTY 命令受输入长度和期限限制，使用所选目录和 DSH 子进程的清理环境；后台 job 由 Assignment 管理，终端输出写入该 Environment 的受控 asset store，Worker 可按 job ID 读取有界状态和分页 spill。原 Worker 收到完成事件并自行决定后续，工具结束不会自动完成 Ticket。

子代理继续使用 DSH 公开 `parentAgent`、原 Worker Mandate、目录、worker route 和授权工具；不引入旧 Bot 互派、群工具或额外 Ticket。停止与代次结束使用已有作业/子代理归属清理和确认路径；预览服务继续按已有保留规则处理。

## 限制

当前 DSH 公共 `spawnTerminal` 在 Windows 的最小复现中，`handle.done`、`handle.terminate()` 与 `ctx.fiber.dispose()` 均完成后仍留下一个 Node `MessagePort`，测试进程不会自行退出；业务 job 的已确认退出与输出不受影响。本票没有修改 DSH，PTY 测试必须显式使用 Node 的 `--test-force-exit`。Windows Host 退出时的自然进程清理仍需上游 DSH 修复或后续独立验证，不能把这条测试称为完整生命周期通过。

本票只打通本地选择与本地 shell/PTY。远端目录、远端 Shell/PTY、设备断线对账及跨设备搬迁留给 R5-29—31；真实模型、UI 原生窗口和完整托管组合另行验收。工作目录限定执行的 cwd 与文件工具范围，DSH subprocess 本身不提供操作系统级的文件沙箱；不把 cwd 说成任意 shell 命令的 OS 隔离。

## Spec-review P1 补正：启动与停止并发

以 `628f5ea` 为基线修复 #109 的本地后台启动竞态：`start_shell`、`start_terminal` 和本地 `start_command` 现在先在 Assignment 事务中记录带稳定 ID 的 `starting` Job，再调用 DSH 公开进程接口；启动响应只在原 Assignment 仍运行、Job 未被取消时激活为 `running`。停止事务能枚举这条意图，停止路径等待启动句柄到达并以 `waitForExit` 确认静止后才记录 `cancelled`。启动调用迟到或 5 秒内无法证明范围静止时，Job 保留 `unknown`、Stop 保留 `stopping` 和未确认标记；迟到句柄一到即请求终止，不能重新激活为可继续的 Job。未改预览独立保留规则、原 Worker 完成唤醒或 DSH 源码。

Node `24.22.1` 定向验证：新增主对话回归覆盖 Shell/PTY 启动窗口、已发停止但尚未确认退出、退出不可证实以及 5 秒后到达的句柄；`product-shell-stop` 5/5，结合 Jobs、预览、停止、子代理、远端执行与真实 PTY 的相关测试共 42/42（补正后的同组复验）。Super-agent typecheck、lint 与 `git diff --check` 通过。集成分支上 Node 24 的后台停止、Jobs、目录、子代理、日程、远端停止、飞书及远端网关定向回归 38/38。真实 PTY 功能用例依照上述 Windows DSH `MessagePort` 限制使用 `--test-force-exit`；未跑全量 CI，未做真实模型或设备验收。
