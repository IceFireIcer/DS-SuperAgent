# R5-26：预览并选择导入记忆资源

- 工单：R5-26 / #118；分支：`dev`。
- 直接前置：R5-21 / #113 已完成代码验收。
- 范围：旧 Bot 记忆的可移植副本导入；不读取旧 Bot 运行时、旧 `~/.dsh`、旧 roster/Session 或未完成工作。

## 用户行为

现有 Memory 设置页新增“导入记忆”。用户选择一份有界的 `ds-bot-memory-export` JSON 副本后，页面显示原件 SHA-256、原归属者/Instance、每一项的原归属范围和完整可导入文本。预览不会创建 `product-memory` 条目，也不会改动或删除用户选择的文件。

每个可导入项默认不选中。用户必须逐项勾选，并明确选择当前 Instance 中的 Main、一个现有工作或 shared 目标；shared 还必须勾选当前 Main/工作接收者，空接收者或 global 不会成立。界面同时显示目标 Instance。导入创建普通记忆，之后可继续使用现有查询、分享范围修改、工作读取授权/撤权、遗忘和全文读取。

批次状态分为 `ready`、`partial`、`completed`、`cancelled`；只有全部项目已导入才是 `completed`，冲突、拒绝或未完成项保持 `partial`。项目状态为 `ready`、`rejected`、`imported`、`conflict`。取消保留已导入条目和未完成项，重试只把批次重新开放。目标内重复记录目标 scope 和已有记忆 ID；同一原归属者/Instance 下的同一来源 ID 若内容哈希改变，标记 `SOURCE_CONTENT_CONFLICT` 并指向较早批次，不能继续导入。部分导入保留未选项的 `ready` 状态。相同文件内容得到相同批次，同一命令重放返回原结果；同一来源项再次提交到同一目标复用原条目，改投另一目标被拒绝。设置页列出最近 20 个持久批次，可直接重新打开；打开另一批次会清空前一批次的勾选与目标，独立查询最多返回 100 个。

## 可移植格式

格式只包含归属展示和文本，不接受旧身份、权限、Session、Ticket、Assignment 或执行状态。根、归属和项目对象均拒绝未知字段。

```json
{
  "schema": "ds-bot-memory-export",
  "version": 1,
  "origin": {
    "owner": "Legacy Alice",
    "instanceId": "legacy-instance",
    "kind": "bot",
    "exportedAt": "2026-11-16T00:00:00Z"
  },
  "items": [
    {
      "id": "legacy-memory-1",
      "text": "A fictional portable fact",
      "originalScope": {
        "kind": "work",
        "role": "Legacy Writer",
        "work": "Old fictional work"
      }
    }
  ]
}
```

文件最多 512 KiB、50 项；浏览器传原始文件的 base64 bytes，Host 严格按 UTF-8 解码（接受一个 BOM），按原始 bytes 计算 SHA-256，不发生字符串重编码。每项文本按现有记忆规则限制为 4096 bytes。私钥、Bearer、`access_token`、`refresh_token`、`client_secret` 等赋值及常见 GitHub/OpenAI/Slack/AWS token 样式不会导入，也不会保存在批次中。原归属元数据同样拒绝凭据样式文本。

## 持久状态与公开接缝

- 新增通用记录种类 `product-memory-import`、`product-memory-import-item` 和来源身份 `product-memory-import-source`，沿用 SQLite/PostgreSQL 共用的 `RecordKind`/`Storage` 事务协议。
- Engine 公开 `previewProductMemoryImport`、`getProductMemoryImport`、`commitProductMemoryImport`、`cancelProductMemoryImport`、`retryProductMemoryImport`。
- 本地产品 Host 接入 `memory-import-list/preview/read/commit/cancel/retry`；所有请求校验 Instance 和字段，远端 client 仍在 Host 被拒绝。预览请求只接受有界 canonical base64，服务器解出原始 bytes 后才校验格式和哈希。
- 预览、批次状态和导入条目在同一业务事务提交。导入项保存 `provenance`，包括批次、来源项、原文件哈希、原归属者和原 scope；普通记忆仍可直接遗忘，不会删除导入批次或用户原件。
- 目标 scope 先通过现有 work/Main 校验；导入冲突在最多 1000 条活动记忆范围内检查，并以规范化 scope 与文本哈希判定。活动扫描超限时整次导入失败，不产生部分提交通知。

## 验收对照

1. 原归属、目标 Instance/角色/工作/shared 范围和导入文本都在设置页显示；默认不选择，Main、工作与 shared 接收者均必须显式指定，默认/global 不成立。
2. 选择由 commit 的逐项结果投影，最近批次可从持久列表重新打开；取消/重试为持久批次状态；冲突记录原因和已有记忆 ID；部分导入保留逐项状态。同内容批次、同命令和同来源项提交均不重复创建记忆。
3. 格式不接受旧 runtime 对象，导入后只创建新的 scoped `product-memory`；原件只读，哈希和字节在预览/导入测试中保持不变。
4. 导入条目使用普通 MemoryEntry，定向测试覆盖新界面数据源的列表/查询、分享更新、工作读取授权/撤权与遗忘；资料全部为虚构。
