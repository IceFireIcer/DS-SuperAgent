# R5-36 升级、备份并观测新产品自身状态

[GitHub #128](https://github.com/IceFireIcer/DS-SuperAgent/issues/128) · [R5 规格](../spec-r5.md) D08、D10–D13，A11、A15、A19、A22、A24 · [双轴复核](reviews/r5-36.md) · [T55 证据](t55-evidence.md#r5-36-product-lifecycle)

## 已交付

- 现有设置页读取产品健康、用量覆盖、更新器状态、版本与有界操作记录；可检查、安装、下载诊断摘要、备份和确认恢复。未启用 Electron 更新器的平台显示明确状态。纯管理操作不经过 Main，不创建 Ticket。
- 用量通过产品公开查询读取近期 Main、Router、Worker Session，并按精确会话序列归入 Router work brief、Worker ticket/work item 和未归属调用。缺失/冲突 Session、预算裁剪、记录截断、未归属和无定价目录均显式报告。UI 标明会话外监督、子代理和准备调用不在范围内。
- SQLite 使用在线一致备份 API；Session 树由公开 JSONL provider 独立枚举、逐条读取并核验目录计数、事件摘要与哈希。不支持业务 schema、替代 Session provider、不可读 Session、未解决工作与外部副作用不会被误报为可恢复升级点。自动安装前生成新备份并要求其可恢复。
- 恢复日志在首个文件交换前持久化。新状态启动成功后先写入 committed 状态再删除旧文件；启动中断能幂等回滚或重试清理。新旧状态的外部 Effect、工作授权/stop、Host fencing 与身份不同会阻止交换，客户端游标按单调值保留。
- 备份和恢复只在确认 Host 退出后持数据锁执行。启动失败时，原生错误对话框会显示近期诊断，并允许重试启动或撤销尚未提交的恢复。修复更新也要先通过备份检查。安装请求与下次启动核对的版本写入操作日志，收到异步安装错误时会恢复 Host。
- 修改了近期角色用量索引读取的唯一所有者、对话框与用量范围，以及定向回归测试；客户端由 `npm run build` 重新生成。

## 验证

Node 24 定向验证涵盖桌面更新、备份/恢复、冷启动重试和日志 **57/57**，Engine 用量、Session 计数和产品 HTTP **4/4**，以及客户端翻译和设置行为 **5/5**。角色配置、近期索引和 SQLite v1→v2 迁移中断恢复测试 **8 通过、1 个 Windows PostgreSQL 夹具跳过**。Super-agent typecheck、lint、build、客户端生成一致性、UI 边界和实施记录检查通过。

公开 DSH `profile-boot` 在临时目录用 mock 模型完成 Main 对话、两项本地 Worker 工作及一项等待远端的工作。分别备份和恢复业务库与 Session 后重新启动，验证原工作历史、人工停止和关闭的日程授权仍有效。

本票使用定向验证。安装错误恢复由 Electron/updater 测试替身覆盖，公开 Profile 恢复使用同一固定 DSH 版本。不同版本安装包升级、托管 PostgreSQL、真实模型/飞书及系统关机中断仍待验收。手动替换安装包的平台在新版首次启用产品 Profile 前备份。T55 总体验收仍开放。
