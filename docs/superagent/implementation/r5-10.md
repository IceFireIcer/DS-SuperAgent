# R5-10：在现有设置中配置三层角色

- 工单：[R5-10 / #102](https://github.com/IceFireIcer/DS-SuperAgent/issues/102)。
- 前置：[R5-05 / #97](r5-05.md)。
- 日期：2026-11-15；实现位于 `dev`，未发布。

## 交付行为

现有产品界面新增 Super-agent 设置页，在同一页选择 Main、Router 和 Worker 的模型、公开 DSH thinking effort 与指令。模型目录和凭据状态来自 DSH 的公开 LLM、settings 和 credentials 服务；保存前异步复核 provider/model/effort。Provider key 只单向写入受控凭据服务，响应仅返回是否已配置。

产品协议新增 `settings`、`settings-save`、`settings-efforts` 和 `provider-key`。读取返回当前 revision、角色、provider/model 目录、版本历史和最近的 `RoleConfigUse`；保存沿用既有 revision CAS、命令去重和请求边界生效，不创建 Ticket、WorkBrief 或 Assignment。Router 非空模板必须保留 `{{goal}}`，Worker 必须保留 `{{goal}}` 和 `{{constraints}}`；未知占位符、保留技能名和超限继续拒绝。

保存冲突不覆盖服务器上的新版本，界面保留完整草稿；用户可以把本地实际改过的字段重接到最新 revision，再检查并保存。最近的配置使用与 Main 工作卡、Router/Worker 观察详情显示对应 revision，区分一次回合实际使用的版本和以后将使用的新版本。已开始的回合继续使用启动时路由，后续请求才读取新配置。

## 验证

- Super-agent 定向回归 26/26：配置校验/CAS/异步复核、Main 在途旧版本与新回合新版本、authoring 权限、产品 HTTP 设置、并发冲突、无效 effort/模板和不建工作。
- DS Bot 定向回归 24/24：provider 安全接缝、生成客户端、界面文案、设置状态与草稿重接。
- `superagent` typecheck、build、lint 通过；DS Bot `client.js` 生成检查和 oxlint 通过（仅既有 warning）；UI boundary 以本票授权通过。
- 未运行全量套件或 CI，按本轮“快速推进、只跑窄测”要求停止。

集成门禁复查补齐了四项 P1：Router batch、单次 Router、Worker 和子代理现在从同一请求起点快照取路由；Worker Assignment 与 Router turn 保存实际 revision，观察详情不再借用 Main revision；默认 provider 没有显式 `apiKeyEnv` 时采用 DSH 的 `<PROVIDER>_API_KEY` 约定并在首次保存时写回；保存期间编辑控件禁用，竞态编辑仍按草稿版本重接到成功响应；最近使用历史改为只保留 100 条的有序索引和 meta，超过 1000 条追加历史后仍只读取有界尾页。

门禁修复定向证据：Router batch、Worker 观察、子代理、Main 配置与 Provider HTTP 共 24/24；配置、execution 与子代理快照组 16/16（两项有重叠入口）；DS Bot 客户端、Provider、i18n、保存竞态共 25/25。Typecheck、build、lint、客户端生成检查与 UI boundary 继续通过。

第二轮独立复查再补齐三项 P1：`updateRoleConfig` 在外部模型/provider 验证前先查稳定命令回执，响应丢失后的重试不会被后续枚举故障阻断；Router、Worker 与子代理的模型请求都在调用边界写入实际 revision，失败尝试同样可查；产品 `settings-save` 强制 Main、Router、Worker 三份 profile 同时存在，Engine 自身仍保留无 Main 的内部用法。对应配置重放、失败 Worker/Router、子代理审计、缺失 Main 和 Router batch 定向测试通过。

## 边界

本票管理 DSH 已提供的 provider 目录及其可写密钥；新增/删除自定义 provider 的完整表单仍由 DSH provider 设置承担。没有真实 provider 密钥、真实模型或浏览器视觉回归证据，留给组合验收。Provider key 的响应/日志泄漏由隔离 fake credentials 测试覆盖，没有使用真实秘密。
