# R5-12：在飞书按三层角色处理讨论与答复

- 工单：[R5-12 / #105](https://github.com/IceFireIcer/DS-SuperAgent/issues/105)。
- 前置：[R5-04 / #96](r5-04.md)、[R5-13 / #103](r5-13.md)。
- 状态：票据实现已接通并在 R5 集成分支验证；真实飞书租户验收按维护者决定暂缓。

## 已接通的行为

显式启用 `mainIntake` 的 FeishuSource/FeishuRuntime 复用来源持久化、成员同步、准入和 Effect：获授权且被寻址的人类新消息进入同一逻辑 Main，旧工作订阅仍经原 Ticket fan-out；ambient、Bot 和未获准入的消息不创建 Main handoff。群讨论以原生 root message 划分 Thread；同一 event 重放不会重复创建 Main handoff。Main 的来源提示、持久消息身份和现有卡片显示 Feishu 而不是 GitHub；私人 Main 文本没有作为外发消息直接发送。未启用 `mainIntake` 的原 FeishuSource 保留原用途。

等待人工的飞书问题在原讨论下送达，并带稳定的 `Q-` 问题码。原接收者在同一讨论回复 `Q-<问题码>: <答案>` 才回答当前问题并继续原 Ticket；错误码、另一发送者、普通讨论、重放或旧问题不作答，也不据此创建新的 Main 请求。飞书话题回复可以仅指向讨论根消息，不能只靠回复的 parent 判定它回答了哪个问题；问题码从 Attention 身份派生，不含密钥。

产品 Host 可接收受信的飞书 Runtime 配置，在同一 Instance 中保留独立的版本化飞书来源 Engine 和直接建工的产品 Main Engine。外发仅按精确来源 ID 进入飞书 Channel，本地回执仍走本地 Channel，未知外部来源明确拒绝。产品 API 的 `feishu-status`、`feishu-stop` 和 `feishu-start` 暴露不含凭据的健康、游标、停止与重连；现有 Main 页面用原有工作卡样式显示状态和按钮，来源卡继续展示发送回执及待核查结果。飞书 setup 失败不阻断 Main，状态保留失败原因以便重连。

正常 profile 启动可读取受信进程环境：`DS_SUPERAGENT_FEISHU_APP_ID`、`DS_SUPERAGENT_FEISHU_APP_SECRET`、`DS_SUPERAGENT_FEISHU_TENANT_KEY`、`DS_SUPERAGENT_FEISHU_CHAT_IDS`、`DS_SUPERAGENT_FEISHU_SELF_ACTOR_IDS` 和 `DS_SUPERAGENT_FEISHU_ALLOWED_REQUESTER_IDS`。群、机器人和准入身份使用逗号分隔；必须全部明确配置，缺项不启用来源，重复或无效 ID 直接拒绝。应用密钥仅在进程内交给 FeishuOpenApi，不写入业务库、产品响应、Main prompt 或仓库。用户可在产品 Main 页面停止和重连；凭据资源 UI/授权管理由 R5-15 承接，不把旧 Bot 密钥授权移到新产品。

## 定向验证

- Node 24 隔离 SQLite + mock DSH：公开 Engine/FeishuSource 接缝确认 Main handoff、去重、准入与群 Thread 隔离；隔离协议替身通过 FeishuRuntime 的 setup、成员页、消息页、poll、health、stop 和重新启动，证明重连不重复创建 Main handoff。分开的产品 Main 与飞书来源 Engine 完成 Main → Router → Ticket → 本地 Worker → 原群消息回执；同讨论跟进不建新工，另一发送者不能回答问题，原接收者的回答续接原工作，私有 Main 回复不外发。
- 产品 Host、profile 显式 opt-in、飞书来源及目录重启联合定向 10/10：Host 关闭后以同一业务库再启动，逻辑 Main 和源请求不重复；客户端 bundle/i18n/状态 8/8。相关来源、回答和 GitHub Main 回归 30/30；Super-agent build/typecheck、改动文件 lint、DS Bot 生成一致性、lint 和 UI boundary 检查通过。
- 补充的 Node 24 定向飞书接收/回答/回执 11/11：同讨论普通回复、错误问题码不作答，正确接收者带码回答；长消息截断仍保留问题码和回答说明。这是隔离替身与 mock 验证，不是飞书真实租户验收。

## 验收边界

本票使用受信进程环境显式启用来源；正常 app 启动不带该配置时，UI 不显示虚假的已连接状态。产品内的持久凭据资源配置、授权与撤销由 R5-15 完成，不在本票复活旧 Bot 身份或权限。未使用真实飞书 tenant/群，按维护者决定不把真实租户验收作为本票阻塞；不能把当前替身测试声明为真实信道通过。真实模型语义质量和托管组合仍由 T55/T58 汇合验收。

## 无工作 Main 回复收尾（2026-11-16）

当显式启用 Feishu `mainIntake` 的人类请求没有形成 WorkBrief 时，Main 的短回复现在在同一来源 handoff 事务中建立持久 `main-source-reply` 与 Outbox Effect，回到原 Feishu 消息和 Thread。回复不进入 Ticket，不把 Worker/旧 Bot 身份引入新产品；已形成 WorkBrief 的 handoff 不额外发送 Main 回复。首次发送前重新核验 handoff、原始 Feishu event、当前版本、Thread、原作者和当前 requester policy；来源被编辑/删除/失权时丢弃未发送的 Effect。

发送使用 Feishu 原有 reply transport、稳定 Effect idempotency key 和 receipt；未知结果按同一 UUID 对账，超过安全窗口保持 unknown，不能盲目重发。产品 Host 将 Feishu Engine 连接到 Feishu runtime channel，并启动其 Effect dispatcher；重启与重连不新增来源回复。Node 24 定向 Main/Feishu/Host 14 通过，覆盖原消息精确回执、重放去重、委托不双发、来源编辑拒绝、Host 异步轮询和重启；typecheck、lint、build、`git diff --check` 通过。未使用真实租户或密钥，未运行全量 CI。
