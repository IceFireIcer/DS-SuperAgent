# R5-22：将日程 occurrence 投递给授权工作

- 工单：[R5-22 / #114](https://github.com/IceFireIcer/DS-SuperAgent/issues/114)。
- 前置：R5-04、R5-06。
- 日期：2026-11-16；原实现分支 `feat/r5-22-schedule`，已合入 R5 集成分支并修复来源 actor 授权缺口。

## 交付行为

产品设置的定时任务页沿用现有日程控件样式，提供一次、间隔、每天、每周的创建、查看和取消入口。创建命令持久保存规则、明确的本地时区、Main 或一个已接单 work item 的目标、创建者授权和首次发生点；取消保留审计历史而停止后续触发。日程来源可单独关闭与重新开启，关闭期间不派发，已在运行的工作不被取消。旧 Bot Session 的 schedule 数据和目标不进入本产品的新规则库，也不会自动重放。

产品 Host 在启动时和运行中检查到期规则。每个 occurrence 使用规则 ID、UTC 毫秒发生点及独立的 `schedule` 来源身份；来源事实与投递决定在同一事务中提交。重启和重复 tick 复用该身份，不重复建工。一次性任务延迟超过一天留下 `missed` 事实；重复任务以单次有界补读和 missed 区间记录长时间停机，避免无界补发。来源关闭、取消、被 stop 阻止、投递失败和工作执行状态分别查询。

投向 Main 的新安排走既有来源 handoff、Main WorkBrief 和 Router 建工路径；在通知、委托和建工三个阶段重验持久规则、来源事实及当前授权。日程是本地来源，不尝试向不存在的 schedule 外部信道发送结果；Main 工作卡和 occurrence 查询展示原工作回执。投向已有工作的规则必须引用当前 Main 的精确 work item 和 Ticket，重验 receipt、Mandate 和 Decision 后才将发生点加入原 Ticket；自然结束的工作记录一次规则授权的恢复决定。人工停止与等待约束优先，定时事件不能解除它们，也不能用已取消规则重启待处理的来源 handoff。

## 发生记录与工作回执查看（2026-11-16）

设置页现在可以展开每条日程的 occurrence 历史。默认显示最近 20 次，可逐批加载更早记录；每次发生展示时间、投递状态、失败原因、执行状态、WorkBrief ID 与 Ticket ID。已有 Ticket 的记录可按 Ticket ID 打开工作卡；已创建 WorkBrief 但 Ticket 尚未出现的中间态可按 WorkBrief ID 打开对应卡片。跳转会关闭设置并定位、聚焦目标卡，使用户可以查看该工作的原始回执。主列表保留最新发生摘要。

定向 React/jsdom 测试以 21 条发生记录验证默认上限、展开和继续加载、错过状态、完成状态、工作 ID/Ticket ID，以及从较早 occurrence 跳转到既有 Ticket 和仅 WorkBrief 两种工作卡。Node 24.22.3 下 `test/product-schedules.test.js` 1/1 通过；`build-client.mjs` 生成及 `--check`、ds-bot lint、经用户授权的 UI boundary 检查和实施记录检查通过。lint 仍报告仓库其他文件的既有警告。未运行全量测试或全量 CI；本次实现没有新增数据库记录或 schema。此增量补齐第 4 项设置页回查入口，#114 收尾后关闭。
