## 已接通的纵向行为

现有主对话输入增加文件选择、已上传项目与取消入口；每份文件先由受信产品 Host 以命令 ID、Instance、客户端、目录和原始字节摘要登记。图像走 DSH 公开附件准入及规范化，普通文件走 DSH 原样存储；同时将原字节存进本工作目录对应的 Environment asset store。应用消息只保存已准入的 DSH 内容块与有界资源元数据，不把 base64、主机路径或凭据写入 Session、Main 文本及业务投影。仅同一来源、同一目录的未撤销附件可再次引用；重复上传使用原命令 ID 去重，冲突拒绝。产品本地 UI 可按页读取已授权原始字节，撤销后未来引用与读取拒绝；已经接纳的 Session 事实不追溯改写。

Main 调用公开 NativeSessions 时保留原生 `file`/`image` 内容块，重启重试复用持久输入；尚未投递的内容在投递前再次核验撤权，Main 建工前再次核验。WorkBrief 保留未经拼接的用户原文、附件目录和每项工作的附件 ID；Main 对复合请求逐项指定附件，Router 只能确认相同的目标与授权分配。未指定、未覆盖或猜测原输入之外的附件拒绝建工；原有单项请求仍可继承该次输入的全部附件。两个明确分配的工作各有 Ticket、Mandate、持久 workItemId 与来源事件，Worker 的提示只带本项资源引用，其原生 Session 只接收本项图片块。`read_asset` 对产品附件同时核验 Ticket 的 workItem 授权与原上传 ID，即使两个上传的字节摘要相同，B 也不能凭 A 的引用读取；Worker 自己 `save_attachment` 的引用按 Ticket 持久登记，子代理沿用同一核验。工作卡按 workItemId 从持久投影定位产物，不受最近 20 张卡限制；经原 Environment 身份验证按页读取并下载，猜测路径没有产物可读。远端客户端暂不开放文件管理入口，不能绕过本地 Host 的文件授权。

录入入口沿用现有 `speech.js` 的公开 DSH 语音 Remote、录音与转写函数；没有该服务时复用现有浏览器听写 hook。转写结果先进入原 Main 草稿，确认发送时才分配命令身份。主对话回复沿用现有语音朗读规则与浏览器播放能力，不创建另一套语音服务。

## 2026-11-16 外部来源与撤权竞态增量

受信来源适配器可把预先准入的附件 ID 和目标 Environment 身份交给 GitHub/飞书来源事件；接收事务核对 Instance、来源接收 Actor、原上传 ID、目录和未撤权状态，保存原生 file/image 内容块的有界引用。来源历史与 Main 来源列表只显示附件 ID、名称、类型、大小和当前状态，不返回资产内部指纹或 Host 路径。Main 来源交接重验当前事件与附件，在原生 Session 写入前再验一次；原文、原生非文本块与引用一起持久。Main 给每个工作项指定准确附件 ID，Router 只能确认这一分配；WorkBrief 与 Ticket 建立时重新核对原上传。已有工作中的 `read_asset` 和子代理读取在 Environment 调用前后重验逐项授权与撤权；产品原始字节下载在 Environment 读回后重验。来源已有工作归属时，不把新的带附件跟进降级为纯文本输入。

Node 24 使用隔离 SQLite、虚构文件/图片、DSH 公开附件服务与真实 LocalEnvironment 验证：GitHub 附件来源拆成两个独立 Ticket，两个 Worker 各得自己的文件/图片授权、同摘要异上传 ID 的跨项读取拒绝；飞书纯图片事件进入 Main 原生 Session；缺少目录、借用其他上传 Actor、同事件 ID 改换附件均拒绝。可控关口分别在来源解析后、Main 原生消息写入前撤权，在 WorkBrief 已建立但 Router 尚未建 Ticket 时只撤销 A（A 拒绝、B 继续），在 Worker `read_asset` 已开始而结果未交回前撤权，以及在产品下载取得字节后、返回前撤权；均未把撤权后的内容交给调用者。既有已持久 Session 和已经完成的读取不追溯擦除，外部读与撤权不宣称跨库原子性。

双轴增量自检分别核对：规范轴相对最新本地 `dev` 仅改 Super-agent 附件/来源/委托/执行模块与对应测试和本记录，不改 DSH、UI、Host 总入口或主检出；使用隔离临时资源，无真实密钥。规格轴核对来源非文本块、逐项授权、跨项同摘要拒绝及四个撤权切点；撤销 A 不能阻止已获授权的 B 建工。合并本地 `dev` 后，Node 24 定向 93/93、TypeScript typecheck、Super-agent lint、构建及 UI boundary 检查通过；没有跑全量 CI 或 PostgreSQL fixture。真实 GitHub/飞书平台二进制抓取、原生桌面录音和下载手测、真实图像模型理解、PostgreSQL 专项、远端客户端文件传输仍未验收；预先准入的来源附件需要受信适配器提供，不能把当前来源事件接缝称为平台文件传输已接通。#106 保持 OPEN。

## 2026-11-16 飞书原生消息资源抓取增量（独立分支）

飞书受信适配器现在解析原生 `image`/`file` 消息的资源键。接收前使用同一受信凭据读取原消息，核对消息 ID、聊天、发送者、更新时间及当前资源键，按平台消息资源接口下载二进制；下载后再次核对当前消息，限制响应头和实际流均不超过 8 MiB，禁用重定向。失败、缺失、已撤回、版本变化或资源过大时不准入、不推进该页来源游标、不把文件占位符交给 Main。`audio`、`media`、`sticker` 及含嵌入资源的富文本暂未提供原生准入，明确拒绝，不能按纯文本成功处理。

产品 Host 只提供当前 Instance 的默认本地 Environment 与现有 DSH 公开附件服务。附件记录继续以飞书来源接收 Actor 为原上传所有者；实际 Environment 存储由产品 Host 本地 Actor 执行，来源 Engine 不取得工作目录的命令权。上传命令 ID 由来源实例、原消息/版本及资源键确定；重复收到相同平台事件复用已持久来源回执，不再抓取二进制。Main 的来源引用与原生 Session 使用已有有界 `file`/`image` 内容块，逐工作项 grant、Worker 读取和撤权重验沿用上节现有契约；平台资源键、二进制和 Host 路径不进入业务来源文本。

Node 24 在隔离 SQLite、本地 Environment、虚构飞书 HTTP、DSH 附件服务和 mock NativeSessions 下定向 26/26，通过来源抓取、Main 原生文件/图片块、重启重放、错聊天/资源键、读取中撤回、403、缺失键、大小上限及来源游标不前进；已有逐项工作授权和撤权用例一并回归。TypeScript typecheck、Super-agent lint、构建、UI boundary 与 `git diff --check` 通过。此处仅证明真实适配器路径配合协议替身，**没有真实飞书 tenant 或设备验收**。GitHub 正文文件链接仍未建立可核查的原生文件身份/授权，不能将任意 URL 作为受信附件；真实平台权限变化的跨系统原子性、原生录音/下载、真实图像模型、PostgreSQL 与远端文件传输仍待独立验收。#106 保持 OPEN。

## 2026-11-17 产品可用性收口

本轮按现有产品入口重新验证时发现：`ProductAttachments.upload()` 仍调用 Worker 的 64 KiB `saveAttachment`，导致大文件准入失败；产品附件和工作卡产物下载仍调用脱敏的 `readAsset`，可能把原文件内容改写；远端自动选址的工作卡没有显式 `brief.environmentId`，产物读取因此被旧检查拒绝。已改为本地受信 `saveProductAttachment` 和受信 `readProductAsset`；远端维持既有 64 KiB 上传限额，并提供受信原字节读取。Worker 工具、观察事实和普通 `readAsset` 继续脱敏。产物下载以实际绑定的 `executionLocation` 校验，仍要求当前工作卡的产物引用、同一 Environment 和授权本地窗口。

定向测试使用隔离临时目录与设备 loopback：本地 128 KiB 上传、原字节分页、撤权/跨工作项拒绝、文件与图片到 Main/Worker、受信原文产物下载；远端设备的原文与 Worker 脱敏差异、远端工作卡产物读取及 Host 重启。Super-agent 相关定向组在 Node 24 下 22/22；DS Bot 产品附件/远程等待入口 5/5，语音组件 12/12。TypeScript typecheck、Super-agent lint、生成客户端检查、UI 边界和差异格式检查通过。此前 DS Bot 本地全套 1503 项中 1501 通过、0 失败、2 项跳过。Super-agent 全套曾启动，但在 benchmark、生产 factory/environment、Session 重启、GitHub 来源交接、PostgreSQL 及 product-terminal 组出现失败后停止；未用该全套运行作为本票通过证据，也未运行远程 CI。GitHub 来源交接独立重跑 4/4 仍失败，来源 Effect 保持 pending；该问题在本票变更前的 Engine/Effect owner 路径，留待独立修复。

这张票交付的是现有产品主对话中发起与核查文件/图像/语音工作的可用链路。GitHub 正文中的任意 URL 不具备受信平台附件身份，不能自动下载为附件；飞书仅原生 file/image 已接，真实飞书租户继续暂缓。远程客户端的文件传输、真实语音/图像模型和跨平台设备组合不由本票代码测试冒充，留给相应平台/环境验收。
