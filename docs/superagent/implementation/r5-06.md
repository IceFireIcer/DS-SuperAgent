# R5-06：分开停止 Main 回复与持久停止工作

- 工单：[R5-06 / #98](https://github.com/IceFireIcer/DS-SuperAgent/issues/98)。
- 前置：[R5-02 / #94](r5-02.md)。
- 日期：2026-11-15；实现位于 `dev`，未发布。

## 交付行为

Main 历史返回当前 `activeTurn`。输入框只在当前回合存在时显示“Stop reply”；queued 输入、Router/Worker 工作和本地发送等待不会获得这个按钮。`stop-main` 以 command identity、message identity 和 Instance 持久记录一次 stop，只 abort 当前 Main turn 的 controller，不取消 WorkBrief、Ticket、Assignment、job 或 UI 请求。

已提交的原生 Main 回合不能靠晚到回复恢复。`publish` 在 stop 已记录时丢弃答案；停止请求与完成/失败竞态会把 stop 记录终结为 `stopped`。Host 重启后没有 live controller 时，对账按当前 Host custody 把遗留 `stopping` 终结为 host-confirmed stop，清除断开的 active turn；仍当前进程内运行的回合则在原生 turn 静默后确认。

工作卡控制直接调用现有 Engine stop/resume/retry，不经过 Main 模型。公开产品协议为 `work-stop`、`work-resume` 和 `work-retry`，必须同时携带精确 `workItemId`、`ticketId` 和当前 Assignment `generation`。Engine 在执行前重验 Main、WorkBrief、receipt、Ticket 和 generation；旧卡片返回 `WORK_VERSION_STALE`。工作卡显示 stopping、设备取消待确认、已确认静止及原因。只有卡上的明确命令解除 stop；普通消息、迟到完成、CI 或重启都不解除。

expected generation 还会进入 Execution 的 stop/resume/retry 同一写事务，在读取当前 stop、创建新 Assignment 或结束旧 Assignment 前再次比较。即使卡片授权检查与领域写入之间发生换代，旧命令也不能作用到新 generation。

Main 卡片 wrapper 只校验稳定的 work item、Ticket 与 Main 归属。同一 command ID 与 generation 的成功回执先于任何换代检查返回；新 command 仍进入 Execution 写事务执行 generation CAS。因此合法换代后重试原 stop/resume/retry 会重放原回执，不会再次改变当前 Assignment。

观察页继续只读，只提供返回 Main；工作控制入口只存在于主对话卡片。

- Main、Attention、stop 与 retry 定向回归 17/17 通过，包括已有 stop/resume/restart、迟到结果和普通跟进不解除约束；直接 stale-generation stop/resume/retry 都在领域写事务中被拒绝，成功换代后的原 command replay 保持同一回执。

- DS Bot composer、i18n、产品状态定向测试 5/5 通过；`client.js` 重新生成，`--check` 和定向 lint 通过。

## 边界

没有增加“全部停止”入口。完整真实设备取消确认、真实模型/CI 组合和最终四目标验收仍由相应汇总票负责。
