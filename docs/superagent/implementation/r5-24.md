## 行为和入口

产品 profile 可从可信环境变量 `DS_SUPERAGENT_WATCHDOG_STATUS_PATH` 接受一个绝对路径。产品 Host 获得当前 Instance 的 Host lease、打开 Main 后，以原子文件每十秒发布 PID、epoch、角色配置 revision、Main 健康、Router/Worker 失败条目、Feishu 来源/setup 状态、人工等待、暂停及 unknown 计数。文件不包含 prompt、工具输出、凭据或用户目录；Main 模型失败是局部组件故障，来源/setup 错误也不能触发全 Host 重启。超过当前 100 Ticket/观察项的巡检范围时记录 `PARTIAL_HEALTH`，不冒充完整覆盖。

独立的 `ds-superagent-watchdog` 进程复用原有 `Watchdog`、`ProcessWatchdogHost`、重启预算、五分钟优雅关闭、通知去重和可查历史。SQLite 按规范化数据库路径和 Instance 使用单机锁文件，PostgreSQL 使用数据库 advisory lease；行动前再次验权。外部进程需持有被监督 Host 的子进程 IPC，才能优雅关闭并启动替身。只有 Watchdog 自己启动的 Host 可按该机制自动替换；已有桌面 shell 启动的非子进程 Host 不会被强杀或冒充已安全停止。其服务恢复依旧需要现有 Host epoch/fencing 与接管对账。

产品 Host 用独立 `supervisor:<instance>` 原生 Session 和原有 Supervisor 每五分钟巡检一次；设置页可主动查证。Session 只提供记录监督结果的工具，带 60 秒和模型步数预算；定时与人工检查合计每小时最多 24 次，计数独立持久，不因显示历史截断而重置。持续失败的巡检留下 `supervisor-run` 历史，三次连续失败成为局部组件故障。语义监督按 Engine 受权游标逐页读每页最多 100 项，单次最多十页/1000 项；超过上限留下 `partial`、已检查数量和下一游标，不能记为全量完成。现有 proposal 窗口/次数预算、正常等待识别和未知结果原身份对账继续有效。批准只通过受信的本地产品设置入口，按 Main work card 归属、提案指纹、当前方向版本、Assignment 代次和人工停止重新验证；拒绝不执行动作，批准纠偏只加一条受控方向输入，批准暂停调用原 Ticket stop。远端客户端和只读观察视图不能访问审批或私有监督历史。配置更改由原有受信设置命令产生版本，监督器没有修改配置的工具。

现有产品设置增加 Supervision 页，列出提案的理由、建议、影响、版本、动作结果、观察及 Watchdog 历史。正常巡检静默，保留英文源文案、中文词条、主题变量、焦点和减少动画规则。`client.js` 由源码生成；没有添加 renderer 或更改 DSH/个人数据。

## 运行方式与边界

隔离 mock 演练使用 `dev/r5-watchdog-host.mjs`：通过 `--database`、`--instance`、`--status` 启动真正的产品 Host/Engine 与独立 Session 存储；外部 CLI 的 `--host-command <node>`、重复 `--host-arg` 指向该入口。真实产品须在可信部署环境中设置与产品 profile 相同的数据库、Instance、状态路径和 profile 环境，并由独立服务运行 Watchdog CLI，且让 CLI 启动并拥有生产 Host 子进程。`--once` 是诊断模式，会停止它自己启动的 Host，不用于保持服务常驻。SQLite 异常退出遗留的 `state.sqlite.watchdog-<instance-hash>.lock` 要先核实旧进程已退出再由操作者清除，不能盲删活锁。

默认桌面 shell 仍直接拥有自己的 Host；若没有上述可信状态路径和独立进程配置，设置页明确显示 Watchdog 未配置，不能把仅有的前端入口当作正在运行的恢复服务。对 shell 已拥有的 Host，现有进程适配器拒绝强行停止；T58/#92 的常驻服务安装、真实服务器替换与客户端接入仍需单独证据。语义巡检现已覆盖 100 项之后的分页；真正超过 1000 项时单次结果保留 partial 和下一游标，调用方须在同一 Engine 的五分钟游标有效期内续查，否则重新从头巡检。现有产品设置入口不提供跨批自动续查；60 秒模型预算届满则记录失败，不冒充完整巡检。独立 Watchdog 的健康快照仍最多汇集前 100 Ticket 和观察项，超出时保留 `PARTIAL_HEALTH`。真实模型的偏离判定质量、真实飞书 tenant、真实设备和全量四目标验收没有在此工作中声称通过。

## 2026-11-16 分页巡检增量

基线为已推送的 `dev` `7502d79`，在短路径隔离分支 `feat/116-r5-24-paged-supervision` 实施。Engine 的监督查询增加可选的单页读取，默认查询仍保留原有十页上限；Supervisor 逐页按受权游标处理，每页最多 100 Ticket，单轮最多十页。缺失、循环或自相矛盾的游标和超量页会以 `INCOMPLETE_STATE` 失败，不能记为全量。超过单轮 1000 Ticket 时返回 `partial`、已检查数量、上限和下一游标，产品 `supervisor-run` 将其写进历史；调用方可沿该游标续查。原有审批对当前方向、Assignment 代次、人工停止和 Instance 的检查没有放宽。

隔离 SQLite 行为回归覆盖 151 个真实 Engine Ticket、225 个分段 Ticket、后页提案与过期方向/代次/停止拒绝、另一个 Instance 不可读和重新连接后的历史；PostgreSQL 独立连接合约覆盖部分巡检记录、续读游标与后页观察历史。Node 24.22.1 的监督、Session、产品 Host、Watchdog 定向组合 57/57，最后游标校验增量窄测 24/24，PostgreSQL 单项合约 1/1，Super-agent typecheck/lint、UI 边界和差异检查通过。未运行全量 CI、真实模型、真实服务器或飞书租户。
