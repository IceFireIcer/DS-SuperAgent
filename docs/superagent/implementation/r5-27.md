# R5-27：预览并选择导入浏览器资源

- 工单：R5-27 / #119。
- 代码提交：`cd8363a7`（`Import browser data into isolated resources`）。
- 直接前置：R5-18 / #110 与 R5-19 / #111 已关闭。
- 范围：用户明确提供 cookie 导出或选择一个已安装浏览器 profile 后，预览并导入到新的隔离产品浏览器资源；不恢复旧 Bot、旧历史或旧权限。

## 实现

App 复用现有 cookie 文件解析和本机浏览器 profile 复制器。文件只由用户在原生选择器中指定；已安装浏览器会先列出，用户选择后才复制读取，并且用户确认后才短暂关闭正在运行的 Chromium。解析后的 cookie values 留在 Electron main process 的 `CookieImports`；页面得到 `previewOf` 的无值投影，并附带由规范化 cookie 数据计算的 SHA-256 `sourceDigest`，用于识别内容变化。

现有 Memory/设置产品页的 Browser 区域新增导入卡。用户先从文件或本机 profile 创建预览，再明确选择目标本地 Environment 并输入浏览器名称；预览显示来源归属、原格式、cookie/site 数量、隔离隐私范围、Target Instance、本地浏览器角色和新资源初始没有工作授权。创建动作发送 `pendingId`、稳定 `sourceRef` 和无值 preview，不发送 cookie values。

产品 Host 的浏览器 adapter 新增受控 `importProfile` 接缝。Host 只向 App 发送随机产品 profile key、`pendingImportId` 和稳定 `importId`。App `ProductCookieImports` 在原有隔离 partition 上逐项写入、回读并 flush；同一 profile/import 的重试返回同一 reports，换 profile 复用 import 则返回 `BROWSER_IMPORT_CONFLICT`。

## 持久状态

- `browser-import` 保存导入来源的无值 preview、`sourceDigest`、稳定来源 key、preview hash、目标 Environment、新 resource ID、状态和清理后的写入报告。
- `browser-import-command` 保存 command ID 的规范化指纹；同一 `pendingId` 和相同 preview 只创建一个资源。
- 新资源先以 `importing` 状态持久提交，Worker、grant、take 与浏览器 operations 都不能使用；App 回执成功后才转为 `active`。
- 写入失败、回复丢失或 App 超时形成 `unknown`，UI 保留同一 preview/command 并锁定原 Environment/名称供重试。App 重启或 pending 过期后，用户重新选择同一原件可得到新 pending；UI 可通过稳定 `sourceRef` 将新 preview 接回原批次，服务端仍核对 preview hash 与 target。App 对同一 import ID 幂等，因此 Host 提交结果未知时不会重复写 cookie；改目标必须先取消旧批次。
- 取消把未完成资源改为 `revoked`、批次改为 `cancelled`；已被取消的 import 不会由迟到的 App 成功回执重新激活。已应用资源必须先走现有资源撤权。
- 同一 pending source 只能对应一个 Environment/名称；改变目标或 preview 得到 `IDENTITY_CONFLICT`。不同 pending 导入总是创建不同随机 profile key，不复用、不覆盖在用浏览器。

## 敏感内容边界

业务库只保存 pending source 的 SHA-256 key 和不含 values 的内容摘要，不保存 pending ID 或 cookie values。preview 经过显式字段白名单重建，未知字段不会被持久化；App 报告也被重建为有界 name/domain/path/count 与通用原因，原始 Electron/Node error 文本不会跨 Host IPC。Host 只接受固定的 `BROWSER_IMPORT_*` 错误码，其他值统一归一为 unknown。Worker/Main prompt 没有浏览器导入工具，产品 projection 不包含 profile key、cookie values 或本机路径。

原始 cookie 文件只读且不离线删除；App pending 和幂等 receipt 只存在于受控 main process，并在既有 10 分钟预算/16 项上限内清理。App/Host 重启后旧 pending values 不持久化，UI 明确保留可取消的 unknown 批次，用户可重新选择原件重试。

## 产品接缝

- Engine：`importBrowserData`、`listBrowserImports`、`readBrowserImport`、`cancelBrowserImport`。
- 产品 Host：`browser-import`、`browser-import-list`、`browser-import-read`、`browser-import-cancel`；只允许本地授权设置入口，远端客户端在 Host 拒绝。
- 新记录种类走共享 `RecordKind`/SQLite/PostgreSQL 事务契约；画像字节由 App 隔离 partition 保存，不写业务库。
- 现有 Browser resources 页继续负责应用后的逐工作项授权、take/return、operation 核查和撤权，不创建第二个浏览器面板。

## 验收对照

1. 预览显示来源、目标 Instance/Environment/名称和新资源无 grant；用户选择后才创建 `importing` resource，未读取用户 DSH。
2. 每次导入生成随机 profile key；不同 pending 不共享 partition。`importing` 状态隔离 Worker/grant/lease，应用成功后才进入现有 Browser panel。
3. cancel/unknown/retry/conflict 都有持久批次；重试复用来源 key 和 App import receipt；原件保持只读，cookie values/未知字段/profile key 不进入业务投影或报告。
4. 应用后的普通浏览器资源可继续使用现有 grant、Worker use、take/return、operation resolve 与 revoke；没有任何旧 Bot 或旧工作对象被恢复。
