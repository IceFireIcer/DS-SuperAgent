## 已接通的行为

现有 `Proactive` 规则库接入产品 Host 的本地设置与 Feishu 接收 Engine。每条产品规则只允许绑定当前配置的一个 Feishu 来源实例、被提及或直接送达的 app 事件、字面文本匹配；不可从来源正文推导新规则或发布权限。用户可创建、编辑、启停、删除 observe/auto 规则及单独暂停主动准备。规则修订按预期版本和稳定命令 ID 提交；旧规则的运行中/已准备结果失效。observe 只记录匹配事实，不调用模型。auto 在同一业务事务里预留窗口运行次数并记录来源事件、规则版本与隔离目录；重复 bot 正文、环境噪声和预算耗尽都保留原因。来源接纳事务先记录候选与规则/暂停版本；若 Host 在准备前退出，替换后的 Engine 可按原身份补读，过期候选不会重启新工作。

auto 使用现有 DSH 公开 Session/Agent、独立 `LocalEnvironment` 与 Worker 模型路由，在产品状态目录下为每个命中的来源事件建立独立目录。模型最多 8 步、一次准备最多 30 秒；仅可读、写、搜索该目录及提交有依据的审阅摘要和相对文件路径。没有 Shell、发信、PR、合并或旧 Bot dispatcher 工具。文件在落库前重新核验真实路径、大小、摘要与规则字节上限；模型未提交有用报告时静默结束。运行记录保存模型步数；当前 DSH 回执未提供可归因的 token/货币成本，因此 UI 显示可用步数而不伪造费用。

模型工具执行前后与准备结果提交前都复核当前来源事件、原工作归属、规则修订、主动暂停和全局处理暂停。用户可按精确运行 ID 持久停止；Host 替换后未完成运行标为中断，不盲目重跑。停止、暂停、规则修改会取消同 Host 的在途模型回合，迟到的结果不能重新变成 ready。主对话仅列出当前规则要求 `notify` 且成功准备的有界摘要，不因 observe、silent、失败或普通进度逐条启动 Main 回合。设置页提供分页运行索引、来源身份、依据、原因、步骤预算、隔离目录及已核验文件的分页阅读。远程只读客户端只能读记录，服务端拒绝停止与规则管理。

记录类型 `proactive-control`、`proactive-candidate` 和 `proactive-notice` 加入 SQLite/PostgreSQL 共用注册表；通知索引只保留最新十条身份，让主对话轮询不扫描全部历史。业务事实与 DSH Session 仍各自持久，不声称跨库事务。

## Router 与受限 Ticket 纵切面（2026-11-16）

本次从已推送 `dev c55eb01` 在独立短路径 worktree 建立 `feat/115-r5-23-router-chain`，只做本地提交。保留上文各增量的历史结论；下述实现收窄其中“尚无正式工作链”的缺口，不替代 #115 全票验收。

只有当前、获授权的 auto 规则产出经文件核验的 `prepared` 结果，才在同一个业务事务保存 `proactive-work` 路由意图及 Router Effect。observe、静默无结果、预算耗尽和已被原工作拥有的来源不建立新 Ticket。Router 以每次运行独立的 DSH Session 和最多两步模型预算判断是否接单；唯一工具不接收模型提供的目标、目录或权限。接单的稳定命令在事务中重新核对原生来源事件、规则修订、暂停代次、来源实例/接收 actor 和原工作归属，再建立真正的 Trigger、Decision、推断型 Mandate、Ticket 与 Intent。`proactive-work-source` 防止同一来源事件经两条规则重复建工。Router 拒绝、失权及模型结果未知分别留在运行索引；Session 已记录但业务决定未确认时不换 ID 盲重跑。

Ticket 的 `proactive` 引用保留准备运行、原生来源事件、规则版本和文件上限；其归属是受信产品 Instance，不冒充人类 Main 委托或生成假的 Main WorkBrief。Worker Assignment 固定准备时的隔离目录，最多八步，只能分页读原始当前来源、读/写/搜索该目录及提交有验证依据的 ready 报告。没有 Shell、MCP、子代理、订阅或跨信道 Outbox；准备报告本身不会把 Ticket 标为 ready。Worker 的模型请求、工具前后及报告提交事务都复核原授权。规则修改、暂停、精确停止、来源停止、来源事件更改与选中飞书凭据撤销会阻断后续执行并请求持久停止；Host 重启按原 Ticket/目录读回，目录丢失时停止而不重建执行世界。

产品 Host 的 `proactive-list/read` 增加路由状态、Ticket/Mandate/Assignment、Worker 报告与已知的准备/Router/Worker 步数；`proactive-work-artifact` 仅允许本地受信窗口按报告引用分页读取，文件变化按原摘要拒绝。没有可归因 token/金额成本，显示步骤和字节上限而不填造费用；Main 仍只收到原有有界准备通知，silent 不唤醒它。业务数据库与 DSH Session 分开持久，不声称跨库 ACID 或外部 exactly-once。

仍未完成：受权仓库快照克隆和测试复现、真实模型质量及 token/金额计量、真实 GitHub/飞书/托管组合验收；当前设置页尚未为新 Ticket 投影添加独立的导航/控制卡，Host 读写接口先形成可验证纵切面。PostgreSQL 新记录仅做存取重开合约，未跑完整产品链路。无 GitHub 写信道，准备或 Ticket ready 都不能自动发信、建 PR 或合并。#115 继续 OPEN。定向验证与双轴自检见[审查记录](reviews/r5-23.md)。

## run.work 控制卡与角色级 Token 归因（2026-11-17）

本节收口上节记录的工作控制与成本可查缺口。`proactive-read` 的 `work` 现在从同一 Ticket/Turn 事实投影当前阶段、生命周期、推断 Mandate、Assignment 代次与执行环境、运行当时的规则次数/窗口预算、准备/Router/Worker 步数/上限、Worker ready 报告和已核验文件。`proactive-list` 只返回轻量状态，完整 Mandate、报告和 Session usage 仅在选中条目的详情读取；不会为分页列表读取最多 50 组 Session 日志。公开视图只保留 Assignment 的稳定身份、代次和 Session 范围，不返回 `runtimeToken`；报告的 `toolFacts` 只合成为数量，原始工具输出仍走既有有界详情入口。

Token 用量只汇总 DSH 持久 Session 中 `assistant/message` 记录的 provider usage，不按文本长度估算。准备、Router 和全部 Worker Assignment Session 分别保留调用数、有 usage 报告的调用数、读取失败 Session 数以及输入、输出、缓存和 provider total；部分调用没有报告或 Session 读取失败时明确显示 partial/unavailable，不把不完整账本标成完整。规则预留时保存 `used/max/window` 快照，后续改规则不会抹掉旧运行的预算依据。Ready 报告只在它属于当前 Assignment、direction version 和 ready 状态时展示，并在读取文件前再次核验当前主动授权；较新 Assignment 或方向使旧报告失效。报告文件可在现有设置页按既有分页接口读取。Router 拒绝/失权而没有 Ticket 的运行仍可读到准备/Router steps 与 token、运行预算及结束原因。现有产品没有受权模型价格目录，因此金额字段明确为 unavailable，不把 token 数冒称货币费用。

现有主动准备设置页在每项审阅中展示上述工作控制卡；停止按钮使用 Host 计算的活动/约束状态，避免已结束或已停止的 Ticket 再显示停止动作。Proactive Ticket 不伪造 Main WorkBrief/WorkItem，也不提供会落空的“查看 Main 工作卡”入口；查看入口就是现有主动准备设置中的对应运行。英文源文案、中文翻译、键盘按钮和现有主题一并维护。

本次没有新增业务 schema 或记录类型，因此 SQLite/PostgreSQL 共用记录边界不变。Node 24 定向测试覆盖持久 Session token 聚合、真实产品 Host 的 Ticket/Mandate/Assignment/预算/usage 投影、设置页控制卡和核验报告文件读取；未运行全量 CI、真实付费模型、真实仓库复现或真实 Feishu/GitHub 组合。真实仓库复现仍不授权发信、建 PR 或合并。
