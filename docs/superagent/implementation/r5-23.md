## 已接通的行为

现有 `Proactive` 规则库接入产品 Host 的本地设置与 Feishu 接收 Engine。每条产品规则只允许绑定当前配置的一个 Feishu 来源实例、被提及或直接送达的 app 事件、字面文本匹配；不可从来源正文推导新规则或发布权限。用户可创建、编辑、启停、删除 observe/auto 规则及单独暂停主动准备。规则修订按预期版本和稳定命令 ID 提交；旧规则的运行中/已准备结果失效。observe 只记录匹配事实，不调用模型。auto 在同一业务事务里预留窗口运行次数并记录来源事件、规则版本与隔离目录；重复 bot 正文、环境噪声和预算耗尽都保留原因。来源接纳事务先记录候选与规则/暂停版本；若 Host 在准备前退出，替换后的 Engine 可按原身份补读，过期候选不会重启新工作。

auto 使用现有 DSH 公开 Session/Agent、独立 `LocalEnvironment` 与 Worker 模型路由，在产品状态目录下为每个命中的来源事件建立独立目录。模型最多 8 步、一次准备最多 30 秒；仅可读、写、搜索该目录及提交有依据的审阅摘要和相对文件路径。没有 Shell、发信、PR、合并或旧 Bot dispatcher 工具。文件在落库前重新核验真实路径、大小、摘要与规则字节上限；模型未提交有用报告时静默结束。运行记录保存模型步数；当前 DSH 回执未提供可归因的 token/货币成本，因此 UI 显示可用步数而不伪造费用。

模型工具执行前后与准备结果提交前都复核当前来源事件、原工作归属、规则修订、主动暂停和全局处理暂停。用户可按精确运行 ID 持久停止；Host 替换后未完成运行标为中断，不盲目重跑。停止、暂停、规则修改会取消同 Host 的在途模型回合，迟到的结果不能重新变成 ready。主对话仅列出当前规则要求 `notify` 且成功准备的有界摘要，不因 observe、silent、失败或普通进度逐条启动 Main 回合。设置页提供分页运行索引、来源身份、依据、原因、步骤预算、隔离目录及已核验文件的分页阅读。远程只读客户端只能读记录，服务端拒绝停止与规则管理。

记录类型 `proactive-control`、`proactive-candidate` 和 `proactive-notice` 加入 SQLite/PostgreSQL 共用注册表；通知索引只保留最新十条身份，让主对话轮询不扫描全部历史。业务事实与 DSH Session 仍各自持久，不声称跨库事务。

从已推送 `dev` 的 `7502d79` 在短路径独立 worktree 建立 `feat/115-r5-23-github-source`，只做本地提交。受信 Host 可由 `DS_SUPERAGENT_GITHUB_OWNER`、`DS_SUPERAGENT_GITHUB_REPO`、`DS_SUPERAGENT_GITHUB_ALLOWED_REQUESTER_IDS` 和可选的 `DS_SUPERAGENT_GITHUB_SELF_ACTOR_IDS` 明确配置一个 github.com 仓库；缺项显示来源配置错误，零人类请求允许清单也是合法的只观察配置。`gh api` 默认仅读取；测试注入隔离 API runner，不读取真实 `gh` 账号或凭据。`github-status/start/stop` 暴露健康、游标和本地管理；停止会取消在途准备并丢弃该来源的待处理候选。

GitHub Issues/PR/评审/评论及 PR check runs 进入同一个产品 Host、SQLite 来源事实和原有 Main/工作归属：当前授权的人类新请求进入 Main；CI 和 bot 事件保留原生 actor kind、仓库与 Thread 身份，可作为已有工作的上下文和单独受规则控制的候选，不直接创建 Ticket。产品设置页可将 observe/auto 规则绑定到 Feishu 或明确的 GitHub 仓库，GitHub 规则可选择 bot 和/或 CI；服务器拒绝人类事件自动准备、跨仓库实例、ambient 事件和非字面的高开销匹配。候选从来源事务排队，经原 Proactive 事务预留规则/暂停/预算并在提交前复核来源、归属和停止；observe 不调用模型，auto 仍只有隔离目录文件工具和审阅提交工具。出站 GitHub 目的地明确返回拒绝，不因 `gh` 的本机登录态或来源正文获得发信/PR/合并权。
