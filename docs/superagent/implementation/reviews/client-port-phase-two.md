# DS Bot 0.3.8 迁移阶段二双轴复核

固定点：`108ae674`。本次改动全部来自 #151–#155，Standards 与 Spec 分别独立复核；没有把
Issue 的 OPEN/CLOSED 状态当成实现证据。

## Standards

初查发现并已关闭：

- 启动页的可见阶段文字仍写“打开团队”，与当前 Main/Router/Worker 产品语言冲突。各语言阶段
  已改为打开 DS SuperAgent / 导入产品数据；旧团队说明和未使用的启动解释分支已收窄。
- IM 字段名、平台名和二维码 `aria-label` 直接输出英文。字段名、选项和二维码标签已走 `t()`，
  中文目录已补齐。
- 连接器错误样式回退到硬编码 `#b42318`。改为 `var(--bt-danger, currentColor)`；功能区域的
  可聚焦控件补齐焦点环。

保留的判断项：

- 服务端、客户端适配层和远端客户端各自维护端点白名单；当前是既有协议边界，合并会增加跨模块
  耦合，未在本切片改动。
- Worker MCP 工具构造有共享形状但分别服务主工具列表和兼容入口；当前有测试覆盖重复名称与预算，
  未为局部抽象扩大改动面。
- `app/src/preload.cjs` 与启动窗同时承担多个桌面职责；该结构来自已迁移的桌面壳，拆分需要独立
  的桥接设计，留作后续维护项。

Standards 阻断：**0**。

## Spec

- #151 原实现将 Main 工作列表截断为最近 20 条，不符合任务板聚合全部 Work Items。已移除该截断；
  在既有 1000 条读取预算内返回全部工作。
- #152 的旧 Bot 团队启动导入仍是明确 fail-closed，不是真正的旧团队导入。该行为遵循父规格
  不迁移真实用户数据和旧团队运行时；浏览器 cookie、凭据和记忆导入走各自隔离流程。若要求完整
  旧团队导入，需要单独产品决策。
- #154 的八个平台只有 mock 协议和契约验证，没有真实账号登录、配对、二维码扫码和收发证据，
  不能宣称八平台真实可用；#153 的真实 OAuth 和 IMAP/SMTP 邮件也仍待环境验收。
- #155 复核认为“绑定允许单 scope、运行时要求 WorkItem+Environment”不构成静默越权：Worker
  MCP 绑定只匹配请求的精确范围，执行时会重新检查精确 WorkItem/Environment；测试覆盖了
  environment-only 绑定配合精确执行范围的路径。页面已限制 Main/Router 只提交 role-only。

Spec 阻断：**0 个可代码闭合项**；剩余项是真实外部环境验收或父规格明确排除的旧数据迁移。

## 结论

定向代码与契约范围内没有新的硬阻断。真实 OAuth/邮箱/IM、真实 Electron 打包与全量 CI 不在本次
验证结果内；相关工单不因本复核自动关闭。
