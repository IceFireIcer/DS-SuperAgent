# R5-27 双轴复核

- 规格：GitHub #119；基线：`origin/dev` `4ea81ac9`。
- 方法：独立 Standards 与 Spec 子代理并行审阅同一 staged diff；Standards 读 `AGENTS.md`、`CONTRIBUTING.md`、`docs/design/ui-standard.md`，Spec 对照 #119、`spec-r5.md` D09/D10/D13 与 A13/A20/A21。

## Standards

首轮阻断为：App 将任意 `error.message` 写入 cookie failed report 后可跨 Host IPC；`importing` 资源仍可被普通 revoke，迟到成功会再次激活；App/Host/业务层未限制错误码。另指出并发 dispatch、UI 用 label/Environment 模糊关联 pending、`importData` 混合过长。

修复后：失败 cookie 只保留通用 reason，原始 driver error 不跨进程；App、HostBridge、BrowserResources 三层只接受固定 `BROWSER_IMPORT_*` code；普通 revoke 拒绝 `importing`，激活事务要求资源仍为 `importing`；Host 与 App 都有按 import/source 的 in-flight 合并；UI 使用稳定 `sourceRef` 关联批次；导入拆为 prepare、dispatch、finalize。最终复核还统一了 `sourceRef/importId` 的 UUID 契约，修正了 App 只接受 64-hex ID 导致真实桥无法完成的问题。

最终复核：**Standards clean，0 个阻断项**。新记录均使用共享 RecordKind/Storage 事务契约，生成 `client.js` 与源一致，UI 复用现有 Card/Row、主题和焦点样式。

## Spec

首轮阻断为：目标 Environment/名称被自动选中，源归属与隐私范围显示不完整；App 重启或 pending 过期后不能用重新选择的原件恢复同一批次；任意 App error code 可进入持久投影。

修复后：Environment 与名称从空值开始，要求用户显式选择/填写；预览显示 Source ownership、Isolated browser profile、Target Instance、Local browser role 和“不授予初始工作访问”。App 为规范化 cookies 计算不含 values 的 SHA-256 `sourceDigest`；`sourceRef` 作为稳定批次引用，重新选择原件产生的新 pending 只有在 `sourceDigest`/preview hash、Environment 和名称都一致时才能接回原批次/资源；变化返回 `IDENTITY_CONFLICT`，取消批次不能复活。错误码和报告字段双重白名单，cookie values、pending ID、profile key 和原始错误文本不进入业务 projection。

最终复核：**Spec clean，0 个阻断项**。新资源在 App 确认前保持 `importing`，不同来源使用不同随机 profile；应用后继续走现有 grant、lease、take/return 和 revoke，没有恢复旧 Bot 或旧工作。
