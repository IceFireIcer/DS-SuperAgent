# R5-33 实施复核

固定点：`6108c74d`。审查当前实现、两个未跟踪测试文件和 #125 正文，Standards 与 Spec 由两个独立清单
并行复核；未把组件 mock、现有票据状态或实施记录当作当前行为证明。

## Standards

- 新增测试最初由一个长回调覆盖启动、接管、会话核验和回答。已拆成
  `openWaitingProduct`、`replaceAndReconnect`、`completeRecoveredWork`，测试主体只保留编排；lease
  时长也改为一个常量并派生等待时间。
- `endedAssignmentNeedsTakeover` 与 `takeOverTicket` 都判断未决工作。前者负责选择旧 Ticket，后者在同
  一 Storage 上重新读取并决定恢复/阻断；保留两段读取是为了让接管记录与真正恢复都在自己的事务内重新
  校验，避免把一次快照当成权威。job/subagent 状态集合仍应从各自状态模块共享，当前只作为后续维护项。
- SQLite/PostgreSQL 仍以两个可选项表示并有运行时 XOR 校验。没有改成闭合 union，是为了保留公开
  `ProductHostConfig` 的现有调用形态和 Cordis 插件配置兼容；错误在打开 storage 前 fail closed。
- `DS_SUPERAGENT_POSTGRES` 在 patch 中分别控制 PostgreSQL row 启用和 JSONL row 停用。两行相反 polarity
  是 Cordis patch 的显式替换方式，并已通过静态 provider 断言与真实 PostgreSQL profile 运行核验。
- 没有修改 DSH、生成客户端、`app/ui`、`CHANGELOG.md` 或真实 `~/.dsh`。Typecheck、build、lint、
  diff check 通过。

## Spec

- 共享 PostgreSQL 业务库与 Session provider 已接入同一产品 profile；SQLite 本机路径保持可用。本地
  state root 不再从数据库路径推导，避免 PostgreSQL 模式把运行时文件放进错误目录。
- 新 Host 在 Engine 构造后立即推进 lease/takeover，然后恢复其他产品组件。真实 ended waiting-human
  Assignment 现在进入接管扫描，保留同一 Ticket、generation、Attention 和 Worker Session。
- waiting-human 产品闭环使用真实两 OS 进程、真实隔离 PostgreSQL 和客户端 gateway。旧进程被强杀，
  新进程只有在 lease 过期后取得 epoch 2；接管记录 completed 后客户端重连同一 Main，回答原 Attention
  并得到 verified result。
- stopped、unknown effect/job、live remote job、queued input、撤权和 pending takeover 由 11 项核心接管
  回归分别覆盖；没有把它们合并成虚假的“同一产品场景全部通过”。
- 断连客户端补读继续由既有多客户端/游标网关测试和本票重连快照共同覆盖。实际外网 TLS、SSH 隧道、
  第二设备与真实桌面视觉仍归 T58/T55。
- 业务投影失败与 Session flush/writer epoch 失败分别由窄测覆盖，没有宣称跨库 ACID。旧
  `input-recovery` flush 崩溃夹具本轮未到达注入边界，记录为未计票的夹具限制，不冒充成功。
- 静态 patch 断言确认 PostgreSQL provider 被加入、JSONL 被条件停用；真实产品子进程再通过相同
  `Profile.apply`、PostgreSQL Session 插件和 Host 配置运行，组合证据足以验收本票的代码装配接缝。

## 结论

Standards 剩余 0 个硬阻断；1 个状态集合共享维护项和 2 个兼容性取舍保留为 judgement call。Spec
范围内的代码阻断已处理。真实服务器、第二设备、持续四目标、真实模型和真实飞书租户仍不作本票证据。
