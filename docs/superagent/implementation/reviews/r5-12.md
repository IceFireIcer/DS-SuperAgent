## Standards

来源、问题、回答和发送回执仍通过既有 Engine、FeishuSource/Runtime 与 Delivery 接缝；只在显式启用 `mainIntake` 时接收 Main 请求，旧用法不改变。产品 Host 配置从受信环境读取；密钥不出现在业务投影或文档。现有 UI 原位接入、生成资产校验及 UI 边界检查在集成阶段通过。未触碰 DSH 安装内容。

## Spec

针对群话题的首次复核发现：仅凭 root reply 或 @Bot 判定问题答案，会把普通讨论误答成等待中的问题，或将其误建为第二个 Main 请求。已改为按当前 Attention 的稳定问题码、来源 Thread、接收者及来源事件版本匹配；先处理原工作订阅/等待问题，再进入新请求准入。隔离飞书收发与产品 Main 的定向行为测试覆盖错误码、普通讨论、不同发送者、正确答案、回执与重连。未使用真实飞书租户，按维护者决定暂缓此层验收；不据 mock 声称真实信道通过。

## 无工作 Main 回复复核（2026-11-16）

**Standards**：新增的无 Ticket 回复仍走现有 Feishu channel、公开 Engine/Effect 和受信 Runtime 授权；业务记录只保存 Main 回复与原来源身份，不保存凭据。产品 Host 为 Feishu Engine 接入 runtime channel，并启动独立 Effect 队列；客户端/UI、DSH 安装和用户数据边界未改变。定向 build、typecheck、lint 和 `git diff --check` 通过。

**Spec**：无 WorkBrief 的人类请求现在由 Main 回复原 Feishu Thread，委托请求只走原 Ticket result；来源版本、Thread、作者、policy 和 Main 身份不匹配时失败关闭。未知发送复用不可变 Effect/reply identity 和 Feishu UUID receipt，后续来源编辑不会将可能已发送的结果伪判为永久失败；撤销 requester policy 会保持 unknown。隔离 14 项测试覆盖新增行为与 Host 异步路径；真实租户仍按维护者决定暂缓。四项验收完成，建议关闭 #105。
