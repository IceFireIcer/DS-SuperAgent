## Standards

来源、问题、回答和发送回执仍通过既有 Engine、FeishuSource/Runtime 与 Delivery 接缝；只在显式启用 `mainIntake` 时接收 Main 请求，旧用法不改变。产品 Host 配置从受信环境读取；密钥不出现在业务投影或文档。现有 UI 原位接入、生成资产校验及 UI 边界检查在集成阶段通过。未触碰 DSH 安装内容。

## Spec

针对群话题的首次复核发现：仅凭 root reply 或 @Bot 判定问题答案，会把普通讨论误答成等待中的问题，或将其误建为第二个 Main 请求。已改为按当前 Attention 的稳定问题码、来源 Thread、接收者及来源事件版本匹配；先处理原工作订阅/等待问题，再进入新请求准入。隔离飞书收发与产品 Main 的定向行为测试覆盖错误码、普通讨论、不同发送者、正确答案、回执与重连。未使用真实飞书租户，按维护者决定暂缓此层验收；不据 mock 声称真实信道通过。
