## Standards

复用 `RemoteEnvironment`、`RemoteDevice`、Execution Policy、Environment probe、MainConversation、WorkDelegation 和现有产品设置组件；没有新增设备协议、renderer 或旧 Bot dispatcher 入口。Main target 与 WorkBrief target 是现有命令/事实的窄扩展；`environmentId` 在 auto 下可为空，资源附件仍要求 exact Environment。远端恢复状态只存在业务持久层，窗口/模型无法提交它。配对和撤销带稳定 command ID、fingerprint 与结果，本地设置以外拒绝管理命令。

新增记录类型在 SQLite/PostgreSQL 共用注册表中；Session 仍由 DSH provider 独立持久。执行选择、Assignment 和 Device/Session 授权沿用原 Host lock、actor/Instance 检查和撤销。UI 使用现有设置页/composer/工作卡，不创建第二 renderer；文案中英同步，生成 `client.js`。

## Spec

Local-only、remote-only 与 auto 从 Main composer 进入真实 Ticket；active Assignment 保留原绑定。remote-only 只列远端且无目标时形成可恢复等待，不回退本机；auto 由现有 Execution Policy 在 Ticket 启动时探测；候选卡显示设备、目录、能力、版本和选择依据。Worker 观察详情读取持久选择记录，展示 target、required capabilities、来源、状态、原因及候选阻塞原因。实际 Worker 在 loopback 设备目录写文件、读回并提交报告，Host workspace 中没有该文件，证明文件/搜索/命令世界没有混用。附件仍绑定 exact Environment；远端未声明的 Office/browser/MCP/技能组合继续不可选。

真实第二设备、网络、真实模型和平台组合仍属环境验收，不在 loopback mock 中宣称通过。

## 修正轮次

复核提出的业务库私钥、配对/撤销命令不稳定的问题已修正：Host 交换私钥改存 DSH credential records，业务库只保留引用；设置页在网络结果未知后重试仍使用原 command ID；撤销先持久化 pending intent，并在完成后清理 credential record。`directory-options` 已限制为 local Environment，精确远端 Environment 未带 target 时会推断 remote-only，选择预览改用 probe 后的 online/version/fingerprint/capacity。远端纵切补充了同 Environment 的搜索、命令、技能、附件读取/保存和子代理工具，以及 Office 的严格远端拒绝和 no-local-fallback 证据。

真实第二设备、公网 TLS/SSH、连接半开、真实模型、真实远端 Office/MCP/browser 组合和生产 PostgreSQL 仍是环境验收项。配对设备后、凭据写入或业务提交完全未知时，Host 不伪造成功，要求先检查设备再重新发起配对；此跨进程人工对账路径不以 mock 通过冒充真实设备验收。

后续复核修正：放弃配对后的迟到凭据写入在事务中拒绝，失败路径会再次清理凭据；撤销先提交业务状态再移除运行时 Environment，提交失败的同命令可重试，重启后遇到 pending 不重复发设备命令，也不冒认设备确认。故障注入覆盖撤销删除事务失败后重启重放；配对网络半开、数据库 COMMIT_UNKNOWN 及真实第二设备仍需专门故障演练，不能从组件 mock 推断已验收。
