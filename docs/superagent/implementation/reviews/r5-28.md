## Standards

复核发现 App 暂存容量达到上限时会在解析新文件前淘汰最旧待处理导出；无效 JSON 或文件名可能使已有预览失去内存值。已将 JSON 和文件名校验移到淘汰之前，并加入容量边界测试。修复后未发现其他已知硬性规范违反或阻断提交的问题。实现使用 DSH credential record API；不 patch DSH、不枚举 DSH vault、不读写用户 `~/.dsh`。secret 只从用户明确选定的导出进入 Electron main process，在 Host IPC 中按单项及稳定引用读取；业务 SQLite 只保存引用、目标、状态和资源回执。错误跨进程时使用固定错误码，预览、状态、资源投影不含值。`client.js` 由现有构建脚本生成；输入焦点环、圆角及中英文案沿用现有 UI 约定。

竞态复核确认取消墓碑在等待中的 App 读取返回前持久化；迟到响应检查持久状态后不会创建资源或 grant。已创建但未确认的资源通过原凭据资源管理器撤销；cleanup pending 可重复处理。业务库与 DSH vault 之间不宣称原子提交或 exactly-once。

## Spec

四项 #120 验收均有对应代码路径和定向测试：

- 预览仅展示来源、原归属和无值项目；没有公开安全枚举 API 时明确提示手动新建资源。
- 用户逐项选择新资源名、角色、purpose 和 target scope；Host 与 UI 都拒绝 role-wide 导入，tool grant 需绑定 work item 或 Environment，source/outbound grant 需绑定精确 source Instance。
- 原件保持只读；同一来源的目标固定，命令重放可核对，冲突/未知/取消可见；重启后可通过重新选择原件恢复，旧 grant 不继承。
- 导入值进入 DSH credential record；使用和删除继续走 R5-15 的 `ProductCredentialManager`，业务记录和产品投影不含 secret。
