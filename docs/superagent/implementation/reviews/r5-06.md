# R5-06 双轴审查

- 日期：2026-11-15。
- 工单：[#98](https://github.com/IceFireIcer/DS-SuperAgent/issues/98)。
- 基线：后续审查使用集成树 `fd7f9ca1b541162090de283fc563e999d86e26df`；本票增量来自 `66bf52f`、`87e3926`、`01db1b7` 和 `fd7f9ca`。
- 范围：Main 当前回复停止、工作卡 stop/resume/retry、pre-Assignment stop、执行代次与 Ticket 版本校验、停止和设备确认投影、只读观察页返回 Main。

## Standards

- 使用现有 `product.js`、composer、i18n 和产品 Host 协议；没有新增替代 UI，也没有绕过公开 DSH Session API。生成后的 `client.js` 只有对应源文件改动，现有生成检查和 UI boundary 证据覆盖这一点。
- Main input stop 具有稳定 command identity，并与具体 message 绑定；它只 abort 当前 Main turn controller。已提交的工作经由 WorkBrief/Ticket/Assignment 继续，不因 Main 停止而被取消。
- Main 卡片 wrapper 现在只验证不可变的 Work item、Ticket 和 Main 归属。命令回执先于可变状态检查返回；新 resume/retry 仍在 Execution 写事务内校验卡片 generation，成功后以同一 command ID 重放不会再次换代。此前“回执查询晚于 generation 校验”的阻断项已关闭。
- 已接单但尚无 Assignment 的工作卡使用 Ticket `directionVersion` 作为稳定版本，并在 UI 显示 Stop。pending stop 在写事务内同时要求 Ticket 版本不变且 Assignment 仍不存在；若 Worker 在读取卡片后启动，旧命令返回 `WORK_VERSION_STALE`，不会出现界面已停但后台继续启动的窗口。
- 工作卡命令携带精确 `workItemId` 和 `ticketId`；有 Assignment 时还携带 generation，所有新命令均在 Execution 写事务内再次核验状态。直接 stale stop/resume/retry 回归覆盖授权检查与领域写入之间的换代竞态。
- 停止状态分别保存 `stopping`、设备确认待定和已确认静止，工作卡按持久事实展示；普通跟进、迟到结果和重启没有解除显式 stop 的路径。

## Spec

- 输入框只在存在当前 Main turn 时显示 Stop reply；已排队输入和 Router/Worker 工作不会因此被取消。
- 工作卡 stop/resume/retry 直达 Engine，不要求 Main 模型可用；精确 Work item、Ticket、Ticket 版本和 generation 阻止按最近 Worker 猜目标。
- pre-Assignment stop 先提交 Ticket stop constraint，再返回控制结果；迟到的 Assignment 不能绕过该约束继续执行。对同一已提交 command 重放会返回原 stop 回执，不修改后来出现的历史 Assignment。
- 观察页只保留返回 Main；回答、停止、恢复和重试入口只在主对话工作卡。
- Host 重启后的 pending stop 以 Host custody 结束为持久 stop，迟到 Main 回复不发布。逻辑工作不依赖 Main 模型存活。
- 当前基线重跑 `main-controls` 为 4/4，覆盖 Main stop 后工作继续、Host 重启确认、pre-Assignment stop/启动竞态和回答控制；实现记录还保留 Main、Attention、follow-up、stop 与 retry 定向组合 12/12。测试使用 mock 模型和临时数据。
- 没有运行全量 suite 或 CI。没有真实设备取消确认、真实模型或最终四目标组合证据；这些仍由 T55/T58 等组合验收承担。

此前记录的唯一阻断项已由稳定回执优先和写事务内版本 CAS 关闭；pre-Assignment stop 与启动竞态也在当前基线有行为测试。剩余阻断项：0。
