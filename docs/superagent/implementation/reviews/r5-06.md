- 日期：2026-11-15。
- 工单：[#98](https://github.com/IceFireIcer/DS-SuperAgent/issues/98)。
- 基线：集成树 `152095b63430af0c51093d227082c1a828d82c33`；本票增量主要来自 `66bf52f`、`30c6701` 和 `87e3926`。
- 范围：Main 当前回复停止、工作卡 stop/resume/retry、执行代次校验、停止和设备确认投影、只读观察页返回 Main。

## Standards

- 使用现有 `product.js`、composer、i18n 和产品 Host 协议；没有新增替代 UI，也没有绕过公开 DSH Session API。生成后的 `client.js` 只有对应源文件改动，现有生成检查和 UI boundary 证据覆盖这一点。
- Main input stop 具有稳定 command identity，并与具体 message 绑定；它只 abort 当前 Main turn controller。已提交的工作经由 WorkBrief/Ticket/Assignment 继续，不因 Main 停止而被取消。
- 工作卡命令携带 `workItemId`、`ticketId` 和 `expectedGeneration`，并在 Execution 写事务内再次核验 Assignment generation。直接 stale-generation stop/resume/retry 回归共 11/11，覆盖授权检查与领域写入之间的换代竞态。
- 停止状态分别保存 `stopping`、设备确认待定和已确认静止，工作卡按持久事实展示；普通跟进、迟到结果和重启没有解除显式 stop 的路径。
- 阻塞项 1：`stopMainWork`、`resumeMainWork` 和 `retryMainWork` 在调用 Execution 的命令回执查询之前，先通过 `requireMainWorkControl` 要求当前 Assignment 等于卡片 generation。成功的 resume/retry 会创建新 generation，因此响应丢失后使用同一 command ID 和原请求重试会被 `WORK_VERSION_STALE` 拒绝，而不是返回原回执。这违反同命令去重和提交未知按原身份对账的要求；应先识别不可变命令回执，同时仍用写事务中的 generation 校验拒绝新的 stale 命令。

## Spec

- 输入框只在存在当前 Main turn 时显示 Stop reply；已排队输入和 Router/Worker 工作不会因此被取消。
- 工作卡 stop/resume/retry 直达 Engine，不要求 Main 模型可用；精确 Work item、Ticket 和 generation 阻止按最近 Worker 猜目标。
- 观察页只保留返回 Main；回答、停止、恢复和重试入口只在主对话工作卡。
- Host 重启后的 pending stop 以 Host custody 结束为持久 stop，迟到 Main 回复不发布。逻辑工作不依赖 Main 模型存活。
- 主对话停止和工作继续的集成测试是 1/1；既有 stop/retry/remote-stop 定向组与新增 CAS 组分别为 11/11。测试使用 mock 模型和临时数据，未运行全量 suite 或 CI。
- 没有真实设备取消确认、真实模型或最终四目标组合证据；这些是本票记录已声明的上游验收边界，不是本次增量内的额外回归。

本轮未重跑测试，只复核了现有实现记录、测试断言和定向证据。剩余阻断项：1，根因是工作卡命令回执查询晚于可变 generation 校验。
