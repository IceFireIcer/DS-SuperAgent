### Spec

产品 Host 的 GitHub 来源从 `gh api` 只读轮询真实 Issue/PR/评论/评审/CI 数据，接纳事实后人类新请求按 allowlist 进入 Main，既有工作依据原 Thread 保留归属。bot/CI 候选仅对当前受信仓库和本地选定规则生效；CI 在已有工作上可同时是上下文和规则候选，不建立额外 Ticket。observe 不调模型，auto 仍由原事务控制预算、规则修订、暂停、停止、来源版本及工作归属，仅在独立文件目录产出可核验审阅材料。来源正文和 CI 不能更改规则或授予写 GitHub、发信、PR、合并及 Shell 权限。Feishu 与 GitHub 同时配置时呈现为两个精确 source instance，规则不会跨仓库误用。

未完成仍在 #115：当前仅单仓库配置，GitHub 出站写信道须另获授权；缺受权仓库复现、正式 Ticket/Mandate/Assignment 投机工作链、真实 token/金额、真实 GitHub/Feishu/模型与组合部署证据。本次 mock 通过不代表真实账号/CI 组合验收，issue 保持开放。
