## Standards

## GitHub/CI 增量双轴自检（2026-11-16）

基线为已推送 `dev` 的 `7502d79`，工作目录为独立短路径 worktree，分支 `feat/115-r5-23-github-source`。以下是实施者自检，不称独立代理审查。

### Standards

检查 `AGENTS.md`、`CONTRIBUTING.md` 与 UI 边界：受信 profile 环境变量/Host 配置启动一个仓库的 GitHub runtime，保留原 `GitHubCliTransport`、`GitHubSource`、Engine/Proactive 和现有客户端设置组件。无 DSH、旧 dispatcher、`.idea/` 或 `CHANGELOG.md` 改动。首次 UI 规则源列表与 CI actor 选择只改现有组件及 i18n；`client.js` 由源码重新生成并检查一致性。仓库规则限制仍由同一 Proactive 事务持久到 SQLite/PG 共用记录类型，不增加单数据库 schema。测试只用临时状态、mock 模型与注入 API runner，并显式把测试 CLI 命令设为不存在；Node 24 检查与 UI boundary 使用本次明确请求的 UI 授权。

自检修正停机窗口：GitHub runtime 在停止开始时报告 stopped；轮询获取 API 页后与逐事件提交前检查中止，完成停机后再丢弃该来源剩余候选，迟到页不能生成新准备。测试验证停机期间获取的页没有推进游标或进入规则，明确重启后才接收。同一主对话的 GitHub 目的地在没有额外出站授权时只产生拒绝回执，不会被本地默认信道误报为已发送。

### Spec

产品 Host 的 GitHub 来源从 `gh api` 只读轮询真实 Issue/PR/评论/评审/CI 数据，接纳事实后人类新请求按 allowlist 进入 Main，既有工作依据原 Thread 保留归属。bot/CI 候选仅对当前受信仓库和本地选定规则生效；CI 在已有工作上可同时是上下文和规则候选，不建立额外 Ticket。observe 不调模型，auto 仍由原事务控制预算、规则修订、暂停、停止、来源版本及工作归属，仅在独立文件目录产出可核验审阅材料。来源正文和 CI 不能更改规则或授予写 GitHub、发信、PR、合并及 Shell 权限。Feishu 与 GitHub 同时配置时呈现为两个精确 source instance，规则不会跨仓库误用。

未完成仍在 #115：当前仅单仓库配置，GitHub 出站写信道须另获授权；缺受权仓库复现、正式 Ticket/Mandate/Assignment 投机工作链、真实 token/金额、真实 GitHub/Feishu/模型与组合部署证据。本次 mock 通过不代表真实账号/CI 组合验收，issue 保持开放。
