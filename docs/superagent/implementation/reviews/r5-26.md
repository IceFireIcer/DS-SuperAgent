- 方法：两个独立子代理并行检查同一 staged diff；Standards 读 `AGENTS.md`、`CONTRIBUTING.md`、`docs/design/ui-standard.md` 与相邻实现，Spec 对照 #118、`docs/superagent/spec-r5.md` 的 D09/D10/A13/A21。

## Standards

首轮发现两处硬性 UI 规范：导入卡片说明超过一句、平面批次/项目边框使用浮层线色。另有来源 secret 正则重复、metadata 取值重复、commit 混合阶段过长、item 装载重复、二次查找、`targetRoles` 未被 UI 消费、UI 测试 harness 重复与目标选择控件的判断项。

修复后：说明缩成一句；平面边框改用 `--bt-line`；credential 识别集中到导入格式模块并覆盖扩展 token 样式；metadata 只解析一次；批次/项目装载、活动记忆扫描与导入条目创建拆分；批次状态使用有序 items；`targetRoles` 直接驱动 UI；同一批次刷新保留选择，打开另一批次重置选择。UI 测试 harness 的重复被保留为测试代码的局部取舍，没有形成产品重复。

最终复核：**0 个阻断项，Standards clean**。生成 `client.js` 与源一致，新增记录继续使用共享 `RecordKind`/`Storage` 合约。

## Spec

首轮阻断为：导入时不能选择目标 shared scope；持久批次无法从 UI 独立重开；`access_token` 等常见凭据可绕过过滤；冲突或全拒绝可能显示 completed；原件哈希经过 `File.text()` 重编码；不同批次复用同一来源 ID 但内容改变时未判定冲突；切换批次可能沿用上一批次勾选/目标。

修复后：逐项可显式选择 Main、工作或 shared，shared 必须有当前接收者；设置页列出最近 20 个批次并可重开，打开不同批次重置选择；浏览器传原始文件 bytes 的 canonical base64，Host 严格 UTF-8 解码并按原始 bytes 计算 SHA-256；凭据匹配覆盖 access/refresh token、client secret、private key、Bearer 及常见 GitHub/OpenAI/Slack/AWS token；只有全部项目 imported 才是 completed，其他已完成尝试为 partial；持久来源身份记录以原归属者/Instance/sourceId 为键检测内容变化，冲突指向较早批次并禁止导入；目标内重复仍记录已有 Memory ID。

最终复核：**0 个阻断项，Spec clean**。四项验收均有 Engine/产品入口/UI 代码证据；真实旧用户资料、真实桌面文件选择、生产 PostgreSQL 与真实模型/信道不在本次环境证据内。
