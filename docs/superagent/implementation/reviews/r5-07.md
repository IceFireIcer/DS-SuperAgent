- 范围：当前 Attention 的主对话卡片、版本化回答、停顿后失效、原 Assignment/Session 续接和观察页只读约束。

## Standards

- Attention 持久保存工作、Assignment、Session、问题版本、选项、回答者与回答正文；stop 将当前等待问题标为 `superseded`，答后事实也保留在历史中。
- 产品命令同时携带 Work item、Ticket、Assignment generation、Attention ID、版本和有界正文。Engine 再核验 Instance、Main 归属、当前 Assignment、当前 Attention head 和等待约束。
- 回答使用稳定 deterministic synthetic Input；同 command、同文重放返回原 Input，异文返回 `IDENTITY_CONFLICT`。错误 actor、旧版本、旧 generation、停止后回答均有定向拒绝案例。
- UI 只向现有 Main 工作卡增加当前问题表单；观察页仍只导航回主对话。`client.js` 由源文件生成，测试覆盖生成客户端和产品状态。
- 阻塞项 1：`answerMainAttention` 在 `answerAttention` 查询稳定 command receipt 之前，先经 `requireMainWorkControl` 和 Attention head 比较当前 generation/version。回答后若 Worker 合法换代或 rollover，使用同一 command ID 重试会在回执查询前得到 `WORK_VERSION_STALE`/`ATTENTION_STALE`，因此网络响应丢失后的成功回答不能跨后续状态推进幂等重放。应先用不可变命令身份返回已提交回执，同时继续要求新命令精确匹配当前卡片。

## Spec

- 卡片回答绕过 Main 模型转述，直接从产品 Host 到 Engine；Main 模型失败不会阻止提交当前结构化答案。
- 合法答案清除了同一 Ticket 的 `waiting-human` 约束，并把 synthetic Input 投递到原 Worker Session；stop 后的晚答和旧 Attention ID 被拒绝。
- 当前 question/options/answer status 来自持久 Attention；stop 后卡片显示问题不再 active。一个 Ticket 的 waiting-human 不会成为全局 Main 或其他 Ticket 的锁。
- Main 卡片集成测试覆盖当前问题读取、错误 actor、旧版本、旧 generation、合法回答、同文重放、异文冲突、stop 后拒绝和观察事实；Attention 回归继续覆盖同一 Assignment/Session 与正常消费。
- 定向串行执行记录为 33/33，DS Bot composer/i18n/产品状态为 5/5；typecheck、build、lint、客户端生成检查和 UI boundary 有通过记录。未运行全量 suite 或 CI。
- 没有真实外部信道、真实模型语义质量或桌面组合验收。回答后的 Main 通知记录与答案命令不在同一业务事务，代码依靠同 command 重放恢复；当前测试没有注入该二次写入故障，故作为证据边界保留。

本轮未重跑测试，只复核了现有实现记录、测试断言和定向证据。剩余阻断项：1，根因是回答回执查询晚于会随工作推进变化的 generation/version 校验。
