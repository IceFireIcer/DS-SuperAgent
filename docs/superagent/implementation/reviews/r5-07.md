## Standards

- Attention 持久保存工作、Assignment、Session、问题版本、选项、回答者与回答正文；stop 将当前等待问题标为 `superseded`，答后事实也保留在历史中。
- 产品命令同时携带 Work item、Ticket、Assignment generation、Attention ID、版本和有界正文。Main 卡片 wrapper 只先校验稳定的 Work item/Ticket/Main 关系；新回答在 Engine 写事务内精确核验当前 generation、Attention head 和等待约束。
- 回答使用稳定 deterministic synthetic Input；同 command、同文重放返回原 Input，异文返回 `IDENTITY_CONFLICT`。持久回执在可变 generation/version 检查之前读取，因此合法 Worker 换代后仍可返回原回答。此前“回执查询晚于 Attention/Assignment 校验”的阻断项已关闭。
- UI 只向现有 Main 工作卡增加当前问题表单；观察页仍只导航回主对话。`client.js` 由源文件生成，测试覆盖生成客户端和产品状态。
- `fd7f9ca` 将 Attention status、synthetic Input、工作命令回执、Main work update、持久 answer fact 与 Router notice Outbox 放入同一业务事务。稳定 fact/effect key 和 Router Session message ID 让原命令 replay 不再重复产生通知；Main 暂时不可用不影响已提交的卡片事实，Router 暂时不可用时 notice 可由 Outbox 重试。
- `fd7f9ca` 同时补齐 pre-Assignment stop；该行为属于 R5-06，并已在该票审查中记录。它不改变本票回答 identity 或 fact/outbox 的去重边界。
- 相邻提交 `8c2254f` 修正 GitHub changed/deleted event 的真实操作者和 source Main recovery；本票复核了它与 Attention destination/answer actor 的接口，没有发现改写用户选择或绕过当前问题校验的新路径，其来源验收仍由 R5-11/R5-13 承担。

## Spec

- 卡片回答绕过 Main 模型转述，直接从产品 Host 到 Engine；Main 模型失败不会阻止提交当前结构化答案。
- 合法答案清除了同一 Ticket 的 `waiting-human` 约束，并把 synthetic Input 投递到原 Worker Session；stop 后的晚答和旧 Attention ID 被拒绝。
- 当前 question/options/answer status 来自持久 Attention；回答 fact 使用稳定 ID 并进入 Main work update，Router notice 由独立、可恢复的 Outbox 处理。stop 后卡片显示问题不再 active，一个 Ticket 的 waiting-human 不会成为其他 Ticket 的锁。
- 当前基线重跑 `main-controls` 为 4/4、Attention 为 7/7，覆盖当前问题读取、错误 actor、旧版本、旧 generation、合法回答、合法换代后 replay、异文冲突、stop 后拒绝、回答 fact/effect 只出现一次和观察事实。
- 实现记录还保留 Super-agent 定向串行 33/33、DS Bot composer/i18n/产品状态 5/5，以及 typecheck、build、lint、客户端生成检查和 UI boundary 通过记录；当前基线未运行全量 suite 或 CI。
- Router notice 与答案事实同事务出现已有行为断言，但窄测没有注入“事务提交后、Router Session 完成前进程崩溃”的故障；真实外部信道、真实模型语义质量和桌面组合仍由后续组合验收承担。

此前记录的唯一阻断项已由稳定回执优先关闭；回答事实和 Router Outbox 的原子提交补齐了通知半写窗口。保留的崩溃注入与真实环境验证属于组合证据边界。剩余阻断项：0。
