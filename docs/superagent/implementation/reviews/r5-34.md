# R5-34 实施复核

固定点：`5015e89ce8b43374292de19fff50494dc3986baa`。Standards 与 Spec 使用两个独立复核；审阅对象是
R5-34 的入口、删除、现有 UI 收口、保留能力、85 项处置、应用 profile 和定向证据。没有把 Issue 状态、旧记录
或 mock UI 当作当前恢复证据。

## Standards

初次复核的硬阻断：

- 应用询问 workspace，但 `main.mjs` 忽略选择，始终使用 `<hostHome>/workspace`。已改为
  `where.workspace ?? <hostHome>/workspace`，并在 `main.test` 断言 Host 收到所选路径。
- `ds-bot/package.json` 的 `check` script 指向已删除的 `dev/check.sh`。已删除该入口。
- app lockfile 的首次重新生成丢失了大量未变依赖的 registry metadata。已用原 lock 的未变 package entry
  合并只删除 renderer 依赖并加入 `playwright`/MCP 所需 entry；`npm ci --dry-run` 通过。
- README 声称 `DS_BOT_USER_DSH_HOME` 仍约束产品目录，但应用不再传入。现在 App 把它传给 Host，
  `product-host` 用该路径执行 workspace 隔离，`product-directories.test` 验证自定义用户 DSH 目录被拒绝。
- 旧 schedule formatter 被产品页导入，导致已删除 team schedule 实现继续生成。格式化逻辑已移入
  `product-schedules.js`，旧 `schedules.js`、Bot/group avatar 和旧 mark helper 已删除。
- `activeProfile()` 是无调用者的常量 wrapper。已删除，profile 测试直接验证固定 home。
- Office patch 中“检查 profile”的源码 regex 测试针对已删除分支。已删除该非行为测试。
- AGENTS 的布局说明和 PR 模板仍要求已删除的 test bench/smoke 脚本。已改为当前 Super-agent
  typecheck/build 与 product-profile 检查。
- Docker 只在空 `/data` 复制新模板，旧持久 web profile 会继续没有 `ds-superagent`。entrypoint 现在检查现有
  profile package，缺少新包时明确失败并要求新/归档 `DATA_DIR`；测试增加 pre-R5 profile fail-closed 场景。
- App README、Docker README 和代码注释仍残留 “Bots/team workspace”。已统一为 Main/Router/Worker/workspace。

最终复核确认上述工程阻断均关闭。剩余项只是既有 judgement calls：产品仍保留大量共享 CSS selector，
历史计划文档保留已标注 superseded 的旧设计说明；二者都没有可执行旧入口。

## Spec

初次 Spec 复核确认 85 个操作清单无遗漏，并发现：

- `browser-plugins/` 仍导入已删除的 `ds-bot/src/host/browser/*`，是可执行的断裂旧机制。该目录及仓库中
  最后一条 ignore rule 已删除；当前浏览器能力由 `superagent/src/browser-resources.ts`、
  `browser-host.ts`、`app/src/bot-views.mjs` 和现有 Browser settings 消费。
- 应用仍出现 “Its Bots go on working” 和 “team workspace”。已改为
  Main/Router/Worker 和 workspace；产品模板中的旧 Bot 配置术语改为 legacy role；View 的发送动作改为
  Send to Main。
- `--check-refs` 缺少本复核文件。已补齐。
- T55 runner 删除 migration phase 后，`t55-acceptance.test` 仍预期它。测试计划已同步；定向运行
  **9 pass、1 Windows POSIX-signal skip、0 fail**。

最终 Spec 复核确认没有保留能力的旧 consumer 残留：

- Office、记忆、MCP、日程、附件、资源、浏览器、远端执行、凭据、导入、监督与 PostgreSQL/Session 路径仍有
  当前 R5 producer/consumer。
- `/api/bot`、旧 SSE/native history/question/delivery façade、roster/group/round/tool hooks 与
  activation/reversal entry 均不再挂载或构建。
- 直接 native Session list/read/export 与 Gateway prompt/control 均被拒绝；产品只通过 Engine/公开 DSH loop
  写入。
- 应用只启动一个 `ds-superagent` profile；可选 browser/credential/memory 导入不依赖旧 runtime。
