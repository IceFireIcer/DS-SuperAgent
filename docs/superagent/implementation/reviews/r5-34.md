## 2026-11-18 单包收口复核

这次追加复核以工作区实际代码、生成产物、package manifest、app profile、Docker 和 CI 为对象，不以 Issue 的
CLOSED 状态或旧实施记录为完成证据。

### Standards

初查阻断与处置：

- `superagent` 仍只有 Engine，而旧 UI/Host bridge/Office/web-search 仍在第二个 DSH 包。已将旧目录整体迁入
  `superagent/dsh/`，删除第二个 package manifest、loader row、cordis patch、lockfile 和 npm dependency。
- package root 仍只导出 Engine，DSH 无法从同一包取得 Host 与 client。现在 root apply 是 production profile，
  `enginePlugin` 供 CLI/mock 使用，manifest 同时声明 bundle patch、`./client` 和 `./web-search`。
- `dist/` 构建不清理，历史 artifact 达到 2,545 files，tarball 约 98 MB。build 现在先清理 ignored dist；最终
  tarball 162 files、约 0.85 MB compressed。
- App 一半 IPC 仍使用 `ds-bot:*`，浏览器全局仍是 `dsBotApp`。产品通道统一为 `ds-superagent:*` /
  `dsSuperagentApp`；Host Browser endpoint 的进程消息同步改名。
- CI 仍保留只测试旧包的独立 job，change scope、UI boundary、scan、release tarball 和 Docker 仍指向旧路径。
  已改为一个 Super-agent job、一个新 UI boundary 和单包 release/Docker。
- App、README、CONTRIBUTING、AGENTS、SECURITY 和 lockfile 的旧路径已同步；`npm pack` 验证不再包含旧包。

独立双轴复核又发现并关闭：

- `start.ps1` 的 source hash 仍包含已删除的 `superagent/.npmrc`，会让启动器在安装前失败。现在只 hash
  `package.json` 与 lockfile。
- `claimBundles` 只移除旧 bundle，仍可能在持久 profile 的 dependency 表中留下 `ds-bot`。现在保留用户包和
  磁盘数据，只清掉 retired bundle 对应的 dependency/dev/optional dependency，并由 profile upgrade 测试覆盖。
- release 的四个 shard 把 `--test-shard` 附加在组合 `npm test` 的最后一条 client 命令，导致每个 shard 重跑
  全部 Server 测试。完整验收现在分别运行 Server 与 client shard；每日 client 全套在 check job 运行一次。
- `/api/product` 的英文错误由浏览器直接显示。`productCall` 现在统一经过 `t()`，对应中文键已加入 i18n；
  HTTP error 的消息与状态也用单表/窄规则生成，避免两个平行错误码级联。
- UI approval 文档仍写旧 `DSBOT_UI_CHANGE_APPROVED`。已统一为新变量，并按用户本次明确授权运行边界检查。
- 最终 `npm ci` 发现 app lock 的 `node_modules/ds-superagent` 缺少 `resolved: file:../superagent`，npm 因而
  尝试访问不存在的 registry 包。已补齐 file resolution，并在干净 `node_modules` 上重跑成功；app 只安装
  `ds-superagent@0.2.5`。App profile dependency 清理新增导出也让 fake app-boot 同步提供同一公开 API，product
  IPC 回归恢复通过。
- 第一次远端 CI 又发现两个真实边界：root profile 顶层等待 `connection` 会让无 Web profile 不发布产品服务；
  pnpm 11 会在 Docker 的 plugin add 阶段拒绝三个未 allowlist 的原生构建脚本。现在 HTTP bridge 自己等待
  `connection`，T59 process 通过；Docker template 只允许精确的 `dsh-subprocess-local`、`koffi` 和
  `node-pty` builds，隔离 profile 中一次单包安装真实完成 49 packages 和全部三个脚本。

Standards 追加阻断：**0**。

## Standards

初次复核的硬阻断：

- 应用询问 workspace，但 `main.mjs` 忽略选择，始终使用 `<hostHome>/workspace`。已改为
  `where.workspace ?? <hostHome>/workspace`，并在 `main.test` 断言 Host 收到所选路径。
- `ds-bot/package.json` 的 `check` script 指向已删除的 `dev/check.sh`。已删除该入口。
- app lockfile 的首次重新生成丢失了大量未变依赖的 registry metadata。已用原 lock 的未变 package entry
  合并只删除 renderer 依赖并加入 `playwright`/MCP 所需 entry；`npm ci --dry-run` 通过。
- README 声称 `DS_BOT_USER_DSH_HOME` 仍约束产品目录，但应用不再传入。现在 App 把它传给 Host，
  `product-host` 用该路径执行 workspace 隔离，`product-directories.test` 验证自定义用户 DSH 目录被拒绝。
- 旧 schedule formatter 被产品页导入，导致已删除 team schedule 实现继续生成。格式化逻辑已移入
  `product-schedules.js`，旧 `schedules.js`、Bot/group avatar 和旧 mark helper 已删除。
- `activeProfile()` 是无调用者的常量 wrapper。已删除，profile 测试直接验证固定 home。
- Office patch 中“检查 profile”的源码 regex 测试针对已删除分支。已删除该非行为测试。
- AGENTS 的布局说明和 PR 模板仍要求已删除的 test bench/smoke 脚本。已改为当前 Super-agent
  typecheck/build 与 product-profile 检查。
- Docker 只在空 `/data` 复制新模板，旧持久 web profile 会继续没有 `ds-superagent`。entrypoint 现在检查现有
  profile package，缺少新包时明确失败并要求新/归档 `DATA_DIR`；测试增加 pre-R5 profile fail-closed 场景。
- App README、Docker README 和代码注释仍残留 “Bots/team workspace”。已统一为 Main/Router/Worker/workspace。

最终复核确认上述工程阻断均关闭。剩余项只是既有 judgement calls：产品仍保留大量共享 CSS selector，
历史计划文档保留已标注 superseded 的旧设计说明；二者都没有可执行旧入口。

## Spec

初次 Spec 复核确认 85 个操作清单无遗漏，并发现：

- `browser-plugins/` 仍导入已删除的 `ds-bot/src/host/browser/*`，是可执行的断裂旧机制。该目录及仓库中
  最后一条 ignore rule 已删除；当前浏览器能力由 `superagent/src/browser-resources.ts`、
  `browser-host.ts`、`app/src/bot-views.mjs` 和现有 Browser settings 消费。
- 应用仍出现 “Its Bots go on working” 和 “team workspace”。已改为
  Main/Router/Worker 和 workspace；产品模板中的旧 Bot 配置术语改为 legacy role；View 的发送动作改为
  Send to Main。
- `--check-refs` 缺少本复核文件。已补齐。
- T55 runner 删除 migration phase 后，`t55-acceptance.test` 仍预期它。测试计划已同步；定向运行
  **9 pass、1 Windows POSIX-signal skip、0 fail**。

最终 Spec 复核确认没有保留能力的旧 consumer 残留：

- Office、记忆、MCP、日程、附件、资源、浏览器、远端执行、凭据、导入、监督与 PostgreSQL/Session 路径仍有
  当前 R5 producer/consumer。
- `/api/bot`、旧 SSE/native history/question/delivery façade、roster/group/round/tool hooks 与
  activation/reversal entry 均不再挂载或构建。
- 直接 native Session list/read/export 与 Gateway prompt/control 均被拒绝；产品只通过 Engine/公开 DSH loop
  写入。
- 应用只启动一个 `ds-superagent` profile；可选 browser/credential/memory 导入不依赖旧 runtime。

## 结论

两次复核合计 Standards 硬阻断 **0**，Spec 阻断 **0**。剩余环境边界仍是真实飞书租户、真实模型、第二设备、
托管组合与完整 T55/T58 验收；本票没有运行全量 CI，也没有把 mock UI 单测当作真实恢复证明。
