## Standards

Engine 继续是目录记录、默认修订、WorkBrief 和命令回执的写入口；SQLite 与 PostgreSQL 使用相同 RecordKind，来源命令与目录选择同事务固定，不做 DSH 源码修改。UI 使用现有文件夹菜单、卡片、主题变量与英文源文案/中文映射；`client.js` 由构建生成。已有场景在二轴核查时发现并修复了首次启动没有默认目录时不能在注册后委托、来源默认切换与重试之间的事务竞态，以及普通远端工具意外暴露后台 start_command 的风险。

`git diff --check`、Super-agent typecheck/lint、DS Bot lint 与 UI 边界检查通过。DS Bot lint 的警告来自本票未改动的文件。未发现本票新增的标准违规；Windows PTY 生命周期限制在实施记录中单列。

与 `feat/r5-integration` 的 `c94ba36` 合并时，保留 Feishu Host/UI 的状态、停止/重连和来源投递，同时让工作目录通过产品桌面 Engine 固定并供来源工作复用；客户端 bundle 重新生成并通过一致性校验。Feishu 来源与工作目录的交叉窄测见实施记录。

## Spec

按 #109 四条验收逐项核对：默认/覆盖选择可用且在 Main 输入及 Assignment 固定；目录、文件、搜索、shell、输出和附件的本地 Environment 一致；异步完成按 job/subagent ID、Ticket 与代次回原 Worker，子代理只继承授权工具；停止只清理目标工作范围，预览保持原独立保留规则。公开 Engine/Host 场景包括无初始目录、并行双目录、默认变更、重启、后台 job 与子代理。

剩余边界：Windows DSH 原生 PTY 在公共 API 最小复现中 `dispose()` 后残留 `MessagePort`；使用强制退出选项的功能测试不能证明原生 Host 生命周期自然结束。远端设备、真实模型与原生 UI 窗口并非本次 mock/本地证据。

## 2026-11-16 Spec-review P1 复核

**Spec：** 原实现先启动本地进程、再验证 Assignment 并登记 Job；人工停止在两者之间只能看见 Worker，无法枚举刚启动的进程。现先持久保留 `starting` Job，停止与代次结束沿同一活跃索引取消，并等待同一进程范围确认静止；启动迟到、退出不可证实均不写 `cancelled` 或停止确认。定向主对话测试将启动返回与进程退出分别设闸，验证停止前后状态、迟到句柄终止及另一目录继续。Worker 的正常后台完成、子代理继承和预览保留仍由既有场景检查。

**Standards：** 写入事实在原 Instance 事务中完成，外部启动在持久意图之后；不访问 DSH 私有实现或改动产品 UI。Node 24 定向测试、typecheck、lint、差异格式检查见实施记录。保留 5 秒等待后 `unknown` 的显式限制和 Windows PTY 强制退出限制，不把它们当作静止确认。未运行全量测试或 CI，未关闭 #109。
