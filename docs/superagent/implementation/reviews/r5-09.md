# R5-09 双轴审查

审查目标：R5-09 Main generation rollover、证据续读和旧代隔离的工作树；对照 `origin/dev`。子代理工具在当前执行环境不可用，因此两轴由主代理分开检查。

## Standards

- 检查 `AGENTS.md`、`CONTRIBUTING.md`、R5 总规格、现有 NativeSessions/ContextReader/Product Host/UI 边界。
- Main fork 进入、seed flush、child dispose 全部使用公开 Agent、Session 和 SessionPersistence API；没有读取或修改 DSH 内部文件。
- fork 先持久化 child Session，再通过业务事务推进 `main-session-rollover`、`main-state` 和 system fact；业务与 Session 仍分开持久，没有宣称跨库 ACID。
- Main 回复与 work notification 均核验启动时 Session/generation。旧代回复返回 `MAIN_TURN_STALE`，不会覆盖当前 `activeCommand` 或当前 Session。
- `read_work_evidence` 先核实当前逻辑 Main 的 accepted workItem，再按 Ticket 重建引用；`ticketId` 不能由调用方覆盖，ContextReader 保持 256–16384 字节预算和 UTF-8 continuation。
- 复用现有 MainConversation、NativeSessions、ContextReader、WorkDelegation 和 ChatRows；没有新增 Session 镜像、第二 Engine 或 UI 写旁路。
- `client.js` 从现有 `src/client/` 生成；系统 rollover、原始请求证据和加载入口沿用现有主题、键盘 focus 与 390px CSS。
- 未发现 secret、用户 DSH 数据、CHANGELOG、生成文件手改或 AI author/trailer。
- 本阶段剩余阻断项：0。

## Spec

- `max-tokens` 将 Main 切换到已持久化的 forked child；`mainId` 不变，generation 前进，旧 Session 和业务消息历史继续可读。
- rollover 记录工作索引、目标、约束、验收、状态和 Ticket/report/attention evidence refs；queued input 在 context-full 回合中单独测试并进入 unread handoff。
- stop 状态在 rollover 前写入 Ticket，交接后工作索引仍为 stopped。waiting/unknown 使用同一持久工作投影进入 workIndex，不会被 rollover 清除；直接的停止/回答 UI 仍归 R5-06/R5-07。
- Main 工具与 Engine 都只能读取已接受工作的精确证据；测试实际从 Main 调用工具，并用 256 字节页续读原请求；伪造 `ticketId` 返回 `INVALID_INPUT`。
- 部分证据显式返回 `truncated`、字节总数、返回字节数和 cursor；现有 Main UI 提供原始请求分段加载，不以摘要伪装全文。
- 旧 Session 延迟完成场景在业务 generation 推进后返回 `MAIN_TURN_STALE`，当前历史不接受旧回复。
- 本阶段剩余阻断项：0。完整 #101 仍需在 R5-06/R5-07 与真实模型/组合环境到位后汇合验收；当前证据是确定性 mock 和真实公开 profile 接缝。
