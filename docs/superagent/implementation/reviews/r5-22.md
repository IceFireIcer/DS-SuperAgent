- 范围：日程来源、明确工作目标、重复发生点、人工停止、Host 重启、现有设置入口和来源授权。

## Standards

新增日程页复用现有设置控件、主题变量及英文源文案/中文翻译；`client.js` 从源码生成。首轮审查发现该页部分按钮没有可见键盘焦点环、发生点失败时直接显示机器代码，现已将焦点规则覆盖本页按钮，并对已知失败原因提供可翻译的用户文案。SQLite 与 PostgreSQL 共用记录类型；本机 PostgreSQL fixture 启动超时，未把这条缺失证据写成通过。

## Spec

单次/重复日程使用稳定 occurrence 身份、明确时区、授权 Main 或具体工作目标；重复 tick、停用来源和重启不会重建已提交工作，停止的 Ticket 不因日程触发而恢复。首轮审查发现同一 Instance 的非产品来源 Engine 可读写全局日程状态，违反受信产品授权边界；现已在公开 Engine 日程查询、创建、取消、来源控制和 tick 入口统一限制产品 actor，并新增 Feishu 接收 Engine 的拒绝回归。真实模型、设备和最终组合验收仍在 #83/#92。

Node 24 定向日程与飞书产品 Host 8/8、客户端日程/bundle/i18n 5/5；构建、类型检查、客户端生成、UI 边界及实施记录检查通过。未运行全量 CI。

## 发生历史 UI 收尾复核（2026-11-16）

**Standards**：历史沿用原设置行，不增设渲染器；使用原主题变量、英文 key 与中文翻译。语义 `<details>/<summary>` 提供键盘展开，历史记录行明确换行并限制首次显示 20 条，更早条目按需加载。每个工作 occurrence 按 Ticket ID 或 WorkBrief ID 打开对应 MainWorkCard；卡片成为程序化焦点目标，并有 `:focus-visible` 强调色焦点环。客户端包由 `build-client.mjs` 生成，UI boundary 经用户授权检查。

**Spec**：逐次显示时间、原因、执行状态、WorkBrief/Ticket 关联；21 条行为测试覆盖最近 20 条、展开后加载旧记录，以及较早记录分别按 Ticket 和 WorkBrief 打开对应卡片。未扩展 occurrence 数据模型，复用现有 `schedule-read` 回执。定向 DOM 测试、客户端生成一致性、lint、UI boundary 与实施记录检查通过；没有运行全量测试/CI。无真实信道或桌面截图测试，此票局部 UI 行为不依赖这类发布级验收。已完成代码复核，可关闭 #114。
