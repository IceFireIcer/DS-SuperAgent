## Standards

产品入口沿用现有 Main 工作卡、受信产品 Host 和 command 鉴权；设备恢复仍使用 `Engine.reconcileStop` 与原远端作业身份。未修改 DSH、设备协议或独立前端。新增英文文案与中文翻译同步，`client.js` 由源码生成。桌面远程客户端与服务端命令白名单同步，read-only 客户端仍无法调用。`remote-command` 的过期测试只更新为当前两阶段作业 API，不改变运行时代码。

## Spec

工作卡可在设备停止确认待定时明确发起原工作对账，且猜测其他工作项被拒绝。已验证的离线和重启恢复核心测试能把设备未知与已确认静止分开。尚未完成同一产品工作卡上的断连、跨进程回连、unknown 依赖隔离及旧代回调审计的整体验收；#122 保持开放，不能因为按钮或 mock UI 测试而关闭。

## 2026-11-17 收口复核

复核发现 Host 替换后的持久形态 `state=stopped + pendingDeviceConfirmation=true` 会让工作卡使用错误的 Stopped 文案。先以产品工作卡测试固定该形态并得到红灯，再修正为 pending-device-confirmation 优先。修复后同一测试同时验证 Check device stop 入口仍存在。

新增的产品 Host 集成测试不再只测 mock 卡片：实际 RemoteDevice 后台进程经断连代理、`work-stop`、Host 关闭/重建、离线 reconcile 保持 pending、回连后按原 job ID 取消并确认，随后从产品入口显式 resume。pending 期间独立 local-only 工作继续到 `waiting`，设备确认前 resume 被拒，确认后 canResume 打开且 outcome 未从 stop 变成 success。该 Host 重建仍是同一 Node 进程内的产品对象替换，不冒充操作系统进程边界。结合既有 daemon restart、Host replacement、unknown scope 与 stop/resume 测试，覆盖本票四项代码验收。

第二轮 Spec 复核发现两个身份窗口：stop reconcile 未核对 Job 的原 device ID/incarnation；迟到 remote start 尚无专项证据。前者现在在访问替代设备前 fail closed，后者以 delayed remote start 测试证明 late answer 保持 unknown/pendingDeviceConfirmation 且不生成 report。产品 Host 测试同时改到最早注册 cleanup，断连代理提成共享 fixture，并把同一进程 Host 对象替换与真实跨进程边界分开表述。

最终定向结果为产品执行 2/2、remote-stop 1/1、远端恢复 4/4、stop/resume 6/6、DS Bot 4/4；Standards 与 Spec 均无剩余阻断。真实第二设备/TLS/SSH 组合和全量 CI 仍由环境票与发布验收负责。
