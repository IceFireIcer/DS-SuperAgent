## Standards

- 配置沿用公开 DSH LLM/settings/credentials 服务；密钥写入受控 credentials 服务，响应只返回 configured 状态，fake credentials 测试确认响应和错误都不含测试秘密。
- `client.js` 由 `ds-bot/src/client/` 生成；设置页复用现有 dialog、card、row、select 和文本输入，没有新增 renderer 或 Session 写旁路。
- Router batch、单独 Router、Worker turn 和子代理使用各自请求起点的 immutable profile/model 快照；Assignment 与 Router turn 持久记录实际 revision。修改配置只影响后续请求。
- Role config 有正 revision、history、command fingerprint 和写事务 CAS；无效 effort、未知占位符、缺失必需占位符、保留技能名和超限内容均在持久化前拒绝。
- UI 在正常保存期间禁用编辑；冲突保留完整草稿，只把实际改动字段重接到最新 revision，不覆盖服务器上的较新字段。
- `updateRoleConfig` 现在先查稳定 command receipt，再对首次执行做外部 provider/model 复核和 revision CAS。相同 command ID 的响应丢失后，即使 provider 暂时不可枚举也返回原 revision view；未提交的失败尝试仍可在 provider 恢复后以同一 command ID 重新执行。此前命令重试幂等阻断项已关闭。

## Spec

- 三个角色的 route 可相同或不同；effort 来自公开模型信息，指令按角色提供。设置保存不创建 Ticket、WorkBrief 或 Assignment，`ui-host` 回归确认保存后 Main history 的 works 仍为空。
- Main 在途回合保留启动时 profile；Router、Worker 和子代理使用同一请求起点快照。配置 revision 会进入 Assignment、Router turn、工作卡和观察详情。
- Router 单次和 batch、Worker turn 与子代理都在调用模型的持久边界通过 `onBeforeModel`/`recordUse` 写入实际 revision。失败的 Router/Worker attempt 也可查询；子代理记录自己的 configuration revision 和 Session。此前“只记录成功请求”的阻断项已关闭。
- revision 冲突保留草稿；保存期间的竞态编辑按本地实际改动重接。无效模板和 effort 被服务端拒绝，authoring actor 限制有独立拒绝测试。
- Recent use 索引只保留 100 条有序元数据，超过 1000 条追加历史后仍可读取有界尾页；不再扫描全历史。
- 产品 `settings-save` 在进入 Engine 前要求 Main、Router、Worker 三份 profile 同时存在；Engine 仍保留无 Main 的 source-only 内部用法，但产品 API 不再接受缺 Main 的保存。此前 Main optional 阻断项已关闭。
