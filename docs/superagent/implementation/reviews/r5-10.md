# R5-10 双轴审查

- 工单：[#102](https://github.com/IceFireIcer/DS-SuperAgent/issues/102)。
- 基线：集成树 `152095b63430af0c51093d227082c1a828d82c33`；本票增量来自 `439f67f` 和 `152095b`。
- 范围：Main/Router/Worker 的路线、thinking effort、指令、revision CAS、provider 目录与密钥、在途快照、配置使用历史和现有设置 UI。

## Standards

- 配置沿用公开 DSH LLM/settings/credentials 服务；密钥写入受控 credentials 服务，响应只返回 configured 状态，fake credentials 测试确认响应和错误都不含测试秘密。
- `client.js` 由 `ds-bot/src/client/` 生成；设置页复用现有 dialog、card、row、select 和文本输入，没有新增 renderer 或 Session 写旁路。
- Router batch、单独 Router、Worker turn 和子代理使用各自请求起点的 immutable profile/model 快照；Assignment 与 Router turn 持久记录实际 revision。修改配置只影响后续请求。
- Role config 有正 revision、history、command fingerprint 和写事务 CAS；无效 effort、未知占位符、缺失必需占位符、保留技能名和超限内容均在持久化前拒绝。
- UI 在正常保存期间禁用编辑；冲突保留完整草稿，只把实际改动字段重接到最新 revision，不覆盖服务器上的较新字段。
- 阻塞项 1：`updateRoleConfig` 在检查 command receipt 之前先执行外部 provider/model 复核。相同 command ID 的响应丢失后，如果 provider 暂时不可枚举或模型暂时不可解析，重试会在读取既有回执前失败，已成功保存的 command 因而不再幂等。应先按 command identity 返回不可变回执，再对首次执行做外部复核和 revision CAS。

## Spec

- 三个角色的 route 可相同或不同；effort 来自公开模型信息，指令按角色提供。设置保存不创建 Ticket、WorkBrief 或 Assignment，`ui-host` 回归确认保存后 Main history 的 works 仍为空。
- Main 在途回合保留启动时 profile；Router、Worker 和子代理使用同一请求起点快照。配置 revision 会进入 Assignment、Router turn、工作卡和观察详情。
- revision 冲突保留草稿；保存期间的竞态编辑按本地实际改动重接。无效模板和 effort 被服务端拒绝，authoring actor 限制有独立拒绝测试。
- Recent use 索引只保留 100 条有序元数据，超过 1000 条追加历史后仍可读取有界尾页；不再扫描全历史。
- 阻塞项 2：设计规格要求每次模型请求都能查询所用配置版本，但 Router/Worker 的 `RoleConfigUse` 在模型运行成功返回后才写入，子代理模型调用没有独立的 use 记录。失败的 Router/Worker 请求和被调用的子代理因此不能通过配置使用查询解释其 revision，只有成功请求与部分持久 turn/Assignment 元数据可见。
- 阻塞项 3：产品 `settings-save` 接受 `RoleConfig.main` 缺失。底层 source engine 允许没有 Main 以便无 Session 的配置调用，但 R5-10 的产品契约要求 Main/Router/Worker 三个 profile；当前 API 可通过漏掉 `main` 保存一份让产品 UI 不再显示 Main 的配置。产品设置边界应明确要求 Main profile。

## Verification

- 现有定向证据：Super-agent 相关组 24/24、16/16、Main delegation 5/5；DS Bot 25/25；provider HTTP 的 fake secret 泄漏检查通过。
- 配置测试覆盖 revision/replay/持久化、异步复核后拒绝旧保存、超过 1000 条 recent-use 有界读取、成功模型请求的 route/instructions 和 use 记录。
- Super-agent typecheck、build、lint，DS Bot 客户端生成检查、定向 lint 和 UI boundary 均有通过记录。未运行全量 suite 或 CI。
- 没有真实 provider 密钥、真实模型、浏览器视觉回归或桌面升级/回滚证据；这些不能由 fake service 测试替代。

本轮未重跑测试，只复核了现有实现记录、测试断言和定向证据。剩余阻断项：3，分别为命令重试幂等性、完整配置使用审计和产品 Main profile 必填。
