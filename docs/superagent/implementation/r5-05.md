## 交付行为

现有侧栏现在从持久 WorkBrief、work item、Ticket、代次、Assignment 和 report 事实自动发现 Router 与 Worker。列表不依赖当前页面或路由，也不借旧 dispatcher 创建 Bots；新条目由新核心事实派生。用户可按 Main、Router 或 Worker 名称及持久事实搜索，并用稳定游标分页。轮询只合并新第一页，不会丢掉已加载的后续页；插入新工作时保持当前观察、选择和输入焦点。

Engine 新增 `getWorkObservations()`、`readWorkObservation()` 和 `readWorkObservationDetail()`。公开产品协议对应 `observe-list`、`observe-read` 和 `observe-detail`，都只接受当前 Instance，且在每次读取时重新校验逻辑 Main、WorkBrief、work item、Ticket、Assignment 代次和当前来源授权。猜测 observation、generation、Session 或 detail 身份不会返回其他对象。

Worker 观察严格绑定 Assignment 代次。历史代次可以读取自己精确的 Session 序列范围，不会被标成当前，也不会继承后一代的成功结果。Router 的每次 route/update 尝试都有持久 pending 记录，完成后记录精确开始/结束序列、step 数和 8-step 预算；失败尝试保留 `STEP_BUDGET` 等错误代码，所以成功、失败和重启后的待定事实都可查。

Session 投影先按 Router turn 或 Worker Assignment 的精确序列/时间范围裁剪，再去除 runtime context，只展示消息、工具调用、工具结果和 turn 结束等有界事实。工具参数只暴露键名；Bearer、token、secret、password 类正文会再次脱敏。工具结果与 report result/evidence/tool facts 的首屏仍是摘要，但超过预算时返回稳定 detail 引用。`observe-detail` 以 8192 字符页读取同一已授权事实，响应有字节数和 next offset，不会让一次读取携带无界 Session 内容。

`historyStatus` 明确区分 `available`、`not-started` 和 `missing`。Session 文件缺失时 UI 显示“历史缺失”，持久工作事实继续可看；有效的空 Session、尚未开始的 Session 和消失的 Session 不再显示成同一种空历史。

观察区没有 composer、steer、审批、重试、工具重放或 fork-and-prompt。返回 Main 保留未发送草稿并恢复输入焦点。产品 Host 禁用原生 `session-reference`、`ui-reference`、Session REST/export 和 Session stream；`/api/session/*` 与 `/api/session.export` 在进入原生 surface 前被拒绝。观察请求带写字段直接返回 `INVALID_INPUT`。

## 边界

本票提供现有产品侧栏中的只读观察，不提供任何工作控制或原生 Session 导航。完整 R5 四目标组合、真实模型语义质量、安装包和最终发布仍由汇总验收负责。动态恢复要求 Session 文件已经持久写入；文件缺失会明确标为 `missing`，不会从进程内快照伪造历史。
