## 交付行为

Main 新增类型化 `follow_up_work`，必须携带确切 `workItemId` 和方向正文。工具不接受“当前页面”“最近工作”或“选中的 Worker”；缺少目标、目标不在当前 Main、工作项尚未接单或引用不属于原来源时都拒绝，Main 必须先向用户澄清。Main Session 生成方向后，WorkDelegation 校验当前逻辑 Main、该 Main 的精确用户消息、工作项、WorkBrief、Ticket 和当前 Session，再持久记录 `WorkFollowUp`。

`WorkFollowUp` 保存 Main、当前 Main Session、原始用户消息、WorkBrief、work item、原来源事件、Ticket、方向正文、原因、方向版本和稳定 command 指纹。相同 command 的完全重试返回同一记录和 Input；同 command 改文返回 `IDENTITY_CONFLICT`。其路由决定持久为 `direct-to-original`：目标明确且工作已接单时直达原 Ticket，不按相似度或页面状态重新猜目标。

方向进入原 Ticket 的新 WorkInput，递增 Ticket 方向版本并触发原 Assignment/Session 的 relay。WorkInput 与 provenance ownership 在同一事务提交，`basis` 为 `main-follow-up`。打开的 Ticket 直接接续；自然结束的 Ticket先写入原 Mandate/Decision 的 `AUTHORIZED_HUMAN_FOLLOWUP` 恢复决定再重开；不创建新 WorkBrief、work item、Ticket、Assignment 代次或 Worker Session。Main Session 换代后仍使用同一逻辑 Main，并把新 Session 记在该 FollowUp 的来源上。

交付和采用分开查询：`delivery.claimedAt` 只表示发送前 claim，持久字段只表示 Session 已确认写入历史，`adopted` 只在 Worker 以 ready、Attention 或 handback 完成承接时为真。卡片同时显示“输入已持久写入”和“Worker 已采用方向”，不会把已写入历史冒充已经采用。最近十条 FollowUp 返回 `queued`、`delivering`、`persisted`、`ready`、`waiting`、`handed-back`、`stopped` 或 `expired`，并保留交付时间、ownership 和原因。

停止与 waiting-human 是持久约束。普通 Main 跟进仍记录为可见的 stopped/waiting 事实，但不创建 Input、不递增方向版本、不启动 Worker。worker 使用既有 `handback_input` 时，ownership 和 Input outcome 保持 handback，Main 工作卡与有界 Router 更新显示交回原因；系统不会自动新建第三项工作。多 owner、context-only、全部交回后人工 requeue 等来源域规则继续走既有 T07 路径。

## 验证

- 公开 Main/Engine 场景：一次请求建立 A/B 两项，随后只跟进 A。A 使用原 Ticket、Assignment Session 和方向版本，B 的 Input、方向版本与 Session 不变，Ticket 总数仍为 2。
- 稳定命令：同一 Main 工具重试复用同一 FollowUp/Input；同 command 改文被拒绝。
- 结束恢复：已自然结束的 A 使用原 Mandate/Decision 写一条恢复决定，保持原来源并继续原 Session。
- 采用事实：FollowUp 的持久投入和 completed adoption 分别可查；ready 后二者同时为真，方向版本和原来源/Ticket 引用保持稳定。
- 交回与等待：Worker handback 后 Main 收到有界更新且没有第三项工作；waiting-human 与 stopped 下的跟进只形成可见 blocked 事实，Input 数量和 Worker turn 均不增加。
- 精确目标：不存在的 work item 不产生 FollowUp，也不改 A/B 或新建 Ticket；服务端没有“当前页面”兜底。
- PostgreSQL：分项完成后在 PostgreSQL 上跟进 alpha，重启后 FollowUp、方向版本、Ticket 和原 Worker Session 保持一致。
- 全量回归：Super-agent 558 项中 556 通过、2 项按平台跳过、0 失败；包含 SQLite、真实进程恢复与 PostgreSQL 合约。
- DS Bot 回归：1444 项中 1442 通过、2 项按平台跳过、0 失败。
- App 回归：252 项中 251 通过、1 项按平台跳过、0 失败，包含真实 `ds-superagent` profile 的 Main 与本地 Worker。

- 真实 Edge + DSH Web：alpha 卡显示 `方向 v2 / 方向变更已完成`、输入已持久写入和 Worker 已采用方向，beta 没有跟进行；刷新后事实仍在。跨 scope、规范化原生写入、实际 WebSocket Session 流、旧 `/api/bot` 和旧 roster 仍被拒绝，390px 深色/减少动态效果无横向溢出或页面异常。

## 边界

本票完成 Main 中明确目标的跟进、同工作续接、停止/waiting/ended 约束、handback 展示和持久查询。Main Session 自动换代、显式工作控制（R5-06）、跨来源自动分流（R5-13）、全量工作历史侧栏（R5-05）及真实模型语义质量分别由后续票验收。

本票没有把越界 handback 自动变成新工作；用户需要在 Main 中确认新的独立目标。这样保留原工作范围，并避免由 Worker 或页面状态静默扩大权限。
