## 已实现的接口

`superagent/src/role-presets.ts` 不读取路径、不启动旧 roster/dispatcher，也不引用旧聊天、Session、工作队列或权限服务。调用方必须自行提供从 `bot/state.json` 明确取得的**副本对象**，并选择一个旧 Bot 和目标角色。没有旧副本时，`createRolePreset(input)` 仍能创建新预设数据。

- `createRolePreset(input)` 仅接受 `id/name/model/instructions/skills/appearance`；模型、指令和技能复用现有 `validateRoleConfig` 约束。形象只接受有界 shape/color 或至多 120,000 字节的 PNG/JPEG/GIF/WebP 内嵌 data URL（旧产品允许约 160,000 字符）；不解析文件路径或远程 URL。
- `previewLegacyRolePreset({sourceIdentity, sourceBotId, state, targetRole})` 从副本的 `bots[sourceBotId]` 读取名称、`provider/model` 路由、effort、指令、技能、颜色和 avatar，返回来源与目标、字段映射、可编辑草稿、问题和被忽略字段。缺少或不合法的模型/技能/形象需在审阅中修正；管理员与资源字段从未映射。来源摘要只覆盖被考虑的旧配置字段，旧 Main Bot/管理员/权限变更不改变摘要。
- `prepareLegacyPresetDecision({..., expectedDigest, decision, preset?})` 重读所提供的副本；摘要变化以 `PRESET_SOURCE_CONFLICT` 拒绝。明确选择返回严格校验后的预设和稳定指纹；明确跳过返回无预设的 `skipped` 决策。相同输入得到相同 key/digest/fingerprint，不向旧数据回写。
- `prepareRolePresetApplication({commandId, current, targetRole, preset})` 生成 `{commandId, expectedRevision, roles}`，供受信调用方交给 `Engine.updateRoleConfig`。只替换指定角色的 name/model/instructions/skills；形象仍属于预设展示数据，不进入角色权限。Engine 的原有身份、命令去重、revision CAS、异步模型复核及在途回合快照仍是实际保存边界。

## 原阶段的待接入持久化契约

预览 `key` 是 `['legacy-preset', sourceIdentity, sourceBotId, targetRole]` 的 JSON 字符串，摘要是所选旧字段的 SHA-256，决策指纹覆盖 key、摘要、选择/跳过和所选预设。后续事务存储需在同一 Instance 内记录命令 ID 和指纹：相同命令与相同指纹返回原收据；相同命令不同内容拒绝；同一来源目标已选且内容不同必须进入明确冲突处理，不覆盖预设。跳过记录为可查询的决定，但不占用所选预设的唯一来源键；用户之后可发起新的审阅选择。存储后查询要提供来源、目标、选择/跳过、冲突及应用形成的角色 revision。SQLite 与 PostgreSQL 应使用同一记录种类和事务语义，不能仅实现其中一端。

原阶段**没有**新增存储记录种类、事务命令或预设查询，也没有修改共享注册文件；上述当时是后续集成契约。较大的头像与指令合并会超出既有单条记录预算，需要把图片分开存储，不直接存入角色配置记录。原模块尚未接入 `superagent/src/index.ts`/构建入口，测试在进程内用 esbuild 编译独立模块；将其作为产品导出需后续接入。Host 需要从明确的旧资料副本发起预览和受信选择、重新检查来源摘要、校验 actor/provider，并把预设应用命令传给 Engine。现有设置/形象组件、选择/取消及冲突 UI、来源与目标预览、角色 revision 关联和在途行为的端到端证据均待完成。预设不创建长期 Bot 或额外 Main；旧 Main/flags/管理员信息不形成权限。

## 持久库增量（基于 dev `12732e8`）

独立短期分支 `feat/117-role-preset-store-20261116` 增加 `RolePresetStore`，接受受信 Host 提供的 Instance 和明确的旧配置副本。`create/update/delete/get/list` 提供按 Instance 隔离的手工预设，修改使用预设 revision CAS；删除留存可查询的 tombstone。原命令重放返回原 revision 的结果，命令 ID 换内容以 `IDENTITY_CONFLICT` 拒绝。预设仍不生成 Bot/Main，不携带权限、资源授权或旧聊天历史。

`recordPreview/getPreview/listPreviews` 保存白名单预览，只有来源身份、所选旧字段摘要、字段映射、草稿、忽略字段名和审阅问题进入业务库；不存旧状态对象、旧聊天、管理员值或私有目录。`decideImport` 的 `skip` 不需要重新读取旧副本，代表取消并留存决定；`select` 必须重新提供副本，源摘要或目标不符产生可查的 `PRESET_SOURCE_CONFLICT`。同一来源目标与相同选择内容形成可查的 duplicate，不重复创建；不同内容、同一预览上的不同决定、已选预设被编辑/删除或已有预设 ID 形成可查的 conflict，不隐式覆盖。冲突保持未导入状态；本层尚无替换来源绑定的受信解决命令，手工编辑预设也不会清除旧来源绑定。

上述操作均在同一 Instance 事务内保存命令收据、不可变预设版本或预览、选择/跳过/重复/冲突记录与来源索引。图片按 60,000 字符拆入独立 `role-preset-image` 记录，支持原模块允许的 120,000 字节 PNG 等嵌入图片，不超过单条 128 KiB 记录限制。新增的 record kind 同时由 SQLite 和 PostgreSQL 的通用事务存储识别，不引入单库私有 schema。

**集成仍缺**：该 store 未进入共享 `index.ts` 构建/产品入口；未接 Host 身份授权、现有 UI 的设置/形象组件、受信导入副本读取、提供方复核或应用命令。应用预设到角色配置的 revision 仍由既有 `prepareRolePresetApplication` 与 `Engine.updateRoleConfig` 分开完成；本库不记录应用形成的角色 revision，不能声称 #117 端到端验收。查询由将来的受信 Host 负责鉴权，不能直接暴露给 Agent。没有旧副本时手工 CRUD 独立可用。

Node 24.22.1 定向运行 `npm test -- test/role-preset-store.test.mjs test/role-presets.test.mjs test/config.test.mjs`：19 通过、1 项 PostgreSQL fixture 因 Windows 平台限制跳过；`npm run typecheck` 与 `npm run lint` 通过。SQLite 测试覆盖跨连接并发、重启读取、命令重放、冲突/取消/重复、预设编辑后的再提取及上限图片；PostgreSQL 测试代码使用同一接口，但本机未执行真实 PostgreSQL。未跑全量 CI、真实模型或 UI 验收。

## 设置组件增量（基于 dev `b96fa70`）

短期分支 `feat/117-role-presets` 新增 `ds-bot/src/client/product-presets.js`：导出 `ProductPresetSettings({ binding, call, settingsRevision, onApplied })` 和 `PRODUCT_PRESET_CSS`。接入方须传现有、已鉴权的 `productCall`、当前 `settings` 回执的 `revision`，将组件挂在现有设置页并将 CSS 加入现有样式装配。`onApplied` 收到成功回执后可刷新父设置快照；未提供当前 revision 时应用按钮不可用。组件复用 `Card`、`Row`、`CharacterGrid`、`BotMark` 和 `avatarImage`，在设置页内展示预设列表和来源/目标审阅；不会创建 Bot 或长期 Main。

| 命令 | 请求（`instanceId` 始终必填） | 成功回执和界面行为 |
| --- | --- | --- |
| `preset-list` | `{instanceId, limit:50, after?}` | `{items: RolePresetEntry[], cursor?}`；失败保留错误和重试入口，列表不可用时禁止写操作。 |
| `preset-create` | `{instanceId, commandId, preset}` | `RolePresetEntry`，需 active 且有正整数 preset revision；失败保留草稿及同一输入的命令 ID。 |
| `preset-preview` | `{instanceId, commandId, copy}` | `RolePresetPreviewRecord`，包含 `id`、`preview.source`、`targetRole`、`draft`、`fields`、`ignored`、`issues`；来源/目标不符拒绝展示。`copy` 来自用户粘贴的明确副本，页面仅向 Host 传所选 Bot 的 name/model/effort/instructions/skills/color/avatar.shape/avatar.image，不传其他 Bot、旧权限、历史或任意 avatar 扩展字段。 |
| `preset-select` | `{instanceId, commandId, previewId, decision:'select', copy, preset}` 或 `{instanceId, commandId, previewId, decision:'skip'}` | `RolePresetImportRecord` 的 `selected/skipped/duplicate/conflict`：只有 `selected`（携带 `presetId`）才显示新预设；`skipped` 记为明确取消；`duplicate` 显示已记录；`conflict` 保留审阅内容并显示原因。选择使用与预览相同的显式副本，受信 Host 应按源摘要重验。 |
| `preset-apply` | `{instanceId, commandId, presetId, targetRole, expectedRevision}` | 至少返回新角色配置 `{revision}`，revision 必须比请求的大；Host 必须检查 actor、预设与当前 revision，通过 Engine 配置保存命令执行 CAS，并返回可查的预设/目标角色/revision 关联。冲突时组件要求刷新设置 revision 后才可再应用。 |

页面对重试保留原命令 ID；对返回缺失或格式异常的回执显示失败，不把调用成功等同于事实已保存。重复提取默认使用 `legacy-<targetRole>-<sourceDigest前20位>` 作为可编辑预设 ID，允许服务端识别同源同内容重放。预览只使用提供的副本，不打开旧产品目录或读取旧聊天；被忽略字段只显示字段名。形象保存在预设中，不写入角色权限或运行中的回合。

## 产品接线增量（合并本地 dev `eac18a4` 后）

`Engine` 公开 `createRolePreset/getRolePreset/listRolePresets`、`previewRolePreset/getRolePresetPreview`、`selectRolePreset/getRolePresetImport/listRolePresetImports`、`applyRolePreset/getRolePresetApplication/listRolePresetApplications`。查询检查 Instance 和 actor 的读取范围；修改还检查 `authoringActorIds`。新建、预览和选择的命令身份按来源与 actor 隔离。Store 保留此前的来源摘要、单预览决定和同源重复/冲突事务语义。

## 同源冲突显式替换增量

同一来源/目标的第二次审阅若得到不同内容，首次选择仍只记录 `PRESET_CONTENT_CONFLICT`。现有设置页此时可明确选择“替换此来源绑定”：请求附上当前冲突回执中的原决定 ID，受信 Host 在同一 Instance 事务内重新检查来源摘要、旧绑定决定、目标预设 ID 和当前绑定，再创建**新的**预设并把来源索引指向新决定；原预设、应用记录和旧导入记录保留可查，不覆盖其内容或扩权。若另一操作已改变来源绑定，旧决定 ID 产生可查冲突而不会覆盖。相同命令重放仍返回原回执。Store 与 Host 定向覆盖旧预设保留、重启后新绑定、重复和旧决定拒绝；现有设置组件 DOM 覆盖必须先看见冲突再明确点击替换。该能力不读取旧资料原件或启用旧 Bot 运行机制。

本增量仍未补齐 PostgreSQL 专项、真实桌面视觉/键盘、预设应用中在途模型回合的端到端证据；#117 保持 OPEN，不把隔离测试称为真实产品验收。
