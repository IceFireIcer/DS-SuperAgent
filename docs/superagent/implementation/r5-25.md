## 已实现的接口

`superagent/src/role-presets.ts` 不读取路径、不启动旧 roster/dispatcher，也不引用旧聊天、Session、工作队列或权限服务。调用方必须自行提供从 `bot/state.json` 明确取得的**副本对象**，并选择一个旧 Bot 和目标角色。没有旧副本时，`createRolePreset(input)` 仍能创建新预设数据。

- `createRolePreset(input)` 仅接受 `id/name/model/instructions/skills/appearance`；模型、指令和技能复用现有 `validateRoleConfig` 约束。形象只接受有界 shape/color 或至多 120,000 字节的 PNG/JPEG/GIF/WebP 内嵌 data URL（旧产品允许约 160,000 字符）；不解析文件路径或远程 URL。
- `previewLegacyRolePreset({sourceIdentity, sourceBotId, state, targetRole})` 从副本的 `bots[sourceBotId]` 读取名称、`provider/model` 路由、effort、指令、技能、颜色和 avatar，返回来源与目标、字段映射、可编辑草稿、问题和被忽略字段。缺少或不合法的模型/技能/形象需在审阅中修正；管理员与资源字段从未映射。来源摘要只覆盖被考虑的旧配置字段，旧 Main Bot/管理员/权限变更不改变摘要。
- `prepareLegacyPresetDecision({..., expectedDigest, decision, preset?})` 重读所提供的副本；摘要变化以 `PRESET_SOURCE_CONFLICT` 拒绝。明确选择返回严格校验后的预设和稳定指纹；明确跳过返回无预设的 `skipped` 决策。相同输入得到相同 key/digest/fingerprint，不向旧数据回写。
- `prepareRolePresetApplication({commandId, current, targetRole, preset})` 生成 `{commandId, expectedRevision, roles}`，供受信调用方交给 `Engine.updateRoleConfig`。只替换指定角色的 name/model/instructions/skills；形象仍属于预设展示数据，不进入角色权限。Engine 的原有身份、命令去重、revision CAS、异步模型复核及在途回合快照仍是实际保存边界。

## 待接入时的持久化契约

预览 `key` 是 `['legacy-preset', sourceIdentity, sourceBotId, targetRole]` 的 JSON 字符串，摘要是所选旧字段的 SHA-256，决策指纹覆盖 key、摘要、选择/跳过和所选预设。后续事务存储需在同一 Instance 内记录命令 ID 和指纹：相同命令与相同指纹返回原收据；相同命令不同内容拒绝；同一来源目标已选且内容不同必须进入明确冲突处理，不覆盖预设。跳过记录为可查询的决定，但不占用所选预设的唯一来源键；用户之后可发起新的审阅选择。存储后查询要提供来源、目标、选择/跳过、冲突及应用形成的角色 revision。SQLite 与 PostgreSQL 应使用同一记录种类和事务语义，不能仅实现其中一端。

本提交**没有**新增存储记录种类、事务命令或预设查询，也没有修改共享注册文件；上述是后续集成应满足的契约，并非已落地的持久事实。较大的头像与指令合并会超出既有单条记录预算，未来应把图片作为单独受控资源存储，不直接存入角色配置记录。模块尚未接入 `superagent/src/index.ts`/构建入口，测试在进程内用 esbuild 编译此独立模块；将其作为产品导出需后续接入。Host 需要从明确的旧资料副本发起预览和受信选择、重新检查来源摘要、校验 actor/provider，并把预设应用命令传给 Engine。现有设置/形象组件、选择/取消及冲突 UI、来源与目标预览、角色 revision 关联和在途行为的端到端证据均待完成。预设不创建长期 Bot 或额外 Main；旧 Main/flags/管理员信息不形成权限。
