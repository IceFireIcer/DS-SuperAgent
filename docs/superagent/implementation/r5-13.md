## 交付行为

Outbox 继续是唯一外发入口。acknowledgement、answer、attention 和 result 分别在派发前重新核验原请求、当前人类问题及 Worker fact、当前结构化 Attention、当前 ready report/Assignment，并核对精确目的地。Router 与 Worker 只能提交已有的类型化事实；跨受众结果仍要求当前、获授权且已关联的原生事件，永久失败不会自动改投或广播私人内容。

Delivery 查询现在明确区分 `pending`、`sent`、`dropped` 和 `unknown`。平台已接收但响应丢失的 Effect 不再伪装成 `pending`；返回 `reconcileRequired: true`、原因和尝试次数。Engine 新增 `reconcileDelivery({ commandId, ticketId, deliveryId })`，只使用该 Delivery 的原 Effect generation 和 idempotency key 调用信道对账。相同命令重放不会再次发送；临时失败仍按既有有界退避恢复，永久失败仍是 `dropped`。

### Independent review follow-up

GitHub snapshot 映射把 creator 与 change actor 分离：create 使用 creator；edited/closed event 使用 `sender`、`actor`、`closed_by` 或 `merged_by`，缺失时保持 `system`，不会回退成 creator。测试覆盖 collaborator edit、bot close、CI PR close。

最终集成复审补齐 REST snapshot 通常不携带 change actor 的情况：changed event 通过有界 Issue timeline enrichment 匹配 edited、closed、reopened、merged actor；timeline 缺失或超出预算时仍为 `system`。测试覆盖 collaborator edit、reopen、bot/CI close、merged、unknown editor 与 deleted PR fail-closed。

Source Main 失败后保留唯一 source card 身份，并为恢复回合使用稳定的 attempt identity；已持久 user message 但无 reply 时不再只读后永久中止。Reconcile command 改为 running/failed/completed receipt，仅在 sent/dropped 后完成；transient 或 not-applied 使用同一 command 重试，success 后才短路。`not-applied` 的 pending Effect 可通过同一 UI 命令进行原键安全重发。

## 缺失 Delivery 的产品结果保护

历史 Outbox Effect 若指向已经归属 Main WorkBrief 的 Ticket，却缺少不可变 Delivery 记录，不能从 Worker ReadyReport 原文重新构造结果。Outbox 会把该 Effect 标为 dropped；正常持久 Delivery 的 Main 回复仍按原身份交付。Node 24 定向交付、Main、Effect 和飞书链路 37/37 通过。通用直接 `submit` 没有 Main WorkBrief 归属，其原结果入口仍待迁移或移除；此项局部防护不满足 #103 第一条完整验收，继续开放。

后续将缺回执防护扩展到 `product-desktop` 的直接 Ticket：即使没有 `work-ticket` 归属，产品来源的 result 也不能从 Worker 报告补造，首次交付时会因缺少 Main 工作归属被拒绝；非产品 `desktop` 接口仍沿用已有行为。Node 24 定向交付、Main 和产品飞书 Host 共 14/14 通过。直接 `submit` 的 Main 归属及历史通用 Ticket 的完整迁移尚未完成，#103 继续开放。
