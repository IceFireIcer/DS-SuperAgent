## 交付行为

Outbox 继续是唯一外发入口。acknowledgement、answer、attention 和 result 分别在派发前重新核验原请求、当前人类问题及 Worker fact、当前结构化 Attention、当前 ready report/Assignment，并核对精确目的地。Router 与 Worker 只能提交已有的类型化事实；跨受众结果仍要求当前、获授权且已关联的原生事件，永久失败不会自动改投或广播私人内容。

Delivery 查询现在明确区分 `pending`、`sent`、`dropped` 和 `unknown`。平台已接收但响应丢失的 Effect 不再伪装成 `pending`；返回 `reconcileRequired: true`、原因和尝试次数。Engine 新增 `reconcileDelivery({ commandId, ticketId, deliveryId })`，只使用该 Delivery 的原 Effect generation 和 idempotency key 调用信道对账。相同命令重放不会再次发送；临时失败仍按既有有界退避恢复，永久失败仍是 `dropped`。

## Integration follow-up

复审六项 P1 的对应修复：GitHub Issue/PR/review 的 author kind 改为按原生 user type/login 统一推导；unknown Delivery 的 reconcile 与普通发送依据校验分离，只使用不可变 Delivery/Effect generation 和原幂等键，basis 改变或方向换代不会阻断；reconcile attempts 有独立预算，即使首次发送预算已耗尽仍可按原键核查。

`DeliveryTarget` 现在持久 evidence author，并由 `destination.actorId` 精确校验；不同 actor 的关联不能借用原目标。ProductHost 新增 `reconcile-delivery`，现有 Main source UI 为 unknown delivery 提供稳定 command ID 的只读对账按钮和刷新。Source receipt 查询改为 bounded cursor 分页，显示 exact source/event/thread/actor，并可按页读取更早回执。
