## 交付行为

启用 `GitHubSourceConfig.mainIntake` 后，新的授权人类事件使用 source-local Main 路径。已有 Worker Thread 才进入原 Ticket fan-out；其他 addressed human 请求在同一来源事务内保存 `MainSourceHandoff`，不执行 Eval、不创建 Ticket。Source event、handoff 和 notice 原子提交，cursor 只在成功后推进；重放、重建 source 或 Main 委派前重启都只保留一个 handoff。Context-only subscription 不吞掉新请求；CI 和机器人事件不会唤醒 Main 或冒充 human authority。

Main 以来源卡和 user message 显示获授权正文、GitHub object、actor 与 Instance-qualified reference。`delegate_work` 必须绑定该 handoff；WorkBrief 存原 source event，Ticket 保留执行世界，同时把默认 acknowledgement/result/attention 目的地绑定原 Issue/PR/author。后续合法 human 跟进沿用原 Ticket、owner、direction 和 source subscription。等待人工原 owner 可回答，Worker 输出仍只形成结构化事实。

Main history/source query 返回 `pending`、`presented`、`delegated` 状态、Main 失败依据、语言无关 source reference、Work/Ticket 身份、最近 delivery receipt，以及 PR 条件。现有产品 Main 侧栏显示来源正文、reference、投递 `pending/sent/dropped/unknown` 和 PR open/draft/merged/closed。跨受众结果仍走既有 association + current evidence 校验，没有新增外发旁路。

## 边界

本票复用现有 GitHub parser、来源身份/版本、关系、subscription、Outbox 和候选失败模块，没有建立第二套 parser。真实 GitHub actor/network 运行、真实模型语义质量和完整桌面组合仍由对应环境验收负责。若 Main 判断请求不可执行，它只在 Main 中记录原因；没有 Ticket 时不向外部信道伪造答复。

## Integration follow-up

GitHub parser 的 Issue、PR、review 与 PR deletion 现在从原生 `user.type`/login 一致推导 `human`、`bot` 或 `ci`，机器人创建对象不会冒充人类授权。

Pending Main handoff 在 Effect 执行事务内重新读取当前 source projection、actor identity 和当前 requester allowlist；编辑后的旧 handoff 与删除事件原子标记为 `discarded`，不会被 Main 处理。批量 handoff 不再落入 Router notice handler。定向测试覆盖 created→edited、created→delete、重启重放和单 Ticket 结果。

Source receipt 投影不再固定隐藏 10 条之后的历史；Engine/ProductHost 提供 source-scoped bounded cursor，现有 UI 显示 exact source/event/thread/actor，并支持“加载更早回执”。Unknown delivery 使用 ProductHost `reconcile-delivery` 和稳定命令身份执行只读对账。

第二次独立复审后，Issue/PR edited/closed event 只使用原生变更 actor；缺失 actor 时保持 `system`，不再借用 creator 通过 allowlist。Source Main model turn 失败时，原 source card 保持不变，并用稳定 recovery turn identity 继续同一请求；已经持久但无 reply 的 turn 不再被误判为完成。

### Final integration follow-up

Source Main 遇到 `max-tokens` 时，现在通过原生 Session fork seam 在执行前持久化 `main-source-rollover`：原子更新 `main-state` 的 child Session/generation、当前 handoff 的 recoverable command、前后 Session 与 turn identity。旧的 source card 和 user message 保持唯一；受限 Effect 在新 generation 上使用新的确定性 recovery turn 重试，child Session 缺失时仍可由自包含的 source recovery prompt 恢复。

Issue/PR 列表没有 native change actor 时，GitHub transport 只对 changed snapshot 读取最多三页 Issue timeline，并用当前 `updated_at`/state 匹配 edited、closed、reopened 或 merged actor；全局最多六十次 actor-enrichment 请求。匹配不到 actor 时保持 `system`，不会回退到 creator；bot、CI 与 human 继续按原生 user type/login 分类。PR merged 现在映射为 `merged` action。

Final follow-up 定向验证：Source rollover、Main GitHub intake、GitHub API 与 Delivery **22/22**，Main conversation **4/4**；Super-agent typecheck、build、lint 通过。
