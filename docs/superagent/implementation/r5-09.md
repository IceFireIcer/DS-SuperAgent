## 交付行为

Main 的 DSH 原生 Session 在 `max-tokens` 时通过公开 Agent/Session API 生成 forked child，并先 flush child seed，再在业务库事务中推进 `generation` 与 `mainSessionId`。逻辑 `mainId` 不变；旧 Session 文件继续可读，新 Session 继承 DSH fork seed。已写入业务历史的消息不删除，主对话追加一条明确的 system rollover fact。

`main-session-rollover` 保存前一/当前 Session、generation、工作索引、每个工作的目标/约束/验收/状态/证据引用，以及换代期间仍为 queued/running 的未读输入。工作索引来自当前 Main 的持久 WorkBrief、item、receipt、outcome 和 Ticket，不重新调用模型。人工 stop、waiting-human、blocked/failed/unknown 等工作状态仍由原 Ticket/Attention/Outcome 事实表示，换代不改写这些对象；交接记录保留其投影和引用。

Main 新增 `read_work_evidence` 工具，Engine 新增 `readMainEvidence()`，产品 API 新增 `evidence`。查询必须给出当前 Main 已接受的 `workItemId` 和已知证据引用；服务端按当前 Ticket 来源与归属重新解析，不能提交 Ticket ID 覆盖目标。ContextReader 继续提供 256–16384 字节分页、总字节数、返回字节数、`truncated` 与 continuation cursor。现有主对话在工作卡上增加“查看原始请求”，按 4096 字节加载并显式显示部分/完整证据和“加载更多”。

所有 Main 回复发布和 Work update 投影都核验启动时的 Session ID 与 generation。换代后的旧代完成回调、已失败投影补读或迟到 Work notification 只能留下审计/失败结果，不能写入当前 Main 历史或推进当前代。旧 Session 的底层 writer 继续由既有 Session writer epoch/flush 合约隔离。
