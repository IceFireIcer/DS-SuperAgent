## 实现

浏览器资源的 `browser-control` 记录固定资源、workItem、Ticket、Assignment/代次、Environment、责任 Actor 和 `taking/held/returning/returned` 状态。受信本地命令 `browser-take` 在联系桌面 Host 前持久写入 `taking`；Worker 浏览器工具从这一刻起即被阻断。Host 确认后才变为 `held` 并断开现有 Worker CDP socket；待确认操作转为 `unknown`，不将 socket 断开当成页面动作已停止。回执丢失可用持久 control ID 调用 `browser-reconcile-take` 重连 Host 确认，不能自动归还。旧 Instance、旧控制代、未经授权来源与只读远端客户端均不能控制。

现有 Browser resources 设置页可选择已授权工作项并接管。Host 确认后，同一个已隔离 profile 的现有 WebContentsView 进入手动浏览；地址输入仅接受通过既有导航规则的 HTTP(S) URL。人工操作期间 Worker 继续等待。用户可停止对应工作，也可显式归还。归还先持久进入 `returning`，再由 Host 解锁；Host 或 DB 回执不明时保持 Worker 屏障直至原命令重试。归还不更改人工 stop、Attention、Ticket 或未解决浏览器 operation；未确认 operation 必须先按原 operation ID 核查。资源的 profile key 在创建时随机生成，业务投影不暴露该 key；App IPC 按原 control ID 拒绝已归还及旧代 WebContentsView 操作。
