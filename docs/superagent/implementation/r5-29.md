## 已接通的用户行为

现有 Super-agent 设置增加“Execution”页。用户可保存后续新工作的默认 local/remote-only/auto、首选 Environment 与所需 read/write/search/command 能力；设置修订使用预期版本命令。设备页展示本机与已配对远端的状态、权限、设备 ID、目录、附件和技能能力。远端的 endpoint、pairing code、设备 ID 与固定公钥指纹由本地受信设置提交，配对成功后只持久化 Host 的 `RemoteEnvironmentState` 与显示标签，不把 pairing code、私钥或读取凭据返回现有客户端。

Main composer 增加 local-only/remote-only/auto 选择，并显示对应候选 Environment。local-only 保持现有本机目录入口；remote-only 可选已授权远端，没有远端时仍可提交不带附件的工作并形成可恢复的等待 Ticket，不静默回退本机；附件上传仍要求 exact Environment。auto 在 Ticket 启动时使用已有 Execution Policy、能力、容量、version/fingerprint 证据选择，附件在 auto 下明确要求先选 exact target。远程只读客户端可以读取设备/环境选项并提交有命令权限的 Main 输入，但设备配对、撤销和策略修改只允许本地受信设置。

Main 输入把 target 与可选的 exact `environmentId` 持久到 MainCommand，Router 接到 WorkBrief 后保留同一 target；Ticket 与 Assignment 沿用既有固定执行世界。Proactive/CI Ticket 的既有 local-only 路径不变。主对话工作卡显示声明的 target、实际绑定 Environment、设备、目录、版本，以及自动选择的 source、candidate eligibility 和阻塞原因；Worker 只读详情还展示声明的 target/required capabilities、选择来源/状态/原因以及逐候选阻塞原因。Active Assignment 不会因后续全局默认修改而迁移。

## 持久化与安全边界

`product-remote-environment` 保存可恢复远端连接快照，`product-remote-environment-command` 保存配对/撤销命令结果。Host 交换私钥写入 DSH credential records，业务 SQLite/PostgreSQL 只保存不可解析的 credential reference；远端恢复在 credential record 不可用或与快照不匹配时失败关闭。两者使用既有 JSON record，没有新增按数据库分支的列或明文私钥列。配对先持久化 pending intent，再执行网络交换；可判定拒绝会清除 intent，网络结果未知保留 `PAIRING_UNKNOWN`，不会伪装成功。配对成功后的凭据或数据库写入若失败，不返回成功。设置页为一次配对/撤销保留稳定 command ID，错误后重试仍重放同一身份。撤销先持久化 pending intent；设备不可达时 Host 仍删除本地恢复状态并停止使用该连接，同时报告设备确认不可用，本地 credential cleanup 失败则保留可重放清理标记。

RemoteEnvironment 的现有加密协议、设备公钥 pin、actor/Instance/Environment allowlist、目录边界、撤销和 Host restore 均原样复用。文件、搜索、命令、附件、spill、技能与子代理继续由 Assignment 的同一个 ExecutionEnvironment 提供，不把 Host workspace 绝对路径传给设备。远端 Office/browser/MCP 没有对应能力声明时继续拒绝；只有 Host 声明的浏览器/MCP 和本机 Office 才能进入候选计划。
