## 产品入口

现有 Main 工作卡新增 Execution Environment handoff 区域。用户从当前 Assignment 之外选择已授权的本地或远端 Environment，依次执行：

1. `work-handoff-prepare`：固定当前 Ticket/Assignment generation 与目标，读取固定源 Environment 和目标的工作副本，生成有界 manifest。
2. `work-handoff-verify`：用户把 manifest 中的修改、未跟踪、删除和可执行位同步到目标后，重新读取源与目标并核验 commit、patch、文件哈希、路径与额外目标变更。
3. `work-handoff`：重新核验目标能力、路径/版本、工作副本与授权；在安全边界对账源作业、flush 原 Session、再次核验目标/副本，并在单个业务事务中结束旧 Assignment、创建同一 Ticket/Session 的新 Assignment。

同步保持不变更的显式步骤：产品不读取 Host 路径替代远端设备，也不把未经核验的文件写入目标。工作卡列出待同步文件和阻塞原因；冲突保持 `handoff-blocked`。这套流程复用既有 T39/T40/T41 工作副本、交接和恢复实现，没有新增设备协议或第二执行核心。

## 安全与恢复

- `expectedGeneration` 是 prepare、verify 和 request 的必需产品条件。核心在任何副作用前、同一 Instance 写事务内检查它；既有 command 回执优先返回，因此交接成功但响应丢失后，用原 command ID 重放仍返回原交接，不会因 Assignment 已换代误报 stale。
- prepare 时就应用 Ticket 的 local/remote/auto 限制、目标环境身份、能力、在线状态、容量、目录、版本和 fingerprint 选择；最终 request 再执行同一目标选择。工作副本要求在 prepare 与 flush 后都可核验。
- 最终 switch 事务不仅检查 Ticket、Assignment ID/generation 和新增后台工作，还通过当前 Environment 对象重新核验源/目标身份与 actor 授权，防止目标或源在 revalidation 后撤权时仍创建新代。
- stop、waiting-human、unknown relay Effect、ready report、active Worker turn/job/subagent/preview、setup failure 和暂停都先于交接；工作卡不显示可交接权限。显式 resume 只创建源环境新代，不继续旧交接。
- 被中断的 `requested | flushing | switching` 记录在 Host 启动/解除暂停时按原记录和 command 身份恢复；失败或目标离线保持 blocked，不创建新代。第二设备故障演练仍归 T58。
- 旧 Assignment ID/generation、Session writer epoch 和 Host fencing 继续拒绝旧 job、子 Agent、Input 和迟到回调修改当前状态。

## 工作卡投影

Engine 只向产品工作卡投影当前有效的交接状态、责任方、下一步、候选目标、有界 blocker 以及当前工作副本摘要；内部 command fingerprint 不下发。若上一轮 completed 交接已被针对新 Assignment 的副本替代，投影回到新副本的准备/核验状态，因此可从远端再交回本地。

责任方固定为 `worker | operator | human | host`，下一步固定为 prepare、synchronize、verify、handoff、reconcile、continue 或 resolve。阻塞文案按固定 code 在现有 i18n 表中映射；原始内部错误和动态标识不直接作为 UI 文案。

## 定向验证

Node 24 使用临时 SQLite、隔离 DSH Session、真实 loopback `RemoteDevice`、Git 工作区和虚构值：

- 产品执行纵切 **5/5**：本地 `auto` 工作经真实远端 prepare、外部显式同步、verify、handoff 后保持 Ticket/Session；随后从远端交回本地，共保留三个 Assignment 代次，旧代非 current。测试同时覆盖响应丢失后 prepare/verify/request 原 command 重放、stop/waiting 禁止交接、目标能力/身份、工作副本冲突和 pending revoke 在 Host 重启后保持不可用。
- 交接核心与工作副本组合 **35/35**：覆盖本地→远端/远端→本地、活跃范围阻塞、unknown/stop 优先、三种中断状态继续同一记录、目标探测期间代次变化、目标离线、pending revoke fail-closed、远端工作副本 inspect、旧代隔离和有界历史。
- 产品鉴权、凭据资源及网络回归 **21 通过、1 个既有 Windows PostgreSQL fixture 跳过**：只读客户端不能调用交接命令，猜测 workItem/Ticket 被服务端拒绝。
- DS Bot 工作卡/执行设置/worker view/样式与生成资产 **12/12**，App 远程产品客户端 **1/1**；prepare/verify/handoff 按钮载荷、责任方/下一步、目标选择和中英文案有产品入口断言。
- Super-agent typecheck 和 lint、DS Bot lint、`client.js` 生成一致性、UI boundary、实施记录和 `git diff --check` 通过。DS Bot lint 仅报告本票未改文件的既有 warning。
