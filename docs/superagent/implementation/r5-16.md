## 用户可见行为

产品设置原有凭据资源卡可创建资源并为 Worker 的 work item 或 Environment 授予 `tool` 用途。新增 MCP 卡显示受信 Host 声明的服务/工具、Host 本地运行位置、所选资源、审批与连接状态；可保存资源、审批/撤销审批、连接、断开、重试。配置动作只写 Instance 内的配置与命令回执，不创建 Ticket。首次声明的固定工具默认未经批准且断开；保存新选择同样清除审批及连接，需重新批准并具备 Worker/tool 授权。

Engine 的受信配置工厂把配置记录存入与其他业务事实同一 Storage 合约。每个配置命令带稳定 `commandId`、规范化指纹和 revision 条件；跨 Instance、只读/远端客户端、陈旧 Host 租约和不同输入复用同一命令均在服务端拒绝。设置页只在结果不明确时保留原命令 ID 重试，确定性拒绝允许修正。凭据值与 MCP URL 不进入设置投影。

断开、审批撤销、资源撤权/删除及部署声明变化均在实际 Worker 调用前重新读取；现有 MCP 适配器在握手后、发出 `tools/call` 前再次检查 Assignment 与受管资源。调用时检查精确 Worker/work item/Environment grant，Main/Router 和远端 Assignment 不取得此工具。`connect`/`retry` 是有持久回执的本地启用与授权核验，MCP 网络握手发生在真实工作调用时，界面没有宣称网络已连接。已确认调用继续由现有 ReadyReport 记录工具事实。

## 2026-11-17 #108 代码验收补全

本轮新增独立的 `worker-mcp-denial` 持久事实，补齐 #108 第 4 项要求的“未发出请求”失败记录。父 Worker 与子 Worker 使用同一 MCP 派发点；输入校验、连接/审批/授权检查、停止或其他派发前失败发生在 `dispatch.begin` 之前时，只记录 Ticket、Assignment/generation、work item、Environment、server/tool、固定错误码与时间。该记录不生成 `requestId`，不保存输入、凭据、响应或错误原文，也不会把未发出的请求伪装成外部 unknown；真正发出 `tools/call` 后失去确认的请求仍由 `worker-mcp-call` 与原始请求 ID 表示。

调用点的配置检查现在区分三类结果：断开或资源选择变化为 `MCP_NOT_CONNECTED`，审批失效为 `MCP_NOT_APPROVED`，缺少精确 work item/Environment/source grant 或唯一 grant 被撤销为 `GRANT_DENIED`。工作观察最多分页读取 1000 条 denial，并按当前 Assignment 显示 `MCP state: not dispatched · server/tool · code ...`；重启后仍可读。若 denial 写入自身失败，工具事实会标记 `evidence: not-recorded`，调用错误明确要求先检查 Host 存储，不会静默声称事实已持久化，也不会伪造外部请求。Main/Router 不取得 MCP 工具，全局同名工具未被调用。

定向验证使用 Node 24.22.3：`superagent` build、typecheck、lint 通过；`product-mcp-configuration.test.mjs` 1/1、`worker-mcp-credential.test.mjs` 1/1、`worker-mcp-unknown.test.mjs` 3/3、`work-observations.test.mjs` 1/1。覆盖无 grant 与撤权不发握手、停止在握手后派发前记录 `TICKET_BLOCKED`、唯一 grant 撤销记录 `GRANT_DENIED`、重启后工作卡可读、无秘密和虚假请求 ID 泄漏、unknown 重启阻断及 denial 写入失败可见。双轴复核见[审查记录](reviews/r5-16.md)，最终无剩余代码阻断项。未跑全量 CI；提交后的选择性 CI 证据记录在关闭 issue 时。
