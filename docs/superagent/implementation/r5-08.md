# R5-08：Main 故障时继续工作并可靠补读

- 工单：[R5-08 / #100](https://github.com/IceFireIcer/DS-SuperAgent/issues/100)。
- 日期：2026-11-15；本阶段实现位于 `dev`，未发布。

## 当前交付范围

Main 用户输入继续使用稳定的 `main-command` 身份持久保存。一个 Main 回合失败后会清除活动回合屏障并记录错误，已在此前入队的后续输入仍可继续执行；新的进程可以扫描 `queued`/`running` 输入，按原始顺序恢复。若原生 Session 已写入用户消息但没有最终回复，恢复回合使用新的稳定 continuation message ID，并通过已有 delegation/follow-up command identity 避免重复建工或重复改变方向。

`getMainConversation()` 和 recent page 现在返回独立的 `health`：`ready`、`running` 或 `degraded`，并给出持久 queued/failed 输入计数和最后的错误代码。Main 错误只更新此健康投影；WorkBrief、Ticket、Assignment 和 Outcome 查询不依赖 Main 模型，继续按自身状态返回。持久出来的主回复若在投影提交时失败，刷新会按原原生消息身份补读，不会再次调用模型。

活动队列、待补读命令和 health 计数分别维护在 `main-active-command`、`main-reconcile-command` 与 `main-health` 索引中。history 查询和恢复不再扫描累计 `main-command`；1,001 条已完成命令且 active queue 为空时仍可正常查询和调用 resume。只有真实活动队列超过 1,000 时才报告预算错误。

现有主对话在工作卡标题上明确标记 `System work fact`，并在 Main 模型异常时显示健康警告。Main 顶部的 ready/running/degraded 徽标及排队数量不把工作执行状态混进模型健康。

Host 正常关闭会 abort 当前 Main 控制器，但只在 `closing` 期间把命令保留为 `running`/`HOST_SHUTDOWN` 恢复事实；不会再把它投影成模型失败。重新打开 Engine 时 `resumeMainInputs()` 从持久 active index 接续原 command/message identity。

## 本阶段边界

直接停止/恢复/回答工作入口和 Main 当前回合的独立取消分别由 R5-06/R5-07 承担；这些依赖当前仍为 Open。Main context-full generation rollover、授权证据续读和旧代写屏障属于 R5-09，本轮没有把它们声明为已交付。
