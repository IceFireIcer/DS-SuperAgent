## 已接通的行为

桌面 Host 原有 Office payload 完整时，产品 profile 将其 Node、已打包的 `ds-bot/office.js` 和 Office 技能目录交给每个本地工作目录的 Environment；缺任一文件时不声明可用。Worker 可在绑定的本地 Environment 列举并读取技能，使用 `stage_attachment` 把本工作项获准的原始 `.docx` 字节复制到工作目录中的新路径。跨工作项、跨 Environment 或已撤销的上传由原授权检查拒绝；已有目标文件不能被静默覆盖。

Worker 使用相同 Environment 中的公开 DSH subprocess 接缝执行现有 Office CLI 的 `docx-read`、`docx-edit`（另存新文件）和 `check`。Office 工具只接受受控操作及目录内相对路径，不提供模型任意 CLI 参数。文件结果继续由 `report_ready` 记录真实 SHA-256、字节数、Environment 引用和相对路径；报告前必须有成功的 Word 检查，并在提交报告时重新检查实际产物与摘要。主对话现有工作卡展示产物，产品本地入口按原工作归属和 Environment 身份逐页读取/下载。重复上传沿用原命令 ID 回执；路径错误、命令失败、取消与退出不可确认均不换执行世界重试。

## 定向验证

Node 24.22.1、隔离临时目录、虚构授权角色、仓库自带 `.docx` 样例及本地 Office CLI：产品上传 → Worker 技能发现 → 授权附件落盘 → 结构读取 → 定点编辑为新 `.docx` → 包检查 → 持久工作卡 → 产物逐页取回并核对摘要和正文；猜测产物路径与工作项被拒绝。另测跨 Environment 附件、越界路径和无效 Word 包拒绝。相关 `product-office`、`product-attachments`、`capability-locations` 定向回归 16/16；Super-agent build、typecheck、lint 与 UI boundary 检查通过。没有运行全量 CI、真实 Office 服务或个人资料。
