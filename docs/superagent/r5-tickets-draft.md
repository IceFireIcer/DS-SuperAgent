## 所有票共用的交付约束

1. 每张票交付窄而完整的用户行为：持久事实、Engine 公开命令/查询、真实适配器接缝和现有 UI 中的可用入口同时到位。不是只交 schema、接口定义或一张静态页面。
2. 使用现有 UI 组件和公开 DSH API；Main 是独立 Agent。新增工作只由新核心消费，不借过渡阶段启动旧 dispatcher。未完成能力明确不可用，不能冒充已接通；R5-34 收口移除剩余旧代码和入口。
3. 不要求保留旧 Bot 身份、群 round、旧历史入口、旧 API 或双 profile 兼容。新对象可以在内部先扩展、迁入调用方再删除旧形式，但不建设面向旧产品的兼容 façade。
4. 领域验收以 Engine 公开命令/查询为主；只读角色授权包含服务端拒绝案例。沿用原 D02—D16/D19 未冲突约束：Mandate、stop/等待、来源身份、Outbox、事务未知、写权代次、执行世界和安全交接。
5. 实施时为新增行为维护最少且有区分力的行为测试、相关外部合约及必要 UI 证据；优先复用现有场景，不按每层重复搭建完整集成链，不为机械改名新增镜像测试。本轮只写验收条件，不运行这些测试。
6. 每个后端 schema/命令扩展同时维护 SQLite/PostgreSQL 适用合约；不能直到托管票才发现新字段只有 SQLite 可用。Session 与业务事实分别持久，对账不宣称跨库 ACID 或外部 exactly-once。
7. 实施验证使用 mock、隔离临时数据、空闲端口和虚构资源；真实模型/信道/设备由 T55/T58 等对应验收分层收集。无真实配置不伪报通过，也不重复要求已明确暂缓的飞书验收。
8. 英文产品源文案、现有主题/动效、键盘和减少动态效果规则随每票 UI 一同维护；有 UI 改动时生成前端资产并执行仓库规定的生成与边界检查。任何过程页都不能偷偷提供原生 Session 写旁路。
9. 每张票可在一个新上下文内完成。先读本票、已完成直接前置和关联契约；范围超出时先拆分。依赖就绪不等于允许同时读写同一文件，执行前分配互不冲突的文件所有权。
10. 下面正文没有固定实现路径和代码片段；发布时每票包含 Parent、What to build、Acceptance criteria、原生阻塞及适用公共约束，不能只发布一行摘要。

## 票据正文

### R5-01 在现有主对话与独立 Main 持续交流

**Blocked by：** 无。

**What to build：** 从隔离的新产品入口打开现有聊天表面，与真正独立的 Main 连续问答；同一授权工作空间的窗口和刷新共用身份，另一隐私范围隔离。本票内先完成最小的 Instance 生命周期、角色扩展和 UI 数据源解耦，随可见行为交付，不先做全仓重构。

- [ ] 冷启动默认 Main；通过公开 DSH loop 调用独立 Main route/Session，不能用 Router 日志或 Worker 回答冒充 Main。
- [ ] 同一 Instance 的多窗口/重连收敛到一个逻辑 Main、Router 核心与有效 Host；UI Session 不再决定 Instance 身份。
- [ ] 用户消息与 Main 回复按稳定身份持久，刷新可读；跨 Instance 的读写拒绝，普通问答不创建 Ticket。
- [ ] Main 初始工具只有声明的产品委托/查询能力，无文件修改、Shell、浏览器或旧团队治理工具；未接线的委托明确不可用。
- [ ] 使用新产品自有数据目录和公开 profile 装配；不自动加载旧 roster、工作、Session 或用户 DSH。沿用现有组件，不建 renderer。

**Spec coverage：** D01、D03、D07、D11、D12；A01、A22、A23（本票部分）。

### R5-02 从 Main 委托一项本地工作并收到有界结果

**Blocked by：** R5-01。

**What to build：** 用户在主对话要求完成一件明确的小工作，Main 产生 WorkBrief，Router 建立工作并分派本地 Worker；用户看见真实工作卡和结果。

- [ ] 固化 WorkBrief/Receipt/Update/Outcome 的最小版本化契约，保留来源、授权依据、目标、验收和配置版本；Main 不直接建 Ticket。
- [ ] 一份委托对应一项 Ticket/Mandate/Assignment，由真实 Worker 在明确的本地目录内完成一次读写及验证；不能只用模型口述完成。
- [ ] 同 ID 重试复用回执、异文拒绝；保存消息、委托、建工与交付的不同事实，不把持久投递当模型已处理。
- [ ] Worker 只回 Router，Main 收有界回执、关键变化与结果引用；完整工具日志不进入 Main，普通进度不逐条唤醒 Main。
- [ ] 主对话的工作卡展示可查身份、状态、证据及真实回执；未收到结果时不能报成功，工作失败不伪装成 Main 故障。

**Spec coverage：** D01—D05、D12、D13；A05、A10、A17（本地基本闭环）。

### R5-03 将一条复合请求可靠分解为并行工作

**Blocked by：** R5-02。

**What to build：** 一条“修复 A 并独立调查 B”由 Router 形成两个稳定工作项，用户能分别看进度和接收结果。

- [ ] 一份不可变来源事件关联分解决定和各工作项；不复制用户消息，不用 requeue 重做整段 A+B。
- [ ] 每项拥有独立目标、Mandate、验收、订阅和交付；两个 Worker 可以并行，一项等待不拖住另一项。
- [ ] 分项身份由持久决定分配，不按模型文本顺序或相似度重新猜；重复模型建议和网络重试复用原项。
- [ ] 部分提交/重启可查询已提交项与缺项，只补缺项；目标修订显式冲突/新决定，不重复派发成功项。
- [ ] 观察到独立工作卡及分别回报；一项的发布权限不能借给另一项。

**Spec coverage：** D02、D04、D12；A02、A03。

### R5-04 把跟进交给原工作并处理越界交回

**Blocked by：** R5-03。

**What to build：** 主对话中说“A 先不要发布”只改变 A；不明确的指代先澄清，越界请求按既有 handback 规则处理。

- [ ] WorkFollowUp 引用原工作与来源，复用 Ticket/合法 Session，方向版本和采用事实可查，不新建第三项工作。
- [ ] 区分“输入已持久投递”与“Worker 已采用方向”；B 不承接 A 的权限或工作。
- [ ] 多 owner、context-only、全部 handback 后重新研判沿用原领域规则；无依据指代不按当前页面猜。
- [ ] 主对话能看见采用/等待/交回事实；停止、waiting-human 与 ended 恢复授权不被普通跟进绕过。

**Spec coverage：** D02、D04—D06、D12；A04、A19。

### R5-05 自动展示只读 Router、Worker 和新工作历史

**Blocked by：** R5-02。

**What to build：** 侧栏按持久工作自动发现 Worker，用户能查看 Router 协调、执行事实和历史，返回 Main 继续交流。

- [ ] 角色/工作感知查询校验 Instance、Ticket、Session、代次及资源授权；分页、引用与错误不泄露不可读对象。
- [ ] 自动新增条目不切页、不夺焦点；结束保留历史，快照与游标补读不漏项、不重复、不把旧代次显示为当前。
- [ ] 观察区允许搜索/分页/复制已授权事实，无 composer、steer、审批、重试、工具重放或 fork-and-prompt。
- [ ] 服务端拒绝观察能力发写命令以及猜测 ID 越权；原生 DSH surface、菜单、快捷键和深链接不能绕过。
- [ ] 主对话、Router、Worker 的新历史可逐页读取，状态与下一步有文字说明；查看详情不自动注入 Main。

**Spec coverage：** D03、D04、D07、D10、D12；A06、A10、A15、A23。

### R5-06 分开停止 Main 回复与持久停止工作

**Blocked by：** R5-02。

**What to build：** 用户能只打断 Main 当前回复，也能从主对话工作卡停止、明确恢复或合法重试一项工作。

- [ ] 输入框 stop 只取消当前 Main 回合；已提交/派出的工作继续，提交未知按原委托身份对账。
- [ ] 工作卡 stop 携带明确目标直达受信核心，先持久记录并传播取消，再通知角色；Main 模型不可用也不阻塞控制。
- [ ] stop、stopping/pending-confirmation 与实际静止分别展示；晚到完成、CI、重启不自动解除停止。
- [ ] 明确 resume/retry 重新校验授权、当前约束和旧执行；普通跟进不等于恢复，不按最近 Worker 猜控制目标。
- [ ] 观察页只导航回主对话控制。若提供全部停止则范围独立显示；首版可不增加全部停止入口。

**Spec coverage：** D02、D06、D07、D12；A08、A18、A19。

### R5-07 在主对话直接回答当前问题卡

**Blocked by：** R5-02。

**What to build：** Worker 等待人的问题在主对话形成卡片，明确答案经鉴权直达原执行，不等模型转述。

- [ ] Attention 含工作、版本、选项/自由输入约束与回答权限；Router 组织问题，Main 可解释，但不改写用户选择。
- [ ] 核心验证当前问题、工作、Instance、权限和停止/等待约束；过期、重复异文、失权和停止后的非法回答拒绝。
- [ ] 合法答案持久去重并继续原工作，Main/Router 收事实通知；原问题过期或失效在卡片可见。
- [ ] 观察页只能回主对话处理；一项 waiting-human 不锁住其他工作，也不能借换代解除等待。

**Spec coverage：** D02、D06、D07、D12；A07。

### R5-08 Main 故障时继续工作并可靠补读

**Blocked by：** R5-06、R5-07。

**What to build：** Main 模型失败期间已有工作继续，用户仍能看持久事实、停止、回答；新自然语言输入排队，恢复后正常接续。

- [ ] Main 健康与工作状态分开；事实卡清楚标记为系统事实，不冒充模型回复。
- [ ] 新输入带稳定身份持久排队；入历史、委托提交和处理完成的不同窗口可恢复，不丢输入、不重复建工。
- [ ] 停止与有效答案直达核心；Main 故障不取消 Router/Worker，普通恢复不扩大权限。
- [ ] 已显示/送达 Outcome 按原身份补读去重，延迟结果可见，不依赖重发用户原话恢复工作。

**Spec coverage：** D03、D06、D12；A09、A18、A19。

### R5-09 换代 Main 上下文并按需核查证据

**Blocked by：** R5-05、R5-08。

**What to build：** Main 上下文满后保持同一主对话，能沿工作索引读取必要证据回答用户核查请求。

- [ ] 换代交接目标、约束、工作索引、未读输入和证据引用，保留逻辑身份与旧历史。
- [ ] Main 仅使用获授权的有界查询和续读入口；预算/截断明确，超大输出不静默冒充全文。
- [ ] 原始请求和证据不被摘要替代；查看执行页面不等于授权把整段历史灌入 Main。
- [ ] 旧 Session 写权和迟到回调不能推进当前代，停止/问题/提交未知不因换代被绕过。

**Spec coverage：** D01、D03、D12；A01、A05、A15。

### R5-10 在现有设置独立配置三层模型与指令

**Blocked by：** R5-05。

**What to build：** 用户在现有设置管理 provider、Main/Router/Worker 模型与指令，并核查使用版本。

- [ ] 三个 role profile 可选相同或不同 route，模型/provider/effort 等保留能力按公开 DSH 服务接入，纯设置不建 Ticket。
- [ ] revision 保存、异步检查后重验、冲突保留草稿和无效模板拒绝；在途回合继续原版本，后续请求才生效。
- [ ] 查询和界面能解释一次回合的配置版本；Agent 自行改配置或提升权限被拒绝。
- [ ] provider 密钥只经受控配置使用、不出现在响应或日志；不需要先恢复旧 Bot 设置对象。

**Spec coverage：** D01、D08、D12；A11、A21。

### R5-11 在 GitHub 进入 Main 并直通已有工作

**Blocked by：** R5-04、R5-13。

**What to build：** GitHub 新人类请求进入所属 Main，已核验 PR/Issue 跟进与 CI 按现有归属直通，结果回合法信道。

- [ ] 复用来源身份/版本/删除/准入、关联和游标模块；新请求不再直接交 Router 充当用户对话。
- [ ] 合法已有工作保持 Ticket、owner、方向与订阅；机器人和 CI 不冒充明确授权，普通事件不逐条唤醒 Main。
- [ ] 主对话可查来源引用和获授权摘要；跨信道发布另核查受众，私人内容不自动外发。
- [ ] 回执、PR 交付条件和候选失败可追查，来源局部故障不阻塞其他来源；不重复建设 GitHub parser。

**Spec coverage：** D04、D05、D12；A04、A16、A17。

### R5-13 可靠交付三层消息并限制跨受众发布

**Blocked by：** R5-02。

**What to build：** Main 组织的确认、回答、问题和结果通过现有 Outbox 可靠到达对应受众，用户能区分发送结果。

- [ ] Router/Worker 仅产生合法结构化事实，Main 形成对用户回复；发送意图仍由唯一核心校验用途/依据/目标并排队。
- [ ] acknowledgement、answer、attention、result 绑定各自依据，缺报告/问题或过期方向不能发送。
- [ ] 原请求信道为默认；改变目标要有核验依据及授权，不凭新事件改投、广播或复制私人上下文。
