## What to verify

用当前 Windows 安装构件和隔离产品 Profile，验证 DS SuperAgent 在连续、高效、主动、持久四个目标上的实际行为。使用现有 Main、Router、Worker 和设置入口。实施票的结果是前置证据，验收发现的回归归回行为票或独立缺陷票。

维护者于 2026-11-18 移除实体第二设备、外部托管 Host、跨机 PostgreSQL/TLS/SSH 和双向跨机交接的验收门槛。此前的环境结果保留在 T58 历史记录中。单机客户端补读、撤销、Host 替换以及停止和未知结果保护仍须核查。真实飞书租户继续暂缓。真实模型和真实 GitHub 仍需各自的授权隔离环境与证据。

## Fixed final scenario

开跑前固定输入、超时、构件哈希、脚本版本、模型与信道、证据路径。记录当前构件上的主流程以及同版本的定向补证：

1. Windows 原生应用从独立构件冷启动进入 Main。关窗、再次启动和重连回到同一 Main 和历史。
2. 一条复合请求创建两项独立工作并可并发推进。跟进只改变目标工作，结果回原会话。核查本地执行、长作业、资源和并发预算。
3. Worker 的问题回到 Main。有效回答续接原 Ticket/Session，过期、失权和停止后的回答被拒绝。
4. 分别停止 Main 回复和目标工作。保留其他工作运行，核验原作业静止与明确 resume。
5. 运行 Proactive、语义监督和独立 Watchdog，核验预算、持久提案和显式人工决定。
6. 中断本机 Host，核验同一逻辑 Main/Ticket/Session、写者 fencing、stop、waiting-human、unknown 与客户端补读/撤权。真实系统休眠与关机按实际覆盖记录。
7. 用隔离的本机 Profile 检查安装升级、业务库与 Session 备份恢复、诊断和用量。重新打开后复核历史、人工停止与授权。

- [ ] 保留 Instance、凭据、角色只读、跨受众、停止与显式恢复、原 ID 对账及写权代次保护。
