# Super-agent 领域词汇补充

## 协作模型

**Super-agent（连续协作者）**：对用户表现为同一个持续协作的智能体；内部可以并行推进多项工作，不要求用户管理执行者或会话。
_Avoid_：Bot 团队的另一个名字、单个永不换代的会话。

**主 Agent（Main Agent）**：拥有独立模型配置与会话上下文、面向用户持续沟通并把工作委托给 Router 的协作者。
_Avoid_：旧 Main Bot、Router 的界面别名、把所有 Worker 细节塞进同一上下文的主会话。

**主对话（Main conversation）**：同一授权工作空间内用户与主 Agent 的连续讨论；切换执行观察页面不改变其身份，上下文换代不切断讨论的连续性。
_Avoid_：某个 Worker 的执行日志、一个永不换代的原生 Session。

**工作委托（Work brief）**：主 Agent 交给 Router、基于用户意图和授权的一项工作请求；它保留目标与约束，具体分解由 Router 组织。
_Avoid_：用户原文的替代、Router 的实施规格、直接创建的 Ticket。


**运行观察视图（Execution observer view）**：允许查看 Router 协调或 Worker 执行事实而不能直接驱动 Agent 的只读视图；查看过程不把完整日志写入主 Agent 上下文。
_Avoid_：可聊天的第二个入口、主 Agent 的原始工具日志。

**问题卡（Question card）**：主对话中与一项工作及其当前待答问题明确关联的结构化提问；用户的选择保留原意，问题变化后旧答复不再自动适用。
_Avoid_：Worker 私聊入口、没有工作归属的普通通知。

**停止生成（Stop generation）**：用户终止主 Agent 当前对话回复的动作；它不撤销已委托的工作。
_Avoid_：默认停止所有 Worker、解除工作授权。

**停止工作（Stop work）**：用户对明确工作设置持久停止约束的动作；与打断主 Agent 回复不同。
_Avoid_：只隐藏进度动画、停止生成的别名。

**Router（全局协调层）**：维护一个上下文共享范围内的工作关联、分解、分派和跨任务协调的角色；接收主 Agent 的委托并向其回传有界摘要，不直接与用户聊天。
_Avoid_：Main Bot、主 Agent 的界面别名、替每项工作规划全部步骤的队长。

**Worker（工作执行者）**：在隔离上下文中调查、执行和验证一项授权工作的角色；可以在该工作内部组织子代理。
_Avoid_：长期具名 Bot、一个聊天入口的固定主人。

**Bot（历史协作者术语）**：早期设计中具有长期身份、独立指令和私聊/群聊归属的协作者；不属于当前 SuperAgent 运行模型，也不等同于 Worker。

**角色预设（Role preset）**：可用于工作执行的模型、指令、技能和专长配置；不是独立接单的长期协作者，也不自动授予权限。

**Thread（讨论流）**：一个来源中连续发生的讨论；它与工作是多对多关系，不等同于某个执行者或某项工作的全部历史。

**能力保留（Capability preservation）**：继续提供用户需要的工具、数据访问和操作能力，同时保留隐私、权限与可恢复性保护；不要求复制旧协作者之间的派活方式。

## 来源与恢复

- **来源实例（Source instance）**：一份具体来源接入范围的持久身份；它与可复用的来源类型不同。
- **逻辑来源对象（Logical source object）**：来源中的一条消息或资源；编辑产生新版本时仍是同一对象。
- **版本事件（Versioned event）**：某个逻辑来源对象的一次已观察创建、编辑或删除事实。
- **当前投影（Current projection）**：根据已核查版本事实形成的对象当前视图；它不代替历史依据。
- **关联证据（Association evidence）**：支持把输入交给某项已有工作的来源引用和核查依据；它本身不授予新的工作权限。

- **运维恢复（Operational recovery）**：在既有授权内恢复故障服务可用性的操作，不改变工作目标或解除人的停止。
- **语义干预（Semantic intervention）**：针对任务无进展或方向偏离而采取的纠偏、暂停等动作；与故障查询及安全重试不同。
- **执行权威链（Execution authority chain）**：判断当前执行安排及其结果是否仍有权推进原工作的一组关联归属依据。
- **未知结果（Unknown outcome）**：外部操作可能已经发生但当前无法可靠确认其结果的持久事实；它要求有界查证或人工决定，不能被当作失败而盲目重做，也不能被当作成功。
- **人工停止（Human stop）**：用户明确要求停止某项工作的持久约束；它优先于自动恢复和 Host 接管，设备重新上线也不会自动解除。
- **Assignment（执行安排）**：某个 Ticket 的一次具体执行绑定；可以换代，但同一时刻只能有一个有效执行安排。
- **等待人工（Waiting human）**：工作已经提出结构化问题，下一步由具备权限的用户回答推动。
- **等待设备（Waiting device）**：工作等待设备或外部条件回报的正常状态，不自动视为失败。

- **执行策略（Execution policy）**：选择工作运行位置的偏好与约束，受已有授权限制。
- **执行环境（Environment）**：提供工作文件、工具及作业运行能力的具体环境；本机与远端环境各自具有身份。
- **执行交接（Execution handoff）**：在保留原工作目标和授权的前提下，结束旧执行安排并由新的执行安排承接工作。
- **交接受阻（Handoff blocked）**：已有明确条件阻止交接，例如目标能力不符或工作副本尚未核验；区别于外部操作结果未知。

- **历史档案（Historical archive）**：保留旧工作及对话依据的只读资料，不授予新执行权限。
- **切换批次（Cutover batch）**：可核查的一次资料准备与核心交接范围，关联原对象映射及输入归属。
- **待核查旧工作（Legacy review item）**：旧工作已接受、执行未完或结果不明的保留记录；须经核查和当前授权才可承接。
