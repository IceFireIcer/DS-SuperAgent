### 1.3 产品约束

- 继续在现有 DSH 客户端和单一产品 profile 内交付。UI 使用现有 `superagent/dsh/src/client/`、已公开的 slots、产品命令和 `/api/product`。逻辑表面包含本机 DSH 承载的 Main、产品自己的历史视图和受授权的远端连接。所有路径以实际挂载和可执行权限为准。变更客户端源文件后由构建产出 `superagent/dsh/client.js`。
- Main 持续拥有用户对话。Router 与 Worker 的运行观察只读，Work 通过既有入口查看。Classic Agent 使用已批准的切换、独立会话授权和同窗返回。设置的页面状态与现有 Main 会话、工作标识、执行安排和授权分别管理。
- 本期工作计划覆盖桌面 Main、Activity、设置 25 个内容落点及共用交互。手机项指桌面侧配对管理，移动 App 另按迁移规格验收。新增配置字段、Host 命令、权限和数据迁移属于后续单独范围，遇到公开 DSH 接缝缺口时先保留现有可用动作并记下阻塞。
- 按 `AGENTS.md`，实施界面改动须获得对应的明确授权，改动已决定设计须由维护者确认。测试使用全新的隔离夹具与 mock 模型，保护用户自有 `~/.dsh`、正在运行的桌面实例和真实凭据。

## 3. 设置导航与页面骨架

### 3.1 用现有落点重排结构

沿用 `settings-navigation.js` 的 `SETTINGS_GROUPS`、`SETTINGS_SECTIONS` 与 `settingsTarget`。分组、页、标签和搜索都从同一份可见落点求值。`settings-sections.js` 的 `settings.section` 保持父页/子页 ID 与扩展内容 outlet。产品层仍由 `product.js` 的 `SettingsDialog` 组装内容，`settings-shell.js` 负责布局、导航状态、关闭和焦点。产品补丁 `superagent/cordis.patch.yml` 明确禁用 `ui-settings-general`，常规入口落到产品自己的 General。组标题和展示文案可调整，调用方传递的 ID 保持可解析。

| 现有组 | 父页及内容落点 |
|---|---|
| General | `general` |
| Models | `models`、`roles`、`presets`、`built-in-plugins` |
| Connections and capabilities | `connectors`、`im`、`phone`、`browser` → `browser-resources` / `browser-plugin`、`computer`、`capabilities` |
| SuperAgent | `execution`、`schedules` → `calendar` / `scheduled-tasks`、`preparations`、`supervision`、`memory`、`usage` → `usage-overview` / `status`、`secrets` → `chat-secrets` / `credential-resources`、`remote-clients` |
| Help | `feedback`、`about` |

显式子页打开对应标签，显式父页打开其首个可用标签。普通设置入口的首批默认行为见 §10.3。不存在、未授权或在当前 profile 不可用的显式目标，由调用方显示可读状态。可用的公开原生 Models 由原生 slot 渲染，产品 Models 作为回退。远端 `Connect to Host` 按其现有授权判断入口。

六组导航作为后续候选，保留全部 25 个内容 ID。基础收 General、Models、Roles、Presets，其中模型凭据由 Models 管理。连接收 Connectors、IM、Phone、Browser。自动化收 Computer、Capabilities、Execution、Schedules、Preparations。监控与数据收 Supervision、Memory、Usage、Remote clients、Secrets，其中 Activity 继续通过产品主导航访问。系统收 Built-in plugins、Status，备份和诊断保留实际动作所在页面。关于收 Feedback、About。采用该候选时验证原 `usage → status` 访问路径、`Secrets` 与产品账户归属，再确定展示名。

| 条件（候选，按容器 CSS 宽度） | 行为 | 检查点 |
|---|---|---|
| 960 px 及以上 | 导航约 198–224 px，内容采用侧边留白与居中受控版心，数据表可使用剩余宽度 | 页面标题、关闭和页内标签位置稳定。导航滚动与内容滚动互不抢滚轮 |

### 3.3 导航、搜索和草稿

1. **统一入口。** 设置按钮与 Account 菜单的 Models、Usage、Automation、Connectors 等共享 `openSettings`。Automation 直达 `scheduled-tasks`，Usage 指向 `usage-overview`，连接器快捷入口打开 `connectors`。页面内的 `navigate` 与这些入口使用同一映射，目标确定后更新父页选中态和子页选中态。点击父页的行为遵循现有默认子页映射。
2. **搜索设置名称。** 搜索当前可见的父页、页签和经评审的中英文关键词。将 `API key`、`OAuth`、`schedule`、`backup` 等词指向明确落点，存在多个匹配时保留父页／子页路径，例如 `Usage › Status`。搜索数据取导航元数据，用户编辑值和诊断信息留在所属内容区。输入清空回到分组。零结果显示 `No matching settings` 和清除动作。搜索结果按顺序用 Tab、Enter 可达。采用复合组件时一并实现相应方向键语义。
3. **打开和返回。** 控制层记录触发元素及无效时的回退位置。打开时焦点落到当前选中项或页标题，从子页返回时回到原链接或本页标题。关闭时优先返回原触发项。Account 菜单消失后回到 Account 触发器，首次配置成功后回到 Main 输入或标题。切页重置新页内容滚动，返回原页可恢复该窗口内位置。切换实例后清理上一个实例的页面详情与编辑状态。
4. **Esc 与指针关闭。** 菜单、选择器、危险确认、设置容器按层级关闭。打开真模态时背景不可交互，Tab 与 Shift+Tab 在可见控件内循环，退场动画期间保留正确的焦点与可访问性闭合顺序。点遮罩与关闭按钮共用退出判定。独立视图若获批，改用页面导航和语义，保留子弹层的模态规则。
5. **未保存更改。** 先接 Roles 等已有显式保存的表单。关闭、切标签、侧栏跳转和外部快捷入口统一走编辑状态判定。出现未保存内容时提供 `Keep editing` 与 `Discard changes`，可以在当前流程安全保存时才提供 `Save`。即时保存的开关与主题偏好直接给结果反馈。移除页面时取消或隔离旧请求结果，慢响应只影响原绑定和选中的操作。已收到写入回执但读取失败时单独刷新。
6. **兼容与验证。** 保留 `hidden` 面板、子页挂载与原生 outlet 的现行行为，直到各页面的清理、焦点与异步副作用有验证。重点覆盖 Usage/Status 在同一父页保留已访问面板的行为。锁定稳定角色/名称和导航 ID，再更新随容器变化的探针选择器。现行窄窗样式在 `≤640px` 使用全宽布局与横向导航，验收时记录候选断点和已有本地设置动画改动对它的影响。

### 3.4 独立设置视图的候选规格

此候选供后续独立设置视图评估。在同一 DSH 产品工作区内容区域放置 Settings 页面。窗口内使用 `Settings` 标题、页导航、内容区和明确的 `Back to Main` 或返回原视图操作。页面使用 `main` 与命名导航区域。危险确认、文件选择等附属交互继续使用各自的弹层语义。

| 场景 | 页面及状态行为 | 验证点 |
|---|---|---|
| Main、Activity 或 Work 中打开设置 | 记录原视图、当前实例与触发位置。设置按目标 ID 在同窗进入，焦点落到设置标题或当前落点 | 从三个入口分别进入，在设置间流转，再回到原视图及合适焦点 |
| Main 有在途回复、附件或问题卡 | 由现有 Main 绑定和产品事件维持工作状态，页面切换只改变显示区域 | 设置期间接收更新，返回时保留实际回执、草稿、附件与待答状态 |
| 页内编辑后返回 | 页面级 Back、快捷导航与窗口普通返回使用同一离开判定。弹层 Esc 处理当前弹层，页面提供独立可见返回动作 | 改 Roles 草稿后分别选择继续编辑与放弃。浏览器历史和桌面快捷键只在当前公开接缝支持时接入 |
| 打开原生 Models 或登录 | 使用当前授权 profile 暴露的 slot。结束或取消后回到原落点，刷新可用模型和登录状态 | 分别验证有 slot、无 slot、原生设置读取失败和返回原 Main 时的落点与焦点 |
| 切换 Host 或 Classic Agent | 重新确认本机/远端绑定和已获授权的原生会话。设置回退记录按当前窗口和实例归属 | 无本机设置权限的连接不能通过历史返回打开设置，Classic 往返通过原会话与工作回归 |

先以 General、Models 和一个已有页签父页试跑上述场景，验证当前 DSH 的公开布局与 slot 接缝。出现未公开的挂载依赖时记录具体阻塞，设置请求继续落到已可用的覆盖层。通过后迁移其他落点，复用 §3.3 的搜索、草稿和异步契约。

### 4.2 首次模型状态流

接线以 `product-model-onboarding.js` 中 `mainModelSetup`、`SuperagentModelChoice` 和 `product.js` 的模型读取、`provider-key`、Roles 设置为起点。当前 key 表单提交前清空编辑值，失败后需要重新输入。首批按 §10.3 的敏感字段默认行为验收。任何一条路径都按重新读取的供应商目录与 Main 角色配置判断配置状态，并通过实际回复确认端到端可用。

| 状态 | 首要反馈与动作 | 成功或失败的分支 |
|---|---|---|
| 正在读取配置 | `Checking model setup…`。保留用户草稿 | 能读取时进入就绪或未配置。读取失败提供 `Retry`，仍保留原 Main |
| 目录或凭据缺失 | `Set up a model` 进入方式选择，展示实际可用方式及一句适用条件 | DeepSeek 登录只在公开 slot 可用时展示。官方 key 只对可写且适用的供应商展示。自定义模型优先可用的原生 Models，其次产品 Models |
| 已有可用目录，Main 未选 | `Choose a model` 跳 `roles`，聚焦 Main | 保存后按最新角色和供应商目录重新计算。在其他角色需要配置时显示独立的工作就绪提示 |

| 保存中 | 操作组显示 `Saving…`，防止重入，清晰说明当前可取消动作 | 保存成功后重读配置。已写入但刷新失败时显示 `Key saved. Refresh model settings to continue.` 并提供读取重试。明确写入失败时在原表单反馈 |
| 已登录、已保存或目录已更新 | 状态文字分别表达用户已完成的步骤 | 目录无可选模型时指向可用配置入口。仍需保存角色模型时保留引导。配置就绪后收起引导并恢复适当焦点 |
| Main 已可发 | 显示实际模型名和发送动作，原草稿仍在 | 用户主动发送测试消息。只有收到 Main 的实际响应才记录可用性结果。请求失败时区分未接纳与已经接纳但回复失败 |

### 4.3 发送、目录和语音约束

- 文本、附件、所选目标、环境及未决 `commandId` 按现行产品协议处理。收到接纳回执后清除对应临时选择，提交失败时继续保留。测试同一命令重试以及换目标后形成新请求。已接纳后回复失败显示消息已保存，从原回执或现有恢复入口处理。
- 场景 A 先让一项工作在目录 A 执行，再从侧栏选择 B。折叠、打开设置和返回均保持 B，失败后 B 仍可用，在下一条符合条件的本机请求被接纳后恢复默认。原工作及其跟进继续读取原已授权环境。权限不足时提示如何回到有效选项。设置中的实例默认目录与这次临时选择分别展示。
- 场景 B 先在一环境上传附件，再切换目标或选择 Automatic。显示已有环境绑定及恢复动作，用户可返回原环境或移除附件。目录尚未授权、设备离线和目标能力不匹配采用不同提示。保留已授权环境与已经接纳的工作记录。
- 场景 C 在回复生成期间点击停止，等待现有 `stop-chat` 接缝及 Main 刷新结果。在工作卡单独检查停止工作的回执、人工停止持久性和恢复权限。未收到确认时呈现等待或状态未知，保留安全的读状态动作。
- 场景 D 连续语音保留 Main 的接纳回执关联，按 `messageId` 与 `reply:<messageId>` 只朗读本次对应完整回复。问题卡、停止回复、最小化、隐藏和用户暂停都按现行规则释放音频并使迟到结果失效。结束后再次使用需要已有的明确用户动作或既定续听条件。单次听写、连续语音和附件各自验收。
- 场景 E Main 回复中进入设置或 Classic Agent 后返回。检查同一实例和会话、草稿和附件选择、回执无重复、原工作继续可见、已停止工作仍受约束、焦点回到合适落点。Classic Agent 仍遵从原生会话授权。

普通设置可用 4 px 间距基准，建议 12–16 px 字段内距、20–24 px 字段组间距和 24–32 px 区块间距。按钮、输入优先沿用现行 36–40 px 档位，关键图标交互目标建议扩到约 40×40 px。通过内外层间距做扩大，保持现有组件形状和视觉节奏。审查稿给出的 HEX、6 px 圆角和 24 px 标题属于提案。最终变量、字号和尺寸由现有主题、可访问性实测及维护者裁定决定。

### 5.2 通用状态与异步结果

| 状态 | 界面判据 | 操作与可测结果 |
|---|---|---|
| `loading` | 当前范围尚未拿到结果 | 局部占位或 `Loading…` 表达首次加载，后台刷新时显示旧数据并标记正在更新 |
| `empty` | 成功读取，当前范围确实无数据 | 给一个真实可达下一步。只读且依赖历史事件的页面说明产生数据的条件 |
| `no results` | 有数据但筛选无匹配，或查询结果明确为空 | 显示条件、查询覆盖范围及清除筛选的动作 |
| `unavailable` / `permission denied` | 桥或平台缺能力／当前身份无权 | 能力缺失、配置前置、权限拒绝使用各自文案。可转到已有配置时提供链接 |
| `pristine` / `dirty` / `invalid` | 显式保存表单的原值与编辑值不同层管理 | Dirty 且字段合法时可提交。错误定位到字段，修正后清理。关闭、切页及回退由相关草稿负责 |
| `pending` | 有在途写入、授权、导入或撤销 | 当前操作有忙态，重复点击只产生一次请求。异步结果受实例和操作身份保护，慢响应忽略已离开的旧 UI |
| `succeeded` | 权威来源确认 | 用 `Saved`、`Connected`、`Revoked` 等实际结果。若后续刷新失败，注明已生效部分与安全的刷新动作 |
| `failed` / `conflict` | 有明确失败／期望版本不匹配 | 局部错误、保留可安全保留的编辑值。Role 配置冲突走既有重新读取和合并，再由用户保存 |
| `unknown` | 请求可能已在外部落地，但当前无法确认 | 读取命令或资源状态，用相同操作身份核查已有结果，只有确认前次已安全结束时才新发写入 |

键盘验收包含可见焦点、完整访问顺序、逐层 Esc、自动滚动到焦点、关闭后返回触发项。文字对比度以 WCAG AA 为目标，普通文字 ≥4.5:1，大字 ≥3:1，必要控件边界和状态/焦点指示与相邻色 ≥3:1。记录浅深配色、hover、focus、selected、error 的实际组合。禁用原因的说明文字按普通文字检查。平台辅助技术抽验使用真实的键盘与屏幕阅读器。

### 7.1 需要覆盖的竞态

- 切到另一实例、切标签或关闭设置时，前一次读取才完成。当前页只应用当前绑定和当前请求的结果。回到旧页时刷新所需状态。
- 授权、导入、轮换或配对已被接受，响应途中断连。寻找已有状态读取、列表或相同 `commandId` 的查证路径。界面明确显示待查证与查询动作。
- 用户刚改了角色配置，后台配置版本变化。保存冲突时保留编辑意图，使用已提供的合并路径展示可审核结果，等待用户确认保存。
- 撤销操作和在途工作并发。按 Host 的即时 read/command、资源状态或终止回执更新界面。已接纳的工作、历史留存和撤销后的访问按实际授权契约分别验证。
- 弹层内正在编辑敏感字段时打开另一个入口。关闭与切换路径清理临时值，焦点恢复到正确的触发项。诊断仅记录步骤和结果元数据。

| A09 自动化与数据 | 以本机时区创建实际支持的重复任务，拿到触发与工作结果。检查无数据和部分用量覆盖 | 时区、触发、归属和状态一致，空态给出可执行的下一步。分页数据表达实际范围 | 客户端、隔离 Host、必要时平台复验 |
| A10 发布保留行为 | 在同候选包开关设置、Main 往返、Classic 往返，验证同窗与进程退出。使用隔离旧包做升级 | 持续使用原 Main 与已有数据，工作和授权记录一致，进程正常退出，构件生成内容与源码对应 | 三平台候选构件、完整 CI |

## 10. 上线与回退

### 10.1 按用户路径逐批合入

P0 要求首次配置、日常输入和设置找路完整通过后一起交付。P1 的连接、敏感资源和权限按服务或页面单独评审。P2 按照数据面、维护面逐步并入。小范围候选先使用内部隔离 profile 或候选包走任务脚本，再扩大覆盖。首批使用现有设置结构时，按每个已迁移落点更新截图探针，保持测试和实际用户入口同步。

### 10.2 回退触发与操作

| 触发 | 回退单位 | 核对动作 |
|---|---|---|
| 广泛设置入口丢失、按键卡死或关闭会丢普通草稿 | 回退设置外壳/导航交付单元和对应探针，重新生成客户端 | 全部 25 个落点、Account 快捷入口、Roles 草稿、焦点返回和最小窗 |
| Main 无法发送、误清草稿或回执重复 | 回退对应引导或 composer 交付单元 | 首次发信、目录 A/B、附件、语音、Main 历史和已有工作控制 |
| 授权越界、凭据暴露或撤销状态错误 | 停止交付，回退受影响接线/展示单元，按相应实际影响处理与复核 | 用隔离材料核查拒绝、撤销、日志、导出和诊断。对已有真实授权按已确认流程处理 |
| 某平台升级或进程退出失败 | 暂缓该候选，按对应构件差异定位并保留可复现证据 | 同平台安装、隐藏唤回、退出、覆盖升级、数据保留和构件指纹 |

本计划沿用现有命令与数据模型，回退以版本化的源与生成 bundle 为单位。已有配置、会话、工作与资源继续由其当前持久化逻辑处理。若未来另行批准更改持久化结构，在相关变更的设计中提供其兼容性、升级和回退路径。回退后重做受到影响的关键用例，再按同一发布门验证选定构件。

### 10.3 首批交互与验收规格

以 §2 已确认的六项裁定为准。以下交互细节沿用现有入口、状态回执与敏感数据处理方式，作为首批实现默认值。

| 用户动作 | 首批交互默认值 | 验收结果 |
|---|---|---|
| 从普通设置入口、快捷入口或搜索进入 | 普通入口打开 General。Account、Main 引导、页内链接及搜索以指定页面或标签 ID 优先。页内返回可恢复本次打开期间的位置 | 键盘打开普通设置命中 General。Account 的 Automation 直达 `scheduled-tasks`。搜索 `backup` 可以直接打开 `status` 并显示正确选中态 |
| 编辑 Roles 后尝试离开 | 用 `Keep editing` 和 `Discard changes` 决定是否离开。焦点默认落到 `Keep editing`，通过表单原有 `Save` 提交 | Esc 优先关闭最上层确认。继续编辑保留草稿，放弃后跳到原目标。持久配置与已提交回执一致 |
| 保存 key 或完成受支持的登录后仍需选模型 | 读取配置后在首次引导中提供 `Choose a model`，由用户打开 Roles 并聚焦 Main。保存成功且配置就绪时返回同一 Main，聚焦原输入框或可用操作 | 模拟保存成功但刷新失败时，重试动作仅读取配置。读到可选模型后能继续选模型。首次回复验收包含同一 Main、原草稿和唯一一条接纳回执 |
| API key 提交失败 | 延用当前首次配置表单清空敏感输入的策略，通过行内错误提示重新输入。普通 Main 草稿继续保留 | 模拟请求失败后原值从表单清除，提示可读。取消、切换实例、归档截图与诊断都按 §7 验收 |

首批交付顺序从 `UI-00` 的基线复现开始。先打通 `UI-01` 的 Models/Roles 落点和返回焦点，随后跑通 `UI-02` 的首次模型配置。`UI-03` 验收日常输入、目录、附件、语音和两种停止动作。设置搜索、窄窗和草稿保护随 `UI-01` 收口。每一条以 §9 对应的实际操作和可观察结果验收。
